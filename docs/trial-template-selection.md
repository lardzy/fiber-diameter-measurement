# 含量／直径试验 Excel 模板

适用版本：0.4.14。本轮调整不改变版本号。

## 选择与替换

进入“采集与试验 → 含量试验 → 报告”，点击“选择模板”。文件名不要求为 `sheet.xlt`。选择后会为当前试验创建新工作簿、补齐当前测量数据，并作为之后新试验的默认模板。新工作簿完成后才切换关联；失败会显示原因，原工作簿及人工修改保留。此时继续测量仍写入旧工作簿，“更换未完成”及原因持续显示，不会被普通的“已同步”状态覆盖。

主设置“采集与试验 → Excel 模板”管理相同的模板来源，分别设置含量和直径模板。此处修改先进入草稿，应用／确定后保存，取消不生效；已打开工作簿保留，需要更换当前试验时在报告页点击“重新创建工作簿”。

没有指定外部文件时，默认直接读取程序资源目录中的 `runtime/content-templates/sheet.xlt` 或 `sheet_dia.xlt`。本次 Windows 安装包的资源位于安装目录下，例如 `C:\程序安装目录\runtime\content-templates\sheet.xlt`；以页面显示的完整路径为准，“所在位置”可打开实际目录。旧版本生成的用户目录 `templates/sheet.xlt` 不再自动优先使用，也不会被删除；如果它包含需要保留的自定义内容，可以显式选择该文件。

替换同路径模板文件后，已有 Excel 工作簿保持原样。再次进入页面会检查模板内容变化并提示；点击“重新创建工作簿”后，才按新内容创建。之后新建试验直接使用当前文件内容。

“查看 Excel”定位当前成功关联的工作簿。报告页显示工作簿名、实际模板来源及 SHA-256 摘要，避免把留给用户保存的旧工作簿当成新工作簿。

## 模板内容与数据边界

- 模板是完整工作簿：保留工作表名称和顺序、可见性、初始页面、格式、公式、控件和 VBA。
- 创建实时工作簿时，不自动改变模板的标准／组距，不自动运行 CU“分组”宏。用户模板自身的打开事件仍遵循 Excel 现有宏策略；不会修改 Office 信任中心或绕过宏权限。
- 首次填写约定的样品／人员信息；量化输入由 FDM 持续维护。之后人工报表信息仍由用户维护。
- “更新报表信息…”中明确勾选标准／组距，或“重新统计报表”，才执行对应的报表操作。调用分组宏前保留工作表可见状态与当前页，避免它隐藏自定义报表页；宏本身计算和修改的统计区域仍按模板定义处理。
- “重新输出测量数据”补齐当前工作簿的受管输入，不等同于更换模板，也不恢复 FDM 的标准／组距。
- 一次性导出使用当前关联的模板。如果源文件内容已变，先重新创建工作簿，或直接在 Excel 保存当前工作簿，避免同一次试验两个出口使用不同模板。
- FDM 不自动保存、关闭或覆盖用户已关联的工作簿。旧工作簿交给用户保存／另存。

文件缺失、映射不匹配、模板读取失败或偏好文件损坏会明确报错，不静默回退到另一份 CU 默认模板。

## 诊断与安装版验证

在报告页收集／导出“模板报告诊断”，可以取得：实际程序与构建身份、配置目录、模板来源和哈希、当前工作簿／Excel 进程身份、关联代次与错误阶段。诊断不包含完整进程命令行或整个模板内容。

本轮新增安装版验证入口，包含在应用中；无需另装 Python。请使用**包含本次修改**的安装包安装后，在 PowerShell 执行：

```powershell
& "C:\实际安装目录\FiberDiameterMeasurement.exe" `
  --verify-trial-template-flow --require-installed `
  --source-template "D:\模板\sheet.xlt" `
  --output "D:\验证\模板完整流程-新目录"
```

输出目录必须尚不存在。验证使用独立偏好目录和模板副本，打开真实主窗口及桌面 Excel，不启动相机。它通过正常采集页导航和报告按钮选择模板，自动填入文件选择路径、丢弃本次测试项目；随后启动第二个程序进程检查重启后的选择。原模板前后哈希会核对。

验证分别检查程序默认模板首次自动打开和报告页显式选择。特别检查用户模板中的“特种毛(报出)”“麻棉(报出)”“分组加权统计”“织物纤维含量报告”，以及工作表可见性、初始活动页、抽样公式／格式、控件数量、既有数据补齐、同路径替换、缺文件和更换失败后旧工作簿的人工备注。坏模板覆盖同一路径后继续入账第二条测量，核对仍写入旧簿且失败提示保留；重新选择有效模板后，两条数据一并带入。

`--require-installed` 同时检查冻结程序身份与安装登记路径；源码运行或未登记的便携程序不会被记成安装版验收。报告 `result.json` 的 `passed` 与 `installed_validation` 必须都为 `true`，且实际构建身份正确，才能据此认定本轮安装版流程通过。

测试只清理明确由本轮创建且进程身份匹配的测试工作簿，其他 Excel 工作簿不处理。截图、日志、报告和模板副本保存在指定输出目录，不加入 Git。通常由用户制作安装包；本轮另获一次构建测试包及安装验证的授权，后续仍遵循用户自行打包的约定。
