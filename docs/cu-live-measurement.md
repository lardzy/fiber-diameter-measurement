# CU 测径与实时含量试验

本功能在 `lard/cu-live-measurement` 分支开发，入口为主窗口“试验 → 实时试验”。原有静态测量、分割模型快速测径和面积识别保持独立。core 发行配置也包含实时试验。

## 操作

1. 选择当前图片、本机相机或外部 CU 画面。当前图片使用文档原始 8 位像素；16 位和浮点图像需要先显式创建 8 位图像副本。外部 CU 的像素是窗口渲染结果，必须单独标定。
2. 确认标定、操作者、经纬方向和材料类别。首次使用可点操作者旁的“改名”，把“操作者 A”改为实际姓名；改名保留此人的记录，也可撤销。另有参与者时再“添加”，最多三人。常规贴边与全图算法要求等比例标定；非等比例标定只能由用户主动选择自由测量。
3. 默认跨纤维两次点击。首次点击保留已经绘制的那一帧，第二击使用本次事件坐标。可切换拖动；Esc 取消草稿，右键取消草稿并打开非模态选类菜单。主画面继续更新。
4. 贴边失败显示原因，不自动退化为自由测量。超出类别范围的结果留在待确认区，显示测量编号、类别、直径和范围；画面中的橙色虚线表示“未入账”。核对提示后选择“保留”“改为当前类”或“放弃”，按钮只处理正在显示的那一项；改类后仍越限，需要再次明确保留。范围不会自动判定纤维材料。
5. 全图分析按按钮时固定一帧；传统和多尺度算法可切换。候选先审核，可逐条选类或批量赋类后确认；未确认候选不进入含量统计。
6. 右侧保留 CU 最多九类直接操作表和“先选／后选”，新试验先配置绵羊毛、山羊绒两类，其它类别通过“更多设置与汇总 → 设置本方向类别”配置。先选用于下一次测量；后选绑定当前视场、当前操作者和方向的最新测量操作，在计算、核验或待确认时也可改类，不会误改前一条。最新操作已取消或失败时，选类只准备下一次测量。数字键 1–9／小键盘对应类别，始终可见的模式开关区分“数字键选类”与“数字键额外计数”。额外计数模式下，数字键选中对应类别并补一根，不触发后选；减号只减少当前类别补计数。按键自动重复不会重复计数。行内加减不改变选中类别，也不创建虚假直径。
7. 视场变化清除当前标记、草稿、候选和未入账结果；历史保留。连续两次稳定检测后恢复。来源、分辨率、标定、操作者或方向变化均隔离旧请求。
8. 选择当前方向、经纬混合或多人汇总查看计算。保存项目保留完整试验；CSV 导出原始测量／补计数账本，Excel 另含当前统计引擎的方向、经纬和多人汇总。切换／新建试验为不同样品保留独立账本。

工作区中央是实时画面，右侧是类别与高频操作区；画面下方切换“当前视场”“试验历史（全部操作者）”“全图候选”。历史表包含当前试验全部操作者的已入账记录，可通过操作者列区分；候选页不属于账本，确认前不计入实测数或含量。经纬重量、类别和计算设置、原图开关与导出位于“更多设置与汇总”。

后选与待确认按钮的目标可能不同：后选跟随最新测量，待确认区按顺序处理首项，界面会显示两者的测量编号。已经入账的最新记录若后选到越限类别，系统提示并保留原类；确需修订时，在“当前视场”或“试验历史”选中记录，使用“改径／改类”。全图批次确认后，后选可修改该批最后一条；若已有更晚的未完成手工测量，则继续作用于该手工操作。

撤销／重做覆盖测量、计数、改类、改径、删除和操作者改名。手工草稿、计算、核验或待确认尚未结束时会提示等待或处理，避免撤掉此前的记录：草稿用 Esc 取消，计算／核验等待结果，待确认选择保留或放弃后再撤销。已入账原图后台写入和单纯全图候选计算不阻止撤销。

“保存测量原图”默认开启，同帧多条记录共享完整无损 PNG，后台写入。关闭只影响后续记录。历史原图在独立面板复核，不替换实时画面。写入失败显示失败状态，测量元数据仍可保存；用户可明确放弃失败原图。原图仍在写入时，关闭与项目切换会等待用户稍后重试，避免丢失已入账数据。

画面沿用恢复的 CU 类别颜色，标记格式为“场内序号 [类别号]”，配高对比标签；滚轮缩放、中键平移、双击中键或“适应画面”恢复显示。变换显示取消未完成手势，已入账历史不受影响。详细迁移对照见 [CU 操作过渡说明](cu-live-transition.md)。

入账前必须核验当前最新已显示帧。生产工作区将灰度／频谱预处理和有序判定分为两个后台阶段，画布持续接收已完成核验的帧，实际绘制后才登记已显示帧。新到但尚未显示的帧不会延后当前入账；显示又向前推进时，核验目标也随之推进，但等待起点不重置；超过两秒明确拒绝本次入账。该规则同样适用于越限保留和整批全图确认。不会为了持续噪声输入下的吞吐量，允许未经检查的新画面绕过移动清场规则。

遇到暂停先看状态栏：视场移动时等待“视场就绪”后重新测量；核验超时的结果未入账，稳定后重测。缓冲暂满时等待任务或原图写入释放，不必点“新视场”，已有记录不会因此清除。来源不可用时检查连接并重新选择来源、核对标定；若提示旧来源仍在释放资源，稍后重试切换或关闭。

## 算法与统计版本

人工贴边 `cu-manual-portable-v1` 保留非标准阈值、连通域、边缘顺序、拟合、角度约束及平均垂距定义。显示线段长度不等于算法直径，不额外补像素。计算内核在现有 C++17／pybind11 模块内执行；只复制局部 ROI，释放 GIL，并保留取消检查。

传统全图保留候选关系及最坏平方复杂度。多尺度保留 Mid → Cu → Thin 顺序和像素补偿。共享内存传入一个常驻隔离进程；同一时刻一个任务。默认 30 秒硬超时、2 GiB 算法预算、10,000 候选上限；资源不足、超时、取消、崩溃分别报告，不能等同“未检出纤维”。全图与重型分割／面积推理共享计算许可，人工测量独立。

含量支持恢复的 11 个方法标签、普通／免脱色汇总、纤维／织物、四种组距和原始直径。默认 GB/T 16988-2013 恢复路径、2.5 μm 分组、普通汇总。计算使用全部有效记录和动态分组，记录追加与统计增量更新不扫描完整历史。密度缺失、只有计数而无直径、无效经纬重量等明确显示未就绪。方法名称不代表已获现行标准或物理计量认证。

材料目录包含恢复的 40 条定义（普通版本前 37 条）。试验保存材料 ID、密度、范围和来源快照。未知字段不赋予推测含义；恢复值为零的密度不擅自补全。经纬与多人层级分别计算，未完成参与者不作为零贡献悄悄稀释结果。

完整权重、棉麻／苎麻分支、单样本与舍入规则见 [含量计算说明](cu-content-calculation.md)。算法保留、有意修复、容量扩展和未验收项集中列于 [CU 差异清单](validation/cu-live-measurement-2026-10-15/CU_DIFFERENCES.md)。

修改组距会在后台重算，底部显示“尚未应用”并可取消；完成前保留原设置与实时画面。期间继续测量或编辑会使旧重算结果失效，界面提示后重新提交即可。重算期间先等待或取消，再修改设置、撤销／重做或保存。关闭会先请求取消，尚未退出时提示稍后重试。已加载的自定义组距会保留，不因确认其它设置而被替换。此路径属于正式首轮采样后的独立修正，验证状态见上述差异清单。

## 组件边界

- `live_experiment/frames.py`：帧身份、不可变像素、绘制完成 token、保留帧预算。
- `live_experiment/controller.py`：手势、异步顺序提交、运动屏障、视场版本、入账、候选审核。
- `live_experiment/motion.py`：CU 参考比较与相邻帧变化；生产修正有符号强变化计数。
- `live_experiment/models.py`、`statistics.py`：试验账本、增量统计、撤销／重做、方法和材料快照。
- `live_experiment/evidence.py`、`png_stream.py`、`project_assets.py`：异步证据、分块无损编码、去重、摘要验证与项目资源落盘；另存为成功后同步更新历史原图引用。
- `live_experiment/sources.py`、`capture_helper.py`：相机与 CU 来源、世代、断流与共享内存桥。
- `native/cu_manual.cpp`、`native/cu_automatic.cpp`：计算内核；`native/windows_capture.cpp` 独立编译为 Windows 捕获扩展。
- `ui/live_experiment_workspace.py`：独立工作区；主窗口只负责入口和项目生命周期。

512 MiB 预算计入保留帧、共享采集余量和 PNG 编码工作区。分块 PNG 不创建完整 RGB 副本或完整压缩数组；工作区按 2 MiB 加两块扫描行预留，同一串行写入器取最大值，独立写入器相加。编码器固定使用 zlib-ng 1.0.0；不易压缩的图像使用标准 PNG 的无压缩 DEFLATE 数据块，以文件体积换取写入速度，像素及透明度不变。该预算是应用缓冲账本，不是整个进程的操作系统内存上限；Qt、SDK、算法、Python 账本和驱动仍需分别纳入实际峰值报告。

## 构建与复现

沿用既有一键打包入口。计算模块源码清单与 Windows 捕获模块分开，缺失或源码摘要过期时自动重建并执行真实微型计算。构建依赖 pybind11，OpenCV 固定 4.13.0.92。Windows 捕获使用 MSVC、Windows SDK 与 C++/WinRT，不向计算模块引入第二套 OpenCV C++ 库。

```sh
python setup.py build_ext --inplace
QT_QPA_PLATFORM=offscreen python -m pytest -q tests/test_cu_manual_measurement.py tests/test_live_experiment_runtime.py tests/test_live_experiment_content_models.py tests/test_live_experiment_content_statistics.py
python scripts/validate_cu_manual_measurement.py --help
python scripts/validation/validate_cu_automatic_gold.py --help
python scripts/benchmark_cu_live_measurement.py --output results/cu-live-performance.json
```

Windows 实际 Qt 工作区的采样使用以下 PowerShell 命令，在没有并行测试或构建时逐条执行。短程需要分别覆盖静止／动态、原图开／关与后台全图负载；完整参数和固定验收规则见正式报告。

```powershell
$env:QT_QPA_PLATFORM = "windows"
python scripts/benchmark_cu_live_ui.py --motion-input lsb-noise --output results/cu-live-ui-windows.json
python scripts/validation/soak_cu_workspace.py --qt-platform windows --size 4096 --duration-seconds 600 --minimum-accepted 2000 --output results/cu-live-2000-windows.json
```

后一条按实际通常不超过 2,000 根的使用规模，在 4096×2730 分辨率运行真实 QPainter／QTest 工作区十分钟，以至少 2,000 条为目标，包含 30 Hz 输入、每秒四次测量尝试、原图保存和每十秒一次传统全图分析。没有给产品增加 2,000 条上限。macOS 可显式使用 `--qt-platform offscreen`，其结果不替代 Windows 桌面验收。旧 `benchmark_cu_live_measurement.py --modes soak` 是无真实画布的控制器诊断，不能用来替代这项验收；程序退出码也不能替代报告中的性能门槛判定。

回放 CU 原金样需要外部证据目录 `/Volumes/LARD/cu_reverse`（Windows 使用同步后的验证子目录），不将旧软件二进制或原实验文件嵌入发行包。正式采样需在正确性测试结束后串行运行，固定来源摘要、环境、线程、预热和采样次数。

## 验收边界

本目录的实现说明不等于验收结论。画面持续更新也不等于测量已经入账；高分辨率动态输入可能触发核验超时，须分别检查测量成功率和延迟。本轮按 4K 为优化上限，默认短程采样为 2K／4K；不新增产品分辨率硬限制。4K 优化复测见 [本轮报告](validation/cu-live-performance-4k-2026-10-15/REPORT.md)，此前测试、Windows 包路径和已知差异保留在 `docs/validation/cu-live-measurement-2026-10-15/`。Parallels 的窗口捕获与安装包测试不能替代真实相机／采集卡、30 FPS 设备流、带时间戳运动录像以及物理计量验证。
