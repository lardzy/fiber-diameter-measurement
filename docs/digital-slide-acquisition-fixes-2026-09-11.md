# 数字切片采集响应与控制恢复修复

日期：2026-09-11。基线：0.4.5 / `bdf9a93`。本次保持版本号不变。

前置排查见 [采集问题审计](digital-slide-acquisition-audit-2026-09-11.md)。本文记录实施结果；审计文件中的测量和代码位置对应修改前的版本。

## 修改范围

### 相机帧与采集时序

- 相机回调把最新帧放入有界邮箱；Qt 待处理事件只带会话编号，不再逐帧携带整张图像。一个会话至多保留一个待处理唤醒。慢界面恢复后直接显示最新帧。
- 邮箱、界面和已接受的写入各持有自己的 `QImage` 值副本；使用 Qt 写时复制保证后续修改隔离，减少不必要的整帧深复制。已接受的采集帧、写入任务和请求式分析结果不会被显示合并规则丢弃。
- 采集使用源端会话、帧序号和接收时间判断停稳后的新帧。丢弃帧数依照源帧计数，独立于界面显示次数；旧会话、尺寸变化和等待超时仍会拒绝采集。
- `preview_frame_stats()` 提供接收、显示、合并次数、待处理唤醒数、最新帧字节数及年龄，便于进一步诊断。

### 逐帧界面工作

- 稳定帧只更新预览像素。设备、模式或图像尺寸变化时才同步控制状态和说明文字。
- 首帧、显示尺寸变化和进入切片模式时适配画面；窗口缩放继续使用画布现有的 FIT 行为。
- 普通实时分析上下文在数字切片模式保持隐藏，避免每帧反复显示、隐藏和重新插入布局。工具栏相同可见性与相同布局请求采用幂等处理，保留原有跨布局移除流程。

### 电机控制

- `MotionController.enabledChanged` 同步实际控制状态与界面开关。正常关闭、设备丢失和串口写入失败都会停止待执行的连续移动，且不会补发松键单步。
- 重新进入采集时显式恢复控制器，避免依赖已经勾选的复选框再次发出信号。
- 保留仍有效的手选串口；原端口缺失时才重新推荐。
- 串口读、写均配置超时，默认 0.2 秒。失败后不推进软件的命令位置，不自动重发；再次进入可重新建立连接。

### 网络操作与结果查看

- 路径检查、目录创建、空间检查、样本压缩估算、暂存准备、网络复制和发布在受控 I/O 线程中执行。调用方等待完成时运行 Qt 事件循环，持续处理预览与进度。
- 进度只保留最新值，不为每个复制块排队。网络打开保留取消；发布保留原有不可中途取消的语义。取消后等待当前底层 I/O 返回并收尾，不能强杀线程或丢弃恢复文件。
- 等待期间阻止重复开始及会释放所有者的工作区转换。断开设备不会递归执行正在进行的发布/清理；准备阶段结束时再次核对相机会话和电机状态。
- 原子发布、目标旧文件保留、失败时本机恢复副本的规则不变。
- 原始路径与文件版本在后台准备后交给渲染器；显示、切换页签及重新创建渲染器时不再重复访问原网络路径的文件状态。
- 未查看的采集结果仍登记为项目文档，并保留焦层、原点、保存和导出所需信息；其画布暂不分配视场底图或启动渲染器。第一次显示时再完成初始化。

### 大帧写入

正常队列字节预算仍为 64 MiB。单张合法原始帧超过预算时允许进入空队列；队列上界为 `max(64 MiB, 一张源帧)`，另有一张正在写入的帧。原始分辨率不变，也不会因为单帧超过预算而永久重试。

## 本机性能对比

同一 macOS 开发机，Qt 6.10.2 / offscreen，1920×1080 窗口、模拟相机和串口。每个尺寸调用 120 次真实预览帧安装函数。数值是 **UI 安装函数耗时**，不含屏幕呈现延迟或整个采集任务耗时。

| 原始帧尺寸 | 修改前 P50 / P95 | 修改后 P50 / P95 |
| --- | ---: | ---: |
| 640×480 | 3.45 / 3.88 ms | 0.014 / 0.024 ms |
| 1600×1200 | 4.63 / 4.93 ms | 0.52 / 0.64 ms |
| 3840×2160 | 5.02 / 5.29 ms | 0.73 / 0.84 ms |

阻止 UI 消费、连续产生 120 张 1600×1200 图像：修改前全部排队，保留约 879 MiB 像素，恢复处理约 580 ms；修改后只显示最新一张，邮箱保留约 7.32 MiB 像素，恢复处理约 5.36 ms。这里计算的是排队/邮箱像素，**不是整个进程 RSS**；当前显示和采集后端仍可能持有自己的图像。

原始路径状态查询注入每次 300 ms 延迟：修改前两次查询均在主线程，16 ms 心跳最大间隔约 878 ms；修改后一次查询在 `fdm-slide-io`，最大间隔约 69 ms。含异步等待的整个挂载约 378 ms，网络本身的等待没有被删除。

普通“未设置输出路径”警告框停留约 5.26 秒：128 张模拟帧全部显示，UI 心跳持续运行，没有待处理帧积压；回调至界面接收 P95 约 3.41 ms。使用共享像素的 `QImage.cacheKey()` 对应源帧与显示帧，不以 Python 包装对象地址匹配。该短时模拟不能代替现场长时间警告框停留测试。

连续 5 次完整模拟采集，每次 6 张 512×384 图像，经过真实写入、暂存、发布和文档登记，未选择查看：全部成功，完成后没有活动写入或渲染线程，X/Z 控制可用。单次总耗时约 1.25–1.65 秒；该短任务包含源帧等待、预检及刷盘，**不用于证明整体采集吞吐提升**。网络发布分支的目标是本机目录，不是真实 SMB。

## 正确性回归

新增专项回归覆盖：

- 120 帧积压合并、图像值复制隔离、旧会话晚到事件、显示回调期间再次来帧。
- 稳定帧不重排工具栏、尺寸变化仍更新画面。
- 丢弃 0 / 3 帧时拒绝停稳前的旧帧，并在没有 UI 投递的情况下使用合格的新源帧。
- 设备转换、设备丢失、反复进入退出、电机重新启用、手选串口和写入失败。
- 后台 I/O 期间 UI 心跳、禁止关闭/重入、取消后线程收尾、异常后的忙碌状态释放。
- 大于队列预算的单帧写入及原始像素保持。
- 未查看文档的焦层保留、第一次显示时初始化、连续 5 次完整采集。
- 网络状态查询和发布的线程归属、缓存指纹兼容、准备时设备断开、发布失败保留旧目标和恢复副本。

验证日志及修复前后 JSON 位于仓库忽略目录 `.tmp/acquisition-audit/`；完整专项测试见 `tests/test_digital_slide_acquisition_responsiveness.py`。

最终同进程全量回归：**2762 passed，1425 subtests passed，411.85 秒**。新增采集专项与工作台主题/交互组合测试：44 项通过。

第一轮全量测试在主题切换阶段长时间重绘，采样后中止；专项组合通过后重新执行，全量正常完成。复核时该阶段存在前面测试遗留的 16 个未关闭隐藏主窗口、约 4.3 万个控件，没有新增进度窗口残留。采样落在 Qt `setStyleSheet` 重绘链路，没有发生 Qt 崩溃。这属于本轮测试运行的限制，不把它当作 Windows 采集卡顿的已确认原因。

## 验收边界

本机测试不能证明 Windows 相机、串口驱动和真实局域网的持续运行已经恢复到现场标准，也不能把“10 分钟任务变为 30 分钟”归因为已证实的单一原因。需要使用重新构建的 Windows 包，在同一相机和局域网目标上连续采集，覆盖警告框久放、完成后不查看、进入退出及 X/Y/Z 控制恢复。网络极慢时发布仍需等待，但不应阻塞预览和进度刷新。
