# 混合模式实时帧间隙丢点修复

日期：2026-10-21。版本保持 **0.4.10**，基线 `dc25a40`。本轮修改一个产品文件 `src/fdm/ui/live_measurement_canvas.py`；不调整混合模式同时支持两点与拖线的规则，不改测径算法或视场稳定判定。

## 已复现原因

`set_frame()` 收到新预览帧后立即更新待绘制帧，但 `controller.presented` 在 Qt 完成绘制后才更新。原混合模式要求这两个帧对象完全相同，在正常的到帧与重绘间隙会静默忽略按下事件。仅手工模式不存在这项门槛。

真实 Workspace、`live=True` 模拟采集、原视场检测和真实贴边测径的受控复现：首点 A=(100,100)，同像素新帧到达但尚未重绘时点击第二点 B=(180,100)。原混合模式丢掉 B，下一次用户意图作为首点的 C=(80,130) 接上遗留的 A，实际提交 A→C，算法返回 `no_complete_crossing`；仅手工模式正确提交 A→B，得到 15 μm，C 只建立新草稿。[修复前轨迹](diagnosis-before.json)记录这一差异。该场景没有上一条失败任务或候选参与。

## 修复范围

- 点击使用实际已绘制帧及其坐标变换，允许同源、同代次、同尺寸的新帧等待绘制。
- 换源、分辨率、显示修订号变化及清空画布仍拒绝旧输入；继续执行现有视场、标尺、操作者、方向和帧内存预算检查。
- 候选点击沿用实际绘制的命中几何及批次，不能将残留失效候选降级为手工首点。
- 有界诊断轨迹增加原始鼠标事件类型、已绘制帧/待绘制帧身份及拒绝原因，便于离线核对。

没有强制重绘、插入事件循环、冻结采集或改用尚未显示的图像。项目数据、版本和显示偏好不迁移。本次不改变丢失焦点/鼠标抓取等输入中断的既有取消规则。

## 实机短测步骤

1. 确认使用本轮构建的 0.4.10；旧第七轮安装包保留作回退。
2. 进入含量试验，选择操作者、类别和标尺，使用混合模式与贴边测径。
3. 关闭自动全图分析，连续使用两点完成至少 30 条测量；每条结束后，下一次首点应只建立新线，不应立即提交。
4. 打开自动全图分析，交替点选候选与两点手工测量，再重复至少 30 条。观察首点、第二点及本场记录是否一一对应。
5. 检查持键拖线、Shift 临时手工、候选刷新、换场及返回页面仍按原规则工作。
6. 如仍出现异常，保留本轮构建 ID、失败文案和性能/输入诊断；重点核对 `press`、`manual_finish`、`task_submitted` 的交互身份及帧身份，不以 UI 当前选择推断执行路径。
