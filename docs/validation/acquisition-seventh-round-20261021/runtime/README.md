# 第七轮真实导航运行验证

验证使用实际主窗口导航、模拟相机 768×576 帧、原有视场检测、真实全图分析进程、Qt 画布点击、账本和 JPEG 写入。没有注入候选、运动判定或入账记录。macOS Qt offscreen 结果不代替 Windows 安装版或实体 Microview。

## 先行包快检

[冻结源码结果](quick-frozen.json)通过，运行期间产品指纹未改变。

- 静态采集 3.004 秒，只自动分析一次。
- 实际点击 3 条候选，3 条记录与 3 张 JPEG 均完成。
- 同批次尚有余项时，整组隐藏 0 次。
- 独立候选对齐 monitor poll 与 worker compare 调用均为 0。
- 换场保留 3 条点选标记，连续两次“新视场”没有续期，约 1.011 秒退出。
- [初始候选画面](quick-initial.png)、[换场保留画面](quick-retained-markers.png)。

首轮运行受沙箱禁止共享内存影响，真实分析进程没有启动，原始失败保留于[沙箱失败结果](quick-sandbox-failure.json)。经针对本地分析进程共享内存的权限放行后重跑；不将该失败归因于产品算法，也不修改产品以绕过共享内存。

脚本为 `scripts/validation/validate_acquisition_seventh_round.py`。快检与完整回归分别使用 `--phase quick`、`--phase full`，完整回归在先行包交付后执行。后续脚本补充的真实视场运动和渐变失焦场景，不追溯声称属于本次快检覆盖。

## 本版工作流性能对照

在全量 pytest、视觉矩阵与 Windows 功能负载结束、VM 内存恢复并静置 15 秒后，顺序运行两组 30 秒采样。输入均为 768×576、每 33 ms 一帧；每秒一次成功测量，同时写入局部 JPEG95；两组各有 29 条记录、29 张图片、909 个实际呈现帧。初始进程启动和准备不计入这段工作流窗口，候选耗尽后的真实新视场分析计入。

| 指标 | 手工自由测量基线 | 自动候选点选 |
|---|---:|---:|
| 呈现帧率 | 30.301 FPS | 30.301 FPS |
| P50 帧龄 | 3.134 ms | 2.854 ms |
| P95 帧龄 | 4.334 ms | 3.685 ms |

[配对比较及门槛](performance-comparison.json)、[基线原始记录](performance-baseline.json)、[候选原始记录](performance-candidates.json)。本组满足帧率下降不超过 5%、P95 帧龄增加不超过一帧；较小的负差值不解释为提速结论。这是**同一个第七轮产品的工作负载对照**，不是第六轮历史构建对比；模拟相机的接收时间至呈现时间也不是传感器至屏幕延迟。

## 验证器修正与保留的失败

- [100 次点选首轮失败](click100-script-failure.json)：第 9 条后切到新视场，脚本把“允许显示”的状态误作“新分析已经完成”，立即查找候选造成 `StopIteration`。修正为分析完成、存在可用候选且已实际绘制，再点选；产品未修改。
- [菜单首轮失败](menu100-script-failure.json)：验证器向组合框弹出容器发送 Escape，而非接收键盘的列表视图，弹出框未关。改为真实列表视图接收按键后通过；产品未修改。
- 初次三个 motion 延迟场景包装了未启用的 `_prepared_motion_work`，实际注入次数为 0；原始结果以 `latency-motion*-unexercised.json` 保留，**不计入延迟覆盖**。补齐实际 `_motion_work` 路径、增加注入次数断言后重跑，最终结果见汇总。
- [第一轮性能基线](perf-baseline-resource-transition.json)恰逢 Windows 验证 PowerShell 退出及资源恢复，明确[排除出比较](perf-baseline-resource-transition-note.json)，另行完成上述静默窗口配对。

所有运行输出目录均保留当轮验证脚本副本、脚本 SHA、产品文件指纹、输入轨迹与状态变化；已有 `result.json` 的目录拒绝覆盖。验证器后来增加或修正的场景不追溯算作早期快检的覆盖。
