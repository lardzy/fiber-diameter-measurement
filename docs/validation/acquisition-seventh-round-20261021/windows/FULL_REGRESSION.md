## 失败原件与补跑说明

1. 首次 100 次点选验证器在第 9 条后提前返回新视场，读取尚未出现的候选导致 `StopIteration`；Mac 同样复现。修正等待“分析完成且可用候选已经实际绘制”后，100 次通过。未修改产品。
2. 首次 100 次菜单验证器将 Escape 发给 QComboBox 容器而不是列表 view，导致测试断言失败。改为实际 view 后 100 次通过。未修改产品。
3. 首轮安装版 125% 截图失败时，本轮 PowerShell 运行器 PID 10508 私有提交达 47,019,810,816 字节、RSS 12,470,747,136 字节，客体可用内存仅 367 MB。后续 CLR 启动报 `0x800705AF`。精确核对 PID、创建时间及本轮脚本路径后准备了保护性清理，但执行时该进程已经退出，**没有发送终止**。脚本临时正文已被移除，无法断言是哪条辅助语句造成增长。未修改 VM 内存/分页配置、未重启或整机回滚。
4. 第一次 125% 补跑功能成功，但视觉复核发现遗留 `python.exe - Application Error / 0xc0000017` 对话框遮挡画面，该次截图不计为无遮挡视觉通过。精确核对标题、错误码及“确定”按钮后，只确认了两个排队的资源错误框，没有终止 csrss。第二次补跑得到干净截图及正常退出；旧图以 `*-resource-error-preserved.png` 保留。

原失败、第一次补跑与最后干净补跑均保留，不能将最初整组运行写为一次性 9/9 通过。详见 `full/harness-issue.json`、`full/vm-memory-incident.json` 和各原始 summary。性能测试在资源恢复后独立进行；最终客体可用内存 14.09 GB。
