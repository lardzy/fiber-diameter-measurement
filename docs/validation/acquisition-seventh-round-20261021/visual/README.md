# 第七轮视觉与输入隔离检查

日期：2026-10-21。版本：0.4.10。先行包交付后的补充检查；未修改产品代码。

**结果：16/16 组合通过本报告列明的检查。** 四套主题分别覆盖 1600×900 的 100% / 125% / 150%，以及 1366×768 的 100%。完整结果见 [matrix.json](matrix.json)，各目录的 `geometry.json` 包含控件位置、标记几何、截图实际分辨率、DPR、字体、窗口显示事件及对应产品源文件 SHA256。

## 环境与证据边界

- macOS、Qt offscreen；每组使用独立进程及隔离配置。尺寸指物理客户区，逻辑尺寸为物理尺寸除以缩放；150% 时整数取整使截图宽度为 1601 像素。
- 通过真实主导航进入采集与试验、真实子导航进入含量试验，使用 QTest 鼠标事件点选两条候选，再点击实际“新视场”按钮。
- 相机输入为 768×576 合成图像。三条候选几何为显式注入，成功入账沿用真实控制器事务路径；本报告不证明全图算法检出率或真实相机稳定判定。
- 保留时长通过现有设置控件设为 10 秒，便于截图及输入隔离检查；没有改计时器或人工延长组的到期时间。默认 1 秒、到期及多组独立倒计时另由控制器测试验证。
- 本次不替代 Windows 原生字体、菜单、任务栏/标题栏可用空间、高 DPI 跨屏和实体 Microview 验收。未在视觉矩阵运行时测 FPS 或帧龄，矩阵结束后已通知性能测试可以开始。

## 已执行检查

每组均执行并记录以下断言：

1. 两条候选通过实际画布点击成功计入，第三条候选仍留在画布。
2. 点击“新视场”后两条点选标记同时保留，后续正常帧不清除它们。
3. 在保留标记线上点击可建立手工第一点；保留层不产生候选命中或悬停结果。
4. 无按键移动 20 次只更新手工草稿，没有完成测量或增加记录；Esc 取消草稿，保留层仍存在。
5. 保留标记编号与当前草稿线段至少相隔 12 个逻辑像素，保留层位于当前草稿下方。
6. 保存、导出 Excel、相册图标及候选菜单入口完整可见；相册为 40px 宽纯图标和箭头，图标资源存在，无文字争抢宽度。
7. 菜单中保留时长控件完整显示；主导航位置不因换场改变。
8. 窗口事件中没有意外顶层窗口，没有模态消息或 Qt 槽异常。正常打开的候选 `QMenu` 单独列出，不计为意外窗口。
9. 保留层没有新增项目字段。每组配置隔离，不覆盖真实用户设置。

视觉复核查看了全部 16 张 `retained-draft.png`，并查看四主题 150% 菜单和局部滚动图。标记的线、端点和编号可辨认；编号没有盖住当前草稿。四主题的菜单文字、按钮图标、保存及 Excel 入口可读。图像视口保持实际像素模式：1366×768 下的图像纵向滚动属于 1:1 显示预期，不自动缩小。

## 复现命令

```sh
.venv/bin/python scripts/validation/validate_round7_visual.py \
  --theme light --size 1600x900 --scale 1.25 \
  --output docs/validation/acquisition-seventh-round-20261021/visual/light-1600x900-125
```

其余主题使用 `dark` / `navy` / `warm`，缩放使用 `1` / `1.25` / `1.5`。脚本运行前会设置 Qt 平台和 DPI，再创建应用。

开发脚本时纠正了两处验证假设：候选文字菜单本来没有图标，不应套用相册按钮的图标断言；`visibleRegion()` 单独检查会误计部分裁切的类别行，最终使用逐祖先裁切检查。矩阵均按最终脚本重新执行，结果和日志为重跑结果。未因验证脚本错误修改产品。
