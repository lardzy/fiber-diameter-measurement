# 第六轮离线 Microview 验收

此清单供联网不可用的真实相机设备使用。macOS 模拟图像、延迟注入和 Windows 虚拟机结果不替代本清单；本轮不修改全局视场稳定判定或测径算法。版本仍为 0.4.10，以交付清单中的构建 ID 和安装器 SHA-256 区分。

**本候选仍有已知未通过项：** Windows 虚拟机的 100 次连续点选中，主线程垃圾回收使一次核验超时，其他候选安全暂停约 335 ms 后恢复；100 条记录及证据均保留。该结果不算“正常负载候选始终可见”通过。实体设备请重点记录是否出现同类暂停，并连同诊断反馈，不能仅因最终入账正确就忽略它。

先备份实际项目，保留此前可用安装包。记录 Windows 版本、屏幕分辨率与缩放、相机型号、实际取帧尺寸、采集帧率、所选全图算法及存档方式。

| 步骤 | 操作与应观察结果 |
|---|---|
| 首点，自动关闭 | 进入含量试验、完成操作者／类别／标尺准备，选择混合输入。点击纤维一侧背景一次，松开后移动鼠标、静置，再打开并关闭菜单；不得自行提交第二点或出现本次失败卡。再点另一侧才提交。至少重复 20 次，包含首次与连续测量。 |
| 首点，自动开启 | 勾选图像控制区“自动”，等候选出现后重复上述步骤。空白两点、候选上起拖、已有第一点时第二点落在候选附近，分别核对手工与候选提交数量。 |
| 拖线与边界 | 持左键实际移动再松开，应提交一条；单击后无按键移动不提交。重复同点、双击候选、菜单切换、窗口失焦、取消后迟到释放不得重复入账。测试普通鼠标；如使用触控板，另记录其结果。 |
| 旧失败与新草稿 | 连续测量中前一次失败若晚到，只能明确归属于旧测量编号，不能遮挡新草稿、改写新测量状态。不要为了制造失败而把无效结果手工计入。 |
| 同一视场周期 | 固定相机和样品，底部保持视场就绪至少 60 秒；候选不得自行换批或重复全图分析。打开菜单、接收一部分／全部候选、无候选结果，不应重新触发自动分析。 |
| 真实换场 | 调整到另一视场，等待原有稳定提示恢复后，自动分析应仅增加一次。连续两次快速换场也应拒绝旧候选／旧回调。 |
| 候选暂时无法对齐 | 如因曝光、模糊或抖动无法核验，应暂停候选命中，实时画面继续。全局视场未变化时，不能靠重新分析来循环刷新；恢复严格核验后应保留原编号和赋类。持续无法确认时可手工测量或显式刷新。 |
| 连续点选 | 跨多个视场累计接受至少 100 条。每点一条仅改变该条状态，其他候选编号和赋类保持；同一候选不可重复入账。正常负载下不应因一次点击而整组隐藏。真实计算过载允许安全暂停，需记录发生时间和诊断，不能算作“全程可见”通过。 |
| 相册入口 | 当前测值旁的图片图标主区打开相册，小箭头打开上一条证据／固定小窗／存档模式菜单；两部分互不误触。四套主题及常用缩放下无图标箭头遮挡，保存和 Excel 导出仍可达。 |
| 持续运行 | 持续采集、测量与局部 JPEG 存档至少 30 分钟；核对图像证据来自实际测量帧、无重复记录、无旧候选复现。检查停止／返回、保存重开及相册复核。 |

发生异常后，尽快从 **“全图分析／刷新候选”旁箭头 →“导出离线性能诊断…”** 保存 JSON，同时记录发生时间并录制屏幕（尽量包含鼠标按键动作）。输入轨迹有长度上限，不要在异常后长时间反复移动鼠标才导出。

诊断重点是 `frame_sampling.input_trace`（按键事件、交互 ID、任务 ID、提交原因）、`frame_sampling.automatic_cycle`（周期、分析次数与批次）和 `frame_sampling.candidate_preview`（暂停原因、恢复耗时、实际绘制显隐）。它们是运行证据，不是测量准确率。提供原始诊断文件、相关项目副本与必要图像证据，保留首次失败，不只提供重启后恢复的截图。

性能应在同一设备、同一输入条件下做基线／功能开启对照：FPS 降幅不超过 5%，P95 帧龄增加不超过一帧。录屏本身会增加负载，性能采样与录屏结果分别记录。不同机器或软件渲染环境的数值不可直接作差。

每项填写：通过／失败／未测、构建 ID、操作者、时间、诊断文件名。当前实体 Microview 状态为 **待验收**。
