# 自动周期与延迟验证

在 macOS、Qt offscreen 和模拟 768×576 图像下，通过真实导航进入含量试验，实际配置操作者／类别／标尺，运行生产全图分析子进程、严格对齐和画布呈现。没有注入候选或业务记录，也没有修改全局稳定阈值。

- **静态周期**：精确计时 60.001 秒，1,862 个源帧，仅一次自动分析，批次不变。见 [原始结果](macos-cycle60-final.json)。
- **独立对齐失效**：逐步增加实际图像模糊，确认每一步全局仍为 ready 且 field_epoch 不变；候选暂停命中，但编号、批次、原参照帧保留。恢复原始图像后重新通过严格核验，恢复原批次。点击“新视场”后才产生第二次分析。
- **界面晚消费**：40／80／200 ms 三种 GUI 阻塞，各注入六次；分析次数仍为一，批次不变，三组均无候选暂停事件。
- **实际工作超时**：40／80／200 ms 在核验工作完成前分别注入 17／10／5 次延迟；每组均只暂停一次、恢复一次，原因分别为 `verification_late` 与 `timely_recovery`。恢复后批次不变、分析次数仍为一。没有放宽帧龄或对齐条件。

六组源文件指纹前后均一致，见 [延迟摘要](latency-summary.json)及同目录原始 JSON。此处验证生命周期和故障注入，不用其运行时帧率替代独立性能配对；运行期间主机另有单元测试。Qt 视频和真实相机测试另行记录。

夹具准备时曾直接模糊合成细线，触发了原全局运动检测，因而被验证脚本拒绝；改为受原判定约束的逐步模糊。首次名义 60 秒计时还发现 Qt 粗定时器提前约 0.48 秒，已改为精确定时器与单调时钟下限后复跑。本报告使用最终精确计时结果，不把夹具失败或 59.516 秒结果算作验收通过。
