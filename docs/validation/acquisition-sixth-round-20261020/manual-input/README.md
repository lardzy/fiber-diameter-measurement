# 手工输入事件验收（第六轮）

结果：通过。保留默认混合输入，全部画布操作使用普通左键，不使用 Shift 绕过候选。

环境为 macOS / Qt offscreen、独立临时配置、768×576 固定合成相机图像，主窗口 1366×768。通过主导航进入采集工作区，再实际点击含量试验子页；操作者、类别、标尺和自由测量均经对应界面入口设置。

| 场景 | 自动关闭 | 自动开启 |
|---|---|---|
| 普通单击首点后等待 | 草稿保留、无提交 | 草稿保留、无提交 |
| 首点后 1,000 次无按键移动 | 草稿保留、无任务、无入账 | 草稿保留、无任务、无入账 |
| 持左键移动并释放 | 实际测量流水线计入 1 条 | 实际测量流水线再计入 1 条 |
| 前任务失败晚到，新首点已经建立 | 草稿保留、不出现失败卡、不修改当前测值状态 | 同左 |

自动开启场景使用真实分析与对齐工作进程，得到 9 条候选；没有注入候选或测量记录。仅“前任务失败晚到”场景使用受控 Future 返回 `endpoints_not_background`，以稳定复现异步次序；不是算法判定准确性的验收。旧失败在底部以具体测量编号显示，其任务 ID 与当前交互 ID 分开保存在诊断中。

- [过程录像](manual-input-qt-offscreen.mp4)：8 fps Qt 窗口抓取，底部附阶段说明。不是 Windows 桌面录像，不验证原生输入或 Microview。
- [验收结果与事件轨迹](manual-input.json)：8 个阶段截图对应的状态、每阶段快照最多 512 条输入轨迹、提交原因、任务 ID、反馈归属、源代码哈希。
- `auto-off-*.png`、`auto-on-*.png`：两种自动开关状态下的首点、移动、拖线接受、旧失败晚到截图。

此录像有截图和编码开销，不作为 FPS 或帧龄性能基线。普通真实拖线采用自由测量，本脚本不评价贴边测径质量；两种算法的交互事件回归另见测试报告。Windows 原生鼠标、触控板、真实相机和高 DPI 硬件仍需相应验收。

运行：

```sh
.venv/bin/python scripts/validation/validate_round6_manual_input.py --output docs/validation/acquisition-sixth-round-20261020/manual-input
```

需允许本地工作进程使用共享内存；沙箱内无法完成自动分析的录制尝试不作为通过证据，以上为开放本地共享内存后的最终结果。临时用户配置在结束时清除。
