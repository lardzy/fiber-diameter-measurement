# 采集与试验重构验收记录

本次在 `lard/cu-live-measurement` 继续开发，版本仍为 0.4.8；没有合并、推送或提交。已有暂存改动保持原状。主要场景是 768×576 Microview、每次试验约 2000 根，原图默认不保存。

## 操作入口

主工具栏选择 **采集与试验**，使用原来的设备菜单选择 Microview 并开始采集；内部切换 **实时采集／含量试验／直径试验**，不重新打开设备。不再提供外部 CU 实时画面来源。

测量区保留两次点击；画面继续更新。右侧九类固定行保留 CU 的计数与选类位置关系，最新直径在上方，详细配置和报告进入“试验设置”，本场／历史记录按需展开。

- 数字键和小键盘 1–9 默认补计，不改变下一根的测径类别。
- 单独按下并释放 Ctrl 切换 NK；Ctrl+C、Ctrl+Z 等组合键不切换。
- NK 数字键、类别按钮、画布右键释放后的菜单用于选类；选类取消未完成草稿。
- 后选只修改当前有效操作对应的最新实测记录；失败、取消、换场后不回改更早记录。
- 减号只减少补计数，最低零；长按不重复计数。文本输入、弹窗和非活动窗口不抢键。
- 下拉框和数值框即使聚焦也不响应滚轮改值，包括 Qt 自带标定／改径弹窗；展开列表只滚动浏览。
- 新试验默认关闭原图保存；旧试验显式保存设置继续尊重。

## 采集实现与设备边界

`CaptureSessionManager` 是唯一设备所有者，试验使用幂等订阅。沿用设备枚举、初始化、参数及 helper；停止异步投递，辅助进程监督器负责超时终止。共享内存中只保留等待确认的一帧，主进程复制到独立不可变像素后再确认；测量绑定实际绘制完成的帧。

独立 Windows C++ `_microview` 模块使用核实过的 `BOOL WINAPI(PVOID, ImageInfo*, PVOID, ULONG)` 回调，20 字节元数据，移除指针经 DWORD 传参。回调不进入 Python／Qt、不编码图片、不等待 GUI。修正 `SkipPixel` 为每行前缀，丢弃无法确认的半高场，停止顺序为停止投递、注销回调、等待回调退出、关闭设备、释放映射。

原生测试 DLL 验证了大于 4 GiB 的设备、上下文和像素地址，8/24/32 位格式、非零前缀、容量变化、迟到回调和停止竞态。真实 helper 用例包含共享会话、崩溃恢复和 20 轮启停／订阅切换；另外原始 backend 也执行 20 轮启停。测试 DLL 没有进入发行包。

**虚拟机没有真实 Microview 板卡。** 真机连接、处理前回调与 CU 处理后画面的差异、方向／裁边、奇偶场、完整帧率及物理换场仍需现场核验。回调次数、完整帧率、显示帧率和帧龄应分别记录，不对 PAL 设备硬套 30 FPS。

## 模板与统计

测量侧栏仍用本地增量统计。报告由独立 Excel COM 进程从模板创建副本，输出 XLS／XLSM，保留 VBA、按钮、公式和打印区域；没有重建为丢宏的 XLSX。模板标准写选择索引 D10，组距写 F10，不覆盖 C10，也不调用会重置组距的 Standard_Change。

默认写入 `原始数据`：日期 A1；操作者 D3/V3/AN3；样品 E1/W1/AO1；编号 G1/Y1/AQ1；六组列 D:L、M:U、V:AD、AE:AM、AN:AV、AW:BE；重量第 5 行，材料／密度／补计第 6/7/8 行；原始直径第 25 行起。只清理约定输入区，不覆盖 9–24 行公式。额外计数不产生直径。

用户模板工作副本与随包默认模板分开；升级不覆盖现有副本。支持选择模板、打开模板、所在位置和 JSON 输入映射。模板不按 MD5、SHA、大小、公式数量或工作表数量限制。其它程序二进制仍进行完整性检查。

[Excel 导出矩阵](excel-export-matrix.json)覆盖原普通版、免脱色版、当前自定义模板，各 0/1/1488/1500/2000 条，共 15 次真实 Excel 导出。独立只读检查逐条确认原始直径、样品编号前导零、864 个原始区公式、VBA、工作表数量、按钮数量和打印区域保留。模板原文件未改写。

[独立保留性核对](excel-preservation-results.json)记录了这 15 份报告的逐项结果。另将模板增加自定义工作表、公式、字体和打印区域，再导出 1／2000 条，两次均成功，见[修改模板导出证据](edited-template-exports.json)。把修改后的模板替换到 core 冻结目录后，资源校验及整个冻结程序自检也通过，见[修改模板后自检](edited-template-frozen-self-check.json)。不随本报告复制用户模板或生成的实验工作簿。

1500 条触发原 CU 分组宏 1488 范围提醒；2000 条还检测到原计数公式只统计 1500 条。完整记录照常写入，报告状态为“需要复核”，不擅自延长用户公式，不用本地含量覆盖 Excel。自动执行宏仍遵循用户 Office 宏策略；自定义宏可能按自身逻辑改变页面可见性，修改计算范围后需重新核验。

真实 Excel 保存时发现旧 XLT 的兼容性检查对话框阻塞，现只在报告副本关闭该保存检查，不修改模板。[微软 CheckCompatibility 说明](https://learn.microsoft.com/en-us/office/vba/api/excel.workbook.checkcompatibility)。报告超时只清理本次创建的 Excel 实例，采集与记录继续保留。

## 正确性与性能证据

Windows 专项回归：218 tests、5 subtests 通过，包含原生 ABI、helper 启停、输入、非冻结操作、本地统计、模板映射和主窗口。

macOS 分批覆盖全部用例后，新增全屏状态栏问题已修复并通过主窗口复测。原来四项布局失败在保护的主窗口基线也出现：导出设置在深浅主题下的滚动条，以及测量检查器的两项区域顺序测试。长时间单进程全量执行还出现过 Qt 后台对象退出时的锁等待／崩溃，不能把分批结果宣称为单进程全绿。图标刷新已移出样式通知栈并合并重复更新；该变更的主窗口、主题、保存和冻结探针专项为 159 通过、20 subtests，通过之外仅上述检查器两项基线失败。

### Windows 高频交互实测

Windows 11 26200、Parallels ARM64／4 vCPU／16 GiB，运行 x64 Python 3.12.13，PySide6 6.10.2、OpenCV 4.13.0；OpenCV、OMP、OpenBLAS、MKL 均限制为 1 线程。使用实际 Qt 试验页面、输入事件与绘制事件，合成 768×576 连续帧以 25 Hz 投递，带低位噪声和独立帧身份；原图保存关闭，1280×720、DPR 1。构建及其它测试结束后串行采样，每档预热 5 次、正式 30 次。不是物理相机或操作系统合成器的显示延迟测量，也不是完整主窗口的长期吞吐测试。

## 真机检查顺序

1. 保留旧版安装包及项目副本，启动新版，选择原 Microview 设备，确认 768×576 完整画面与方向、裁边、标定。
2. 往返三页、停止／启动至少 20 轮，检查无访问冲突、重开设备冲突和串场。
3. 先选 A 后按数字 2，确认只给 B 补计，下一根仍属于 A；核对 Ctrl/NK、右键、后选及中文输入法焦点。
4. 测量过程中移动载物台，核对草稿取消、候选失效、历史保留；断流后不能接受新测量。
5. 记录实际有效完整输入帧率和显示吞吐；使用 0/200/2000 条历史检查响应。2K／4K仅兼容回归，6K不在本轮优化范围。
6. 选择实验室自己的 sheet.xlt，核对方法、组距、输入映射和用户宏覆盖范围，特别是单一类别超过 1488／1500 条的情况。
