# 0.4.9 采集与试验工作流重构

**最终候选已重建并验证：** Windows 截图复核曾发现 1366×690／1280×670 客户区进入试验后被撑到 715 像素高。首候选已撤回归档；修复两处显隐时序并增加逐路由尺寸断言后，新安装器的五组冻结 GUI 检查全部保持目标尺寸。下方交付身份对应修复后的最终候选。

本轮按确认方案保留 PySide6 / Qt Widgets，重做工作区路由、采集显示、试验操作台和应用偏好。候选版本为 **0.4.9**。实施与验收阶段未提交代码；2026-10-17 按用户要求归档相关实现及其依赖的采集、保存和报告改动，保留既有数字切片、调研文档与 IDE 等其他暂存内容。

Git 归档保留源码、验证脚本、主要报告、测试日志及结构化结果。安装器、截图、录像、临时配置、测试项目及完整原始证据包保留在本地；下文媒体与交付链接需在该验收工作区查看。既有安装器仍以构建时的源码快照和 SHA256 为准，不将本次提交追认为其构建来源。

## 显示与布局记忆

采集家族共享实际像素、适应窗口、百分比和物理倍率。默认实际像素按物理屏幕像素 1:1 计算；超出视口可滚动和平移。百分比、倍率分别保存最后数值，同设备同帧尺寸保存视口中心。首帧、页面切换、停止重开、软件重开和 DPI 变化均重新应用选择。

物理倍率同时要求显微镜标尺和实际测量的屏幕标线；条件不足时保留倍率偏好并明确回退实际像素，条件恢复后应用。旧屏幕标线配置继续可读；新配置记录屏幕物理栅格，显示模式变化要求复核。普通测量文档的旧缩放/平移值继续使用原有语义。

应用配置目录中的 `acquisition-display.json`、`acquisition-workbench.json`、`workspace-layouts.json`、`trial-workbench.json` 采用版本字段，分别保存显示、最后子页、工作区布局与试验侧栏；它们不写入项目业务数据。项目快照继续兼容既有格式，未改变测量算法和三名操作者容量。聚焦输入框尚未失焦时，主保存快捷键也会先提交文本和重量，再创建保存快照。

## 尚未通过或需要真实设备验证

## 离线真机检查顺序

1. 保留旧安装器和项目副本，核对候选安装器 SHA256。先用空白配置启动，再用已有配置和旧项目验证升级恢复；不要覆盖唯一的原始项目。
2. 接入 Microview，进入采集与试验应自动显示；连续切换三页、手动停止后切页、返回测量再重入，核对导航、面板及设备打开/停止次数。
3. 对同一视场核对颜色、方向和标尺；两击测量、补计、改类、换场、切换操作者/方向、撤销重做、保存重开与报告统计逐项比对。
4. 逐一选择四种显示方式，停止重开并重启软件；百分比/倍率保留输入，同源视图中心恢复。切换屏幕和 DPI 检查 1:1 及倍率回退提示。
5. 打开记录/报告、扩展九类别、输入长中文样品名、键盘 Tab/快捷键操作；各主题下核对最低分辨率的实际可用空间，确保局部滚动可达。
6. 连续动态采集至少 30 分钟并记录帧率、帧龄、CPU/RSS、测量响应和错误；含拔插、无帧、保存失败及待确认结果。遇到已知 4K 动态核验超时应保留原始日志，不将拒收结果计入成功样本。
