# 纤维类别配置与 Excel 人工操作共存验证

日期：2026-11-11。版本：**0.4.14**。本轮交付源码、测试和文字说明；按后续用户指令仅在本地提交，不推送、不构建安装包。

## 实现范围

- “选择本次纤维”改为搜索、直接勾选、独立的数字选类顺序及同窗口参数草稿。常用组合只保存类别 ID 和顺序，整组校验后追加。已有实测、补计、待确认引用均阻止移除；无变化确认不创建修订。
- “纤维类别库”改为信息表格与详情编辑，支持名称／别名搜索、来源／完整性筛选、单项恢复和草稿保存。宽窗口并排，小窗口使用内部标签页。
- 原始直径、分类、补计、类别名称、密度和经纬重量持续输出。样品、日期、人员、标准及组距只初始化一次；后续更新需明确操作。设备和备注不写入。
- 正常输出按变化区域写 `Value2`，不保护输入区、不反复选择工作表、不重建分组宏、不做整表旧数据核对。模板原有保护不变，Excel 手动计算模式不变。
- 固定批次身份与操作游标恢复部分写入；已确认输入、计算和保存状态分别管理。只读失败不触发重写，关闭工作簿停止关联。更新报表信息与重新统计属于独立操作。
- 同修订重新输出也等待该批 ACK；量化恢复与辅助操作的忙碌请求分别保留。最终 ACK 后的状态查询失败不撤销输入完成，后续查询可恢复显示。

使用方式见 [操作说明](../../trial-materials-live-excel.md)。

## 实时输出性能

脚本 `scripts/validation/benchmark_trial_excel_events.py` 使用真实 `QApplication.exec()` 和生产 STA 通信，不靠 `QTest.qWait` 或同步 `flush` 推进。每种试验三轮，每轮 100 条暖态记录，合计 **600 条全部完成**。含量使用用户提供的 `sheet11.xlt`，直径使用原直径模板。

计时从 FDM 记录入账开始，包含合并等待、投影准备、IPC、COM 写入、状态读取和最终回执回到 Qt。采用最终回复，未用提前输入 ACK 缩短结果。屏幕刷新未关闭，但本测试不测显示器像素呈现时间；原始数值的正确性另由原生读回检查证明。

| 试验 | 第 1 轮 P95 | 第 2 轮 P95 | 第 3 轮 P95 | 全部 300 条 P50 / P95 |
| --- | ---: | ---: | ---: | ---: |
| 含量 | 116.47 ms | 110.34 ms | 118.54 ms | 90.84 / 115.97 ms |
| 直径 | 119.70 ms | 119.17 ms | 108.31 ms | 90.56 / 118.34 ms |

以上软件确认延迟低于 500 ms 目标；最长样本为含量 171.83 ms、直径 236.90 ms。首次创建工作簿分别约 8.02 s、1.01 s，单列，不混入暖态样本。

同一 Windows／Excel 环境、同一脚本及模板，以本轮起始提交 `ec26b6819de0e689017c0f078783cb82906bb56a` 的源码副本重跑 600 条（各三轮 100 条），完整对照如下：

| 试验 | 旧版 P50 / P95 | 新版 P50 / P95 | P95 降幅 |
| --- | ---: | ---: | ---: |
| 含量 | 446.63 / 557.08 ms | 90.84 / 115.97 ms | 79.2% |
| 直径 | 309.13 / 378.05 ms | 90.56 / 118.34 ms | 68.7% |

旧版首次运行在第 185 条后发生工作进程超时，失败结果完整保留，没有计入成功 600 条对照，也没有据一次故障推断其发生率。复跑时采用独立目录和新 Excel 实例，全部完成。旧／新版各轮连续执行、无其他 UI 矩阵并行；虚拟机顺序测试仍可能受调度和缓存影响，以上不是多台设备的统计结论。

该两份工作簿测试中，独立 Excel 进程的峰值工作集为旧版 864,997,376 字节、新版 698,249,216 字节；这是 Excel 进程指标，不是 FDM、Python 与整个虚拟机的总峰值。

| --- | ---: | ---: |
| COM 量化写入 | 18.94 / 23.58 ms | 26.22 / 31.74 ms |
| 元数据与计算状态读取 | 8.70 / 18.45 ms | 7.84 / 15.98 ms |
| 报表信息／标准／组距更新 | 0 / 0 ms | 0 / 0 ms |
| 分组宏 | 0 / 0 ms | 0 / 0 ms |

入账至请求开始的 P95 为含量 74.09 ms、直径 72.07 ms，包括 100 ms 合并定时器的实际等待、投影构建和调度。自动计算可能在 `Value2` 调用内部执行，因此“量化写入”包含该部分公式成本，不能声称已独立测得纯公式时间。没有逐批 `Application.Calculate` 或重建分组，正是本轮降低等待的主要改变。

最小入账调用的 P95：含量开／关同步 0.216 / 0.189 ms，直径 0.205 / 0.187 ms。含量这一微小调用的相对增幅超过 10%，不能据此宣称完整测量交互已达到 10% 目标，也不能用人为等待稀释比值。

另用 `benchmark_trial_excel_ui.py` 检查完整主窗口、试验控制器、统计与记录表：模拟相机以 33 ms 提交帧，真正的 Excel 开／关两条路径交替执行相同记录数的测量。每种试验各 100 组配对，加各 5 组预热，共 **420 条完成**；DPR=1，两个窗口实际为 1600×900。未在计时区主动 sleep、flush、processEvents 或强制 repaint。统计刷新保留产品原有 80 ms 调度；回调执行时间单列，避免靠调度等待掩盖开销。

| 完整 UI P95 | 含量关闭 → 开启同步 | 直径关闭 → 开启同步 |
| --- | ---: | ---: |
| 控制器入账处理 | 1.300 → 1.259 ms（−3.2%） | 1.185 → 1.263 ms（+6.6%） |
| 入账、记录通知、统计回调合计 | 2.377 → 2.557 ms（+7.6%） | 2.117 → 2.343 ms（+10.7%） |
| 第二点提交至本次统计／记录／画布实际 Qt 绘制完成 | 110.09 → 109.25 ms（−0.8%） | 93.17 → 112.56 ms（+20.8%） |

**完整界面性能目标尚未全部达到。** 含量的上述指标在 10% 以内；直径入账处理通过，但统计回调合计和最终绘制未通过。直径采样中，入账后的统计调度等待 P95 为 78.78 → 83.63 ms，统计后绘制等待为 26.93 → 31.34 ms，各阶段分位数不可直接相加。这些结果提示剩余开销涉及 Qt 调度和绘制，而不只在 COM 写入；尚未把来源精确归因到单个回调，不据此扩大修改无关画布代码。

该 UI 探针首次正式尝试因窗口裁小、统计标签处于滚动裁切区而无法取得所要求的 paint，0 条样本后超时，证据保留。之后使用进程级 100% 缩放重跑，系统 DPI 未变，未放宽实际绘制判断。5 组小样本仅作工具冒烟，不混入 100 组结果。真实相机／鼠标到显示器的完整响应仍须现场验证。

性能快照保留文件哈希。其后只增加两项错误状态恢复修复，不改变正常写入路径；最终源码通过专项回归，并完成含量／直径各 5 条原生冒烟（共 10 条，全部通过）。
