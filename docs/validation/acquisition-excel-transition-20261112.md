# 采集工作区加载过渡与 Excel 操作验证

日期：2026-11-12。版本：0.4.14。实现验证阶段仅修改源码与文字说明；之后按用户要求整理本地提交，不推送、不构建安装包。既有模板重做及 DSX 工作保留。

## 实现范围

- 采集工作区先显示框架；试验页按模型、控件、显示、报告与连接阶段准备，Qt 控件仍在主线程创建。150 ms 后才显示不定进度动画，缓存页直接复用。
- OpenCV 设备枚举、打开、首帧等待与释放使用串行后台任务；Microview 的阻塞式辅助进程枚举离开界面线程，Qt 相机和原生窗口绑定保持原线程。正常重入优先使用已有设备清单，连接失败才刷新。
- 页面、项目与设备请求有取消代次。取消运行中的驱动操作只撤销使用意图，保留设备租约直到释放；迟到图像或旧页面不能重新进入当前会话。无设备完成后不再永久显示“查找中”，释放失败提供“重试停止”。
- Excel 主按钮采用表格图标、主题主色和固定宽度。现有工作簿直接显示；已关闭的工作簿单次点击重建并补齐数据；连续点击合并。显式重新输出完成后显示一次，后台测量更新不反复抢焦点。
- 显示意图按试验、代次和用户请求跟踪。切页、停止和失败会撤销待显示请求。最小化恢复及任务栏提示核对 HWND、PID 和进程创建时间；Excel 忙碌时先展示窗口，之后再激活工作簿。
- 错误与警告前置并使用红／黄色，正常状态保持普通文字色；修复试验页 `trialHint` 选择器覆盖状态色的问题。模板配置错误可以直接查看异常并进入模板设置。

操作说明见 [采集页面加载与 Excel 操作](../acquisition-loading-and-excel-controls.md)。

## Windows 桌面 Excel

使用现有 Windows 11 虚拟机、现有 Python 环境和桌面 Excel 16.0，以独立配置、模板副本和新建 Excel 实例运行源码。未重新安装开发环境，未构建测试包。

原生集成验证 `native-v3` **30 项检查通过**：

- 含量、直径工作簿最小化后恢复；查看不触发量化输入重写。
- 未经轮询发现关闭的工作簿，第一次点击即可重建；连续点击仅创建一份替代工作簿。
- 实际 Excel 模态窗口中展示已核验窗口，结束人工操作后补写新测量。
- 手工报表单元格和工作簿备注在显示、重新输出及另存后保留。
- 多试验切换显示原关联工作簿；明确结束测试 Excel 进程后再点击能够重建。
- 主动停止同步后由明确点击恢复；源模板文件哈希不变；测试实例完成清理。

含量采用用户模板副本，SHA-256：`56f6f1510932d1d1a33b34b6831671b17f5ab4366d26dea320a371f705d90417`。保留全部工作表及新增报告页，查看前后页面、可见性和采样样式相同。直径使用现有 `sheet_dia.xlt` 副本。

最初两次预跑暴露的是验证脚本问题：另存 XLS 需要确认兼容格式；主动停止应等待 `detached`，且记录请求的 transport 子类要兼容无参数 shutdown。修正后以第三轮完整结果为准，预跑日志仍在本地保留，没有将失败记录删除。

Windows 首轮核心测试中，虚拟机默认 200% 缩放使两个按 100% 编写的既有测试超出物理屏幕或使用错误的像素预期；另一处断言早于异步启动意图。核心测试改用明确的有效 DPR 1，交互断言等待真实状态，另用独立窗口矩阵检查 100%～200%，不以取消高 DPI 检查规避问题。

## 证据和边界

本地证据根目录：`build/acquisition-excel-transition-20261112/`。包含源文件 SHA-256、原有未提交差异核对、Qt／PowerShell 测试日志、Windows 原生 Excel 请求与回复、主题截图和性能 JSON。所有图片与运行生成物都位于 Git 忽略目录。

设备性能来自受控慢设备模拟，未连接用户的真实相机，不能据此宣称驱动启动速度提高。Windows 测试为源码运行，未验证新安装包。系统拒绝前置的分支由 PowerShell 模拟契约验证；真实桌面测试验证了正常恢复与忙碌窗口流程。

当前运行中的、无法中断的驱动调用仍需要自行返回才能释放设备；GUI 不等待这个调用。已在采集中的设备尚未释放时，关闭／切换项目沿用现有停止后重试机制，并给出明确状态，不把未释放当作停止成功。
