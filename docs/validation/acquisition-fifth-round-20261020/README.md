# 第五轮：候选呈现、混合手势与证据相册

版本保持 **0.4.10**。本轮在第四轮未提交变更之上实施；最终安装包以构建 ID、源码清单及 SHA-256 区分。真实 Microview 不在本次可连接设备范围内。

## 实现

- 已核验图像与候选一起呈现。超预算后实时预览继续、候选统一暂停；连续 300 ms 且至少八次及时有效核验后恢复。有效但稍晚的结果保留批次，真实不一致立即失效。原对齐阈值和入账核验保留。
- 默认混合输入：候选短点击在释放时按当前类别提交；空白支持两点和拖线，候选上起拖同样手工；已有第一点与 Shift 强制手工优先。按下帧以受预算约束的令牌保留，刷新、来源或页面变化取消手势。仅手工保留原手势配置。
- 空全图结果使用固定状态栏，不覆盖画布、不更改上一条测值与已计入状态、不触发反复分析。
- 高级选项直接显示不保存、局部 JPEG、完整无损 PNG，与证据菜单即时同步并支持撤销重做，只改变之后接受的测量。
- 原证据分裂按钮主入口改为当前试验的独立相册。默认全部操作者与方向、最新在前，提供筛选、缩略图大小、测量标注和双击历史复核；不新增侧栏高度。切页临时隐藏，切试验重绑并清筛选。
- 相册以实测记录和证据 ID 为依据，不扫描目录。单后台解码、最多 128 项待请求、64 MiB 图片预算（含临时解码预留），超预算大图保留单图复核入口。同时间戳使用账本持久插入次序，避免 Windows 时钟粒度使“最新”顺序随机。
- 旧应用交互偏好转为混合并保留手工算法；用户之后显式选择仅手工／仅候选会持久记忆。旧项目存档策略、坐标、标定和统计格式不迁移。

## 证据入口

- [候选呈现与过载压力](candidate-presentation/README.md)：30 Hz 连续采集与每 150 ms 接受、JPEG 写入；0/40/80/200 ms 注入，帧率、帧龄、显隐转换、恢复和预算均记录。
- [相册验证](gallery/README.md)：三操作者、双方向、同图多记录、保存重开、历史滚动、读取异常、一万条懒加载、四主题截图。
- `before/`：修复前只读复现的原始显隐轨迹，不作为修复后验收。
- `macos/`、`windows/`：各平台原始回归日志与候选包验证。失败和复测分开保存，不以末次成功覆盖原始失败。
- `visual/`：工作台真实导航、候选点选、相册及高级选项截图与过程录像。Qt 控件抓取录像不等同于完整系统桌面录像。

## 复现入口

```sh
QT_QPA_PLATFORM=offscreen .venv/bin/python scripts/validation/validate_acquisition_fifth_round.py \
  --cycles 200 --menu-cycles 100 --motion-cycles 100 --video --output /tmp/fdm-round5-ui

QT_QPA_PLATFORM=offscreen .venv/bin/python scripts/validation/validate_acquisition_fifth_round.py \
  --matrix --workers 2 --cycles 6 --output /tmp/fdm-round5-matrix
```

Windows 使用 `--platform windows`。若显示器原生 DPR 为 2，传 `--base-device-scale 2`；脚本会核对最终客户区物理像素，不能将 3200×1800 截图标成 1600×900。

安装包验证继续使用内部 `--exclude-area-models` 配置，保留模板及 Microview 组件。最终结果、构建身份、离线交付和未验收边界汇总于 `DELIVERY.md`。
