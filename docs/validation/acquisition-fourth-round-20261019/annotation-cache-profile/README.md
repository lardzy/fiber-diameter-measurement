# 标注几何缓存的局部性能对照

2026-10-19，macOS、Qt offscreen，768×576 固定图像。每组预热 10 次、测量 100 次，候选位置固定，已接受记录使用持续采集基准中的同一网格位置。对照仅改变画布标注缓存，不修改对齐条件或可点击条件。

单条缓存遇到候选显隐交替时反复重新计算所有编号的位置；使用最多四条的几何缓存后，显隐各有可复用布局。缓存不包含图像、帧或像素引用，隐藏时仍不能命中候选。另有自动回归确认交替 20 次只创建两种布局、缓存上限和换场清理。

| 已接受记录 | 显隐交替：原绘制 P95 | 四条缓存：绘制 P95 | 原布局 P95 | 四条缓存：布局 P95 |
|---|---:|---:|---:|---:|
| 20 | 1.158 ms | 0.404 ms | 0.848 ms | 0.048 ms |
| 50 | 4.293 ms | 0.957 ms | 3.511 ms | 0.115 ms |
| 100 | 11.463 ms | 1.655 ms | 9.990 ms | 0.228 ms |

原始结果分别见 [单条缓存](single-entry.json)、[四条缓存](four-entry-lru.json)。`LruPrototype` 条目是同一几何布局的实验原型；上表仅取实际 `LiveMeasurementCanvas` 前后对照。所有数据是独立画布微基准，不含采集、对齐线程、完整主窗口或 JPEG 写入，**不能据此判定持续采集性能通过**。

此优化只避免相同布局反复计算。每次新增记录、变更缩放或改变视口仍会产生新布局；后续 30 秒 Windows 压力测试在近 200 条记录时发现新增布局耗时，需以相应连续采集结果另行判断。

## 逐条添加记录的增量布局复测

进一步使用已验证的旧位置作为布局起点。旧标签仍重新检查全部当前线段、端点保护区、草稿和已放置的高优先标签；受新增几何影响的原可见标签重新安置，原先已隐藏的普通标签不重复搜索 42 个位置。悬停提升优先级，删除、撤销、几何或视口变化后可重新寻找空间。

实际逐条添加 200 条记录，每条依次绘制候选可见、隐藏、再次可见、再次隐藏。对照为相同四条缓存但每次新增全量布局的 `FullReflowLRU`。结果见 [增量布局数据](incremental-layout.json)。

| 添加记录区间 | 全量重排冷绘制 P95 | 增量冷绘制 P95 | 全量重排温绘制 P95 | 增量温绘制 P95 |
|---|---:|---:|---:|---:|
| 1–50 | 4.069 ms | 1.550 ms | 0.916 ms | 0.873 ms |
| 51–100 | 11.831 ms | 3.353 ms | 1.742 ms | 1.530 ms |
| 101–200 | 32.514 ms | 3.467 ms | 2.388 ms | 2.169 ms |

表格取候选可见帧；隐藏帧有相近结果。9、20、50 条记录都能显示全部编号；200 条密集记录的可见编号由全量重排的 92 个变为 83 个，全部测量线仍保留，悬停可重新请求编号。测试包含 143 项安全布局、点击及既有确认交互回归。

复现（仅源代码开发环境）：

```sh
.venv/bin/python scripts/validation/benchmark_annotation_layout.py --output /tmp/fdm-annotation-layout.json
```

这仍是独立 Qt 画布微基准。Windows 连续采集、JPEG 并发和长时帧龄验收应使用完整持续采集基准，不能用本表替代。
