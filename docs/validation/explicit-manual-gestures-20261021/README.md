## 操作变化

在原右侧测量方式的位置，将原有 140 逻辑像素区域分成“贴边／自由”算法选择和“两点／拖线”手势菜单。不增加操作行，不减少类别区域高度；算法完整名称保留在提示及无障碍说明中。

| 选择 | 确定行为 |
|---|---|
| 两点 | 每次按下左键只放置一个端点。首点后的移动、持键移动和松开均不提交；第二次按下完成测量。 |
| 拖线 | 按住左键且移动超过 Qt 系统拖动阈值后开始；松开完成。短点击、仅释放坐标变化不建立隐藏起点。 |
| 混合交互中的候选 | 两种手势均支持短点击候选入账。两点手势不会因移动转为拖线；拖线手势可从候选上起拖。 |

已有手工第一点优先于候选命中。Shift 临时绕过候选，仍遵循所选手势。切换手势取消旧草稿；重复同点不会提交零长度任务。“仅候选”禁用手工手势入口。沿用既有手势配置及保存、撤销语义，不迁移项目数据。

混合与仅手工通过相同的显式手势接口处理，鼠标处理函数不再发出旧的 `pointPressed/pointReleased` 测量信号，避免两条输入路径产生不同提交时机。

## 同时修补的异步边界

- 保留上一轮实际已绘制帧的输入令牌修复：新预览帧尚未重绘时，不静默吞掉正常同源落点；来源、尺寸或显示修订变化仍拒绝过期输入。
- 第二点因帧预算、画布范围、来源上下文或业务条件被拒绝时取消旧起点，避免下一次意图作为首点的点击实际接上遗留起点。
- 成功建立新草稿时清理上一条失败卡；上一条异步失败不能覆盖新草稿。拖线按下至首次持键移动之间到达的旧失败，也会在真正开始新草稿时清除。
- 输入诊断继续记录鼠标事件、持续按键、手势、交互身份、提交原因以及已绘制／待绘制帧身份。

此前修复解决了一个可复现的帧间隙丢点路径，但未覆盖用户现场所有同表象问题。本次是明确的交互契约调整，不能将模拟测试通过表述为已经验证实体设备上的全部异常来源。

## 实机短测步骤

1. 安装本轮同版本包，核对构建 ID。保留上一轮安装包以便回退。
2. 混合交互、贴边算法、**两点**手势，关闭自动分析。每条首点后移动及松开鼠标，应只显示草稿；第二次按下才提交，连续测量至少 30 条。
3. 打开自动分析，交替短点击候选与两点手工测量。候选点选不应遗留手工起点，其他候选继续保留。
4. 切换为 **拖线**：空白位置短点多次不应留起点；按住拖过纤维再松开，应只提交一条。候选短点仍入账，从候选上起拖则按手工测量处理。
5. 建立首点后切换手势，原草稿应取消。模拟第二点落到图外后，下一次有效点击应重新建立首点。
6. 若再次出现异常，导出输入／性能诊断并保留构建 ID、手势选择和失败文案；用 `manual_finish`、`task_submitted` 的交互身份及提交原因区分实际第二点、拖线和旧任务反馈。

Windows 虚拟机、安装版和实际 Microview 相机结果分别记录。实体相机、物理鼠标和现场负载当前仍待用户实测。
