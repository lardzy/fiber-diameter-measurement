# 试验高级设置、画布标记与临时图片回收验证

日期：2026-11-11。软件版本：0.4.14。验证对象为提交前的源码工作区；验证时未构建安装包、提交或推送。报告随本轮修改本地提交，其他未提交的 DSX 工作保留。

## 实现范围

- 主设置新增稳定标识 `trial` 的“采集与试验”页，统一显示、交互、图片存档及全图分析偏好。试验高级入口跳转同一页面；快捷控件和隐藏试验同步更新。设置不写试验数据，不生成试验撤销记录。
- 两侧日常稳定状态默认隐藏，控制器继续核验视场。使用独立 `routineStatusChanged` 信号区分状态消息，异常和操作反馈继续显示。
- 含量试验已入账标签默认显示类别全称，直径试验显示值和单位。默认无白底、跟随类别／线条颜色、应用字体 12 pt；候选及待确认仍有独立身份。预览与画布复用文字布局和绘制函数。
- 图片存档默认关闭，显式开启跨重启保留。图片策略在测量开始时固定；后续更改不会改写在途任务。
- 专用临时资源管理器记录实例锁、目录身份与逐文件身份；后台分批回收。保存发布、撤销历史、正在写入、读图与保存快照均参与引用管理；已发布路径同步回图片去重缓存。
- 成功保存／确认放弃项目／成功结束换样后回收无引用临时图片。取消、失败、切页和仍保留的试验不释放图片。退出停止维护扫描但保留实例锁至进程终结；下次启动处理归属明确的退出实例。

操作说明见[采集与试验设置及测量图片存档](../../trial-settings-and-image-storage.md)。

## 回归方法

本地联合回归使用真实 Qt 控件、控制器和项目保存流程，覆盖主设置入口、取消／应用／恢复默认、偏好重启、隐藏页面同步、标记内容及字体、改类／换场、原图与测量数据不变、在途策略、算法预览失效、资源归属和图片生命周期。

资源测试包含：默认关闭不建目录、不编码；取消退出与保存失败保留；保存成功发布并回收临时副本；保存后相同位置去重可读；撤销唯一引用、在途保存和异步读图保护；另一实例锁、崩溃残留、未知文件、身份不符、链接及权限失败；清理暂缓续跑、退出停止和最终汇总反馈。

Windows 使用已有 Python 3.12.13 / PySide6 6.10.2，在独立目录运行本轮源码差异和相关测试。没有安装新的环境、启动物理相机或使用用户样品。测试隔离应用配置并禁止连接桌面 Excel。

最终本地联合回归：**1453 passed，1 skipped，4 subtests passed，127.84 秒**。唯一跳过为 Windows 专用目录联接用例；macOS 上实际执行了符号链接拒绝用例。覆盖 `test_live_experiment_*`、`test_trial_*`、`test_measurement_evidence_*`、设置、项目保存／导出、采集流程及 `test_optical*`。

之后对最终节流调整和跨平台鼠标事件用例补跑资源／UI生命周期／标记／主设置入口：**42 passed，1 skipped，9.25 秒**，跳过原因同上。

最终 Windows 功能回归：**169 passed，1 skipped，52.83 秒**。普通用户无法创建文件符号链接（WinError 1314），该项按明确原因跳过，未提升账户权限或改变系统设置；实际的目录联接拒绝测试通过。前期验证副本缺失测试夹具和配置隔离文件的问题已补齐，最终测试使用当前 `conftest.py` 与显式源码路径。

最后复核额外补齐了四个边界：首次升级只打开／切页也保留旧算法偏好；光照诊断采集成功自动发布全局参考；主设置已有未应用草稿时只合并晚到的参考资源；延期清理追踪后续任务并累计最终数量。恢复稳定提示只使用当前已核验且同来源／同视场的信息，不覆盖较新的操作或异常。

使用原生 `windows` Qt 平台。采集器先测原生 DPR（本机为 2），再通过本进程倍率补偿取得目标 DPR；没有修改 Windows 系统缩放。分别核对 QWindow、截图 DPR 和物理尺寸，不能仅凭环境变量声称完成了 DPI 测试。

| 浅色 | 1.25 | 1.25 | 同上 |

设置窗口为 900×640 逻辑像素，长内容通过页内滚动访问；清理按钮、实时预览和应用／确定／取消可达。截图为实际 QWidget 客户区抓取，不是物理显示器录像。首次采集器错误地叠加原生倍率，得到 2～4 DPR；已修正并重新验证，首次结果未作为 100%～200% 验收。

四组设置均补测原生窗口悬停：先核对 Qt 活跃窗口及 Windows 前台 HWND，再通过 `QTest.mouseMove` 投递并等待真实事件，核对标签命中的记录 ID 和提示中的 `#` 编号，含量与直径两页均通过。单位测试使用同步事件投递隔离命中逻辑，桌面采集器不直接调用事件处理函数，避免以修改内部状态代替鼠标验证。

## 性能方法与边界

`scripts/validation/benchmark_trial_cleanup.py` 使用真实 Qt 事件循环、试验控制器和画布，30 Hz 定时器模拟相机送帧，异步自由线段测量、视场核验、入账和绘制均走实际路径。每轮关闭／开启清理各 300 条，正式对照三轮；由独立子进程创建带真实归属清单的临时图，退出后由生产回收器处理。历史调优每轮 8192 份，最终 Windows 对照每轮 4096 份，两者均覆盖完整连续测量窗口。测量开始前生成数据，不把夹具创建计入响应时间。

交替运行开关顺序，记录每条原始时序、绘制、回调、帧交付、清理任务及实际删除重叠数量。性能段不使用 `sleep` 或 `processEvents` 推进测试；后台回收自身按生产实现分批让出。记录的是软件送帧和绘制完成，不等于传感器采集或显示器扫描输出。

首次压力运行曾出现超过 10% 的响应回退。先将维护任务缩小到每 8 项让出 10 ms，并在测量／编码／保存活动期间暂停；暂停后从清单偏移续跑，避免反复扫描整个增长清单。Windows 原生绘制实测仍超限，最终再缩小到**每 2 项清单操作让出 20 ms**；每个文件有临时名及完成名两条归属记录。取舍是后台回收总耗时增加，而单次文件操作竞争下降。

Mac 三轮优化后合计 900 条关闭和 900 条开启，入账 P95 5.664→5.737 ms（+1.28%），可见结果 10.840→11.357 ms（+4.77%），绘制 5.430→5.562 ms（+2.43%）。三轮各回收 8192 份文件，数据正确。**第二轮可见结果 P95 单轮仍为 +10.32%**，保留此超限记录；不能把合计达标解释为所有单轮均达标。退出停止修正后的单轮补测 300+300 条、1024 个文件，六项 P95 回退均在 10% 内。

上述 Mac 结果为 8 项／10 ms 阶段记录。Windows 同调度三轮入账 P95 22.011→25.290 ms（+14.90%），可见结果 43.865→50.466 ms（+15.05%），绘制 20.825→24.142 ms（+15.93%），未达目标。提交和入账回调基本稳定，回退主要出现在绘制；每轮测量期间确实删除 723～754 个文件。

4 项／20 ms 的单轮短测将可见结果回退降至 7.64%，但入账和绘制仍分别为 11.24%／11.64%，没有作为达标结果。2 项／20 ms 的单轮 300+300 条短测，入账／可见／绘制分别回退 1.58%／2.92%／1.82%，测量期实际删除 174 个文件，258 条测量区间与实际删除重叠；回收 1024 份文件耗时 25.75 秒。

最终 Windows 三轮使用 2 项／20 ms，合计关闭／开启各 900 条，结果如下：

| 指标 | 关闭清理 P95 | 开启清理 P95 | 变化 |
|---|---:|---:|---:|
| 测量提交到入账 | 21.444 ms | 22.390 ms | +4.41% |
| 测量提交到结果绘制 | 42.013 ms | 44.369 ms | +5.61% |
| 模拟帧交付间隔 | 43.173 ms | 44.085 ms | +2.11% |
| 界面回调 | 18.468 ms | 19.283 ms | +4.42% |
| 单次帧交付回调 | 1.096 ms | 1.142 ms | +4.18% |
| 画布绘制 | 20.261 ms | 21.526 ms | +6.24% |

合计六项 P95 回退均在 10% 内。三轮分别统计的入账／结果绘制／帧间隔／回调也均在 10% 内；入账回退依次为 7.35%、3.30%、2.77%。每轮全部回收 4096 份文件、无跳过或删除错误，维护总耗时 100.56／101.25／101.92 秒。测量期间分别实际删除 178／177／181 份，262／263／270 条测量与实际删除区间重叠，并非只开启线程却不执行删除。

**保留尾部延迟记录：**开启清理时最大可见结果延迟为 155.48 ms（关闭时 52.11 ms），最大绘制 123.49 ms。此次数据不能单独确定峰值来自清理还是虚拟机调度，不将 P95 达标扩大为每一帧均无迟滞。

回收夹具是 68 字节的有效 PNG，重点施压目录／归属清单／文件元数据操作；输入帧为 1024×768。基准未加载 Excel、完整侧栏、持续大图编码或真实相机，也不代表机械盘删除大文件的延迟，因此真实设备连续工作仍需现场观察。不能从合成帧结果推导设备吞吐量或计量精度。
