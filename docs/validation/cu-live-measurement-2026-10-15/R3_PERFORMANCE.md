本报告只读取已经到达且符合本页版本命名的 JSON。缺失项明确列为待验收；不使用早期 `performance-*.json`，也不把早期无真实画布的一小时控制器测试算作最终 UI 联合验收。

**源码身份：**本页独立读取 `final-r3-{macos,windows}-*.json` 的每平台六组新版短程结果及 `cu-live-workspace-hour-windows-final-r3.json`。首轮 [PERFORMANCE.md](PERFORMANCE.md)、[R2_PERFORMANCE.md](R2_PERFORMANCE.md) 与原 JSON 保留；新版结果不覆盖旧失败。R2 尚无正式采样时保持待验收，不从 R1 或 R3 借用数据填充。三个尺寸的独立全图算法未改，单列引用 R1 的六份报告，明确是原构建证据，不伪称重新跑过 R3 全图。配置修正见 [overlay](configuration-rebuild-overlay.json)，各运行的实际源码／原生摘要以原始 JSON 为准。

**当前已出现未达标条件，不能宣称整体性能通过。** 逐项成功、失败与未完成以以下表格为准；脚本退出 0、快速原生内核或静止画面通过，均不能替代动态画面和联合负载验收。

## 固定口径与覆盖

硬门槛以 [采样前固定规则](performance-acceptance-rules.md) 为准。每个短程条件预热 5 次、正式尝试 30 次；不补测凑满成功数。成功延迟只以实际成功且绘制的样本计算，失败分母始终保留 30 次。预热拒收单列。`—` 表示没有有效样本或未测，不是零耗时。

短程 UI 的 `interval_ms=100` 是每次结果成功／失败后再等待 100 ms，属于串行连续测量，**不是固定每秒 10 条**。输入请求 30 Hz；不同帧绘制 FPS 与重复重绘次数分开。结束区间边界计数可能使短窗口 FPS 略高于 30，不代表请求速率提高。

表内延迟单位均为 ms，四元组依次为 **P50 / P95 / P99 / 最大值**。30 次中的 P99 仅为本批估计；失败越多，可用分位样本越少，不能解释为长期尾延迟保证。

GUI 发布计时覆盖 `_accept` 和同步 UI 信号，每次最大值须 ≤ 4 ms；不能用接受后重绘时间替代。端到端结果可见由实际 QTest 第二击计到包含该记录的 `paintEvent` 完成。

UI／运动的默认 OpenCV 配置是这两类场景的主验收：`requested=null` 表示未主动调用线程限制，不能解释为1。手工／统计及独立全图使用另一采样脚本，其入口显式请求 `cv2.setNumThreads(1)`；旧JSON未单列请求字段，上表已区分代码依据与实际报告值。该脚本 SHA256 `ee3f3f8837b82ff2ac1712361c35cb1a83d46c7f16181c0f7703f7e44cbfa3fb` 与首轮905文件清单一致；新报告若改变脚本，应另核对该设置。

不能将某一行请求或报告值扩展到全场：首轮 Windows 手工／统计报告1，运动与四种UI报告默认4／Concurrency；首轮 macOS UI／运动为默认18／GCD，手工脚本即使请求1也报告18。报告线程数不等于实际同时运行的线程数；主进程环境记录也不能证明全图子进程采用同一个线程数。OMP／BLAS 等环境变量另列，不把其值1等同于OpenCV单线程。未到达的新版条件不沿用其他版本配置猜测。源码摘要、输入摘要、原生编译器／ABI 位于原始 JSON，不能只凭 Git HEAD 判断未提交工作树一致。

R3 的 512 MiB 逻辑预算包含去重后的保留帧、来源声明的 CPU／GPU 采集预留，以及 PNG 编码工作区。生产 `png_workspace_bytes(width, channels)` 为 2 MiB 编码 allowance＋两行缓冲，即 `2*width*channels+1` 字节；原帧租约与编码预留原子准入，同一串行 writer 组取尚存任务预留的最大值，不同组相加。生产逐行 SUB／Z_RLE 编码不建立完整 RGB 图像或完整压缩 PNG 数组；原帧在编码结束后释放该 writer 的租约，其他消费者仍持有的像素继续计费。该 allowance 是逻辑工作区预留，**不是进程 RSS 或驱动内存的硬上限**；不能因账本低于512 MiB就称全部内存已达标。R1 的完整 `cv2.imencode` 输出未纳入账本的历史缺口不应被改写为R3仍使用同一路径。RSS 另含 Python、Qt、算法、SDK、PNG 与子进程工作区；GPU 驱动不透明开销也不能由 RSS 完整覆盖。资源表按每个条件约100 ms采样的父／子／合计峰值列出，短于采样间隔的峰值可能遗漏；三者各自取峰，不要求父峰＋子峰等于同时观测到的合计峰。

## 独立全图服务

所有行分别预热5次、正式30次；返回状态 `ok` 和 `empty` 都表示算法正常结束，空结果是按恢复规则未保留候选，不能当作运行错误。错误、超时、内存拒绝另列。worker 往返包含传递与等待，worker 内服务是诊断分段；相减不同分位数不能作为精确复制成本。30秒硬超时、2 GiB算法预算是资源保护，不是交互延迟验收目标。

**本节全部为 R1 原构建证据。** 全图算法代码未改，因此保留三个尺寸的原独立采样，不将其源码／原生摘要替换成 R3。新版端到端联合 UI 的全图负载另见本页 R3 条件；这两类证据不互相冒充。
