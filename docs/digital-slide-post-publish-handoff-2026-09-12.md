# 局域网采集完成后停留在“准备本机读取副本”的修复

日期：2026-09-12。基线：0.4.5 / `a58931d`。本次保持版本号不变。

## 发现

采集已经先写入本机暂存文件，再完整复制、刷盘并原子发布到局域网。发布成功后，`_finish_digital_slide_acquisition()` 将这个本机文件作为 `interaction_path_override` 传给文档打开流程，因此这一步不需要从网络复制回来。

但是 `_prepare_digital_slide_source()` 仍先对网络路径执行 `resolve()`，随后读取网络文件的 `stat()`。原来的异常回退只有在 `stat()` 返回错误后才读取本机状态，无法处理网络调用持续不返回；路径解析本身也在回退保护范围外。后台线程使界面能够刷新，但调用方仍须等待该线程结束，所以完成流程会停在进度窗口。

这个窗口在“复制网络文件”和“挂载已完成的本机文件”两条路径中使用同一段文字，容易让用户误认为还在重复复制。

此外，完成窗口的“查看切片”也会在主线程解析原网络路径及各文档路径，有相同的不必要网络依赖。

Python 官方文档区分了 `absolute()` 的绝对路径构造和 `resolve()` 的文件系统解析，并说明 `stat()` 每次重新查询文件信息。本次使用前者保留已选输出路径，不通过符号链接解析重新访问网络。[路径操作说明](https://docs.python.org/3/library/pathlib.html#pathlib.Path.absolute)、[文件状态查询说明](https://docs.python.org/3/library/pathlib.html#pathlib.Path.stat)。

已确认上述代码路径和缺少超时回退的依赖关系；没有现场 Windows 线程栈，不能确认现场具体停在路径解析还是文件状态查询。

## 修改

- 已有本机采集副本时，只读取本机文件的路径、大小和修改时间；网络路径只用作项目文档的原始保存位置。缓存版本对应实际读取的本机字节。
- 完成后的查看操作直接匹配已登记的路径，不再解析或查询网络文件。路径比较使用 `Path` 的平台语义，保留 Windows 路径的大小写处理。
- 采集完成后的进度文字改为“正在加载已采集的数字化切片…”。真正从网络打开其他切片时仍创建本机读取副本，保留来源版本检查及取消操作。
- 未点击查看时继续延迟渲染器初始化；网络发布失败时仍保留本机恢复文件。

## 验证

新增回归在发布成功后禁止任何对目标目录和文件的 `resolve()`、`stat()`、`open()` 调用，并禁止调用复制服务，覆盖正常完成和中断后保留。验证完成通知、文档登记、原始保存路径、本机读取、控制状态释放以及随后切换到查看并读取正确图像。另有准备阶段测试核对使用本机文件版本。

修改前，新增准备阶段测试明确失败在网络路径的 `resolve()`；修改后通过。原有 Mac 测试曾断言源路径必须经符号链接解析，现在改为保留用户选择的绝对路径，实际读取文件仍使用本机规范路径。

采集、存储、配置和压缩专项：113 项通过。界面、发布和数字切片浏览回归：96 项通过。合计 209 项通过，`git diff --check` 通过；没有重复运行全部软件测试。

以上在 macOS Qt 离屏环境运行，发布目标为本机模拟目录，故障通过禁止网络调用注入。需要重新构建 Windows 安装包，在真实局域网复测完成后关闭、查看及连续采集；不把本机回归当作现场 SMB 验收。
