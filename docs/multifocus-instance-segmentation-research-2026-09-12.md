# 数字切片多焦层实例分割方案调研

调研日期：2026-09-12。项目：Fiber Diameter Measurement（FDM）。

已确认的需求是：**同一对象跨焦层统一 ID，输出可复核的二维轮廓；最低兼容 RTX 3070 8GB，利用本地 RTX 30／40 系显卡运行。**

本次完成网络资料核对和当前源码分析。没有进行模型安装、训练或 RTX 实机推理；下文的显存预算、分块参数和验证规模属于建议起点，不是已经测得的性能。样品具体类型尚未确定；仓库演示截图中有细长、交叉纤维，但不能把演示图视作实际待处理数据集。

## 1. 推荐决策

建议采用：**原始多焦层分块读取 → 各层二维实例候选 → 跨图块与跨焦层关联 → 每个对象生成一个二维代表掩膜 → 人工复核。**

这里将其称为“利用焦层信息的二维实例分割”。核心是利用多个焦层辨认同一对象、选择清晰边界，而非从焦点堆栈计算真实体积。

实施顺序建议如下：

1. **首轮验证 μSAM ViT-B、CellposeDINO-B，并保留现有 YOLACT 为基线。**三者先共享完全相同的输入、坐标、跨层关联和评价规则。
2. **μSAM 优先用于自动候选与交互修正相结合的工作流。**先比较 AIS、APG；光学纤维对细胞模型存在分布差异，也要保留原始 SAM ViT-B 的点／框提示对照。
3. **CellposeDINO-B 是自动分割的重要竞争方案。**它较新的模型结构值得验证；不能把旧 Cellpose 或 Cellpose-SAM 的论文结果直接作为 DINO 版本的准确率证明。
4. **有代表性标注后，再比较 RF-DETR-Seg Small 与 YOLO26n/s-seg 的纤维专用模型。**这条路线适合固定样品、长期批量运行；若现有 YOLACT 已能提供足够好的候选，应优先补全跨层处理，再决定是否替换模型。
5. **SAM 3／3.1 保留为实验候选，不作为 8GB 默认引擎。**这是基于集成成本、任务匹配和资源余量的排序，不等于判定它绝对无法在 8GB 上运行。

目前可以确定架构与比较顺序，尚不能确定本项目的模型冠军。

## 3. 模型选型及证据

### 3.1 μSAM：优先验证的交互与自动候选引擎

μSAM 提供针对显微图像的模型、自动分割和点／框提示修正能力。推荐从 `vit_b_lm` 起步；若细胞模型对纤维形态不适用，比较原始 `vit_b` 的提示分割。官方支持 AIS 和 APG：AIS 使用附加解码器生成实例，APG 从解码结果产生提示再预测掩膜。[官方功能与模型说明](https://computational-cell-analytics.github.io/micro-sam/micro_sam.html)

对 FDM 的优势是自动候选与人工修正可以共用模型体系，适合“分割后测量、发现错误再修”的操作方式。需要验证的问题包括：一根长纤维被切成多个对象、交叉处误合并、内部纹理被误认成对象、清晰外轮廓与内部孔洞的处理。

建议先比较 AIS 的速度和 APG 的召回／分离质量，再决定是否仅对困难区域启用 APG。原始 SAM 不具备 μSAM 专用实例解码器，不能把其 AIS／APG 能力默认视为存在。

2026 年的 *Revisiting foundation models for cell instance segmentation* 在所测显微数据上发现 μSAM APG 和 Cellpose-SAM 表现较强。但该研究由 μSAM 团队开展，主要评价二维细胞／细胞核，SAM3 主要使用文字提示，未评价视觉示例提示；结论不能直接推广为纤维、多焦层和 8GB 设备排名。[论文及方法限制](https://arxiv.org/html/2603.17845v1)

### 3.2 CellposeDINO-B／Cellpose-SAM：自动分割对照

截至调研日，官方模型包含 2026 年 6 月推出的 `cpdino`、`cpdino-vitb` 和更新的 `cpsam_v2`。`cpdino-vitb` 使用较小的 DINOv3 ViT-B；DINO 系列内部 tile 默认 384×384，可调整，SAM 系列内部 tile 为固定 256×256。[官方模型清单](https://cellpose.readthedocs.io/en/latest/models.html)

8GB 首先测试 `cpdino-vitb`，随后根据显存和效果比较 `cpsam_v2`。这两个尺寸是网络内部处理单元，不等于 FDM 外部数字切片分块尺寸，也不意味着原图只能输入这些大小。

Cellpose 有现成的逐 XY 层分割、按 IoU 跨层连接机制：`do_3D=False` 配合 `stitch_threshold>0`。它很适合做关联基线；仅靠相邻层 IoU 无法充分处理长纤维断裂、重叠和消失后再出现。[官方多层处理说明](https://cellpose.readthedocs.io/en/latest/do3d.html)

Cellpose 的普通输出是每像素一个实例 ID 的标签图。最终若要表达不同焦层对象的二维投影重叠，应在 FDM 汇总时为每个全局对象保留独立掩膜，不能简单压成一张互斥标签图。被遮挡且任何焦层都不可见的边界，仍需要标为不确定。

### 3.3 YOLACT、RF-DETR-Seg、YOLO：有标注后的批量运行路线

现有 YOLACT 的集成与业务类别映射已存在，因此应作为实际工程基线。是否继续使用，应由真实样本的漏检、误合并、边界误差和耗时决定，不能只按模型发布时间淘汰。

RF-DETR-Seg Small 和 YOLO26n/s-seg 均值得纳入专用训练对照：

| 方案 | 优先验证的原因 | 需要解决的问题 |
| --- | --- | --- |
| YOLACT 现有权重 | 已有业务模型与 worker；可以先看多焦层是否补足单层缺陷 | 检查训练分布、候选上限和原始 mask；改进现有最大外轮廓输出的损失 |
| RF-DETR-Seg Small | 对象级 mask 路线；可从 COCO 实例标注接入，适合比较复杂对象轮廓 | 用原生分辨率裁块保住窄纤维；核对所选版本的 RLE、重叠和孔洞加载行为 |
| YOLO26n/s-seg | 小模型适合 8GB 的批量运行目标，训练与导出工具成熟 | 本项目当前 YOLO 导出不能无损表达孔洞／多连通区域；不能让有损标签影响面积测量 |

RF-DETR 官方当前列出多个 Seg 尺寸；YOLO 官方已有 YOLO26 分割模型。其 COCO 成绩与 T4／TensorRT 延迟不能换算为 FDM 的纤维精度或 RTX 3070 整片耗时。[RF-DETR 官方模型表](https://github.com/roboflow/rf-detr)、[YOLO 分割官方文档](https://docs.ultralytics.com/tasks/segment)

两类通用 COCO 权重都不能被当作现成纺织纤维模型。必须用代表性数据微调，或者先作为候选／标注辅助验证。全局层间关联仍由 FDM 处理。

2026 年一项直接针对拼接显微图中残余纤维长度测量的研究比较了 U-Net、Mask R-CNN 和 YOLOv11，研究重点也包含重叠和图块边界的身份保留。这支持“按实例评价整个测量流程”的选择，但它并非 FDM 多焦层数据的结果，也没有证明 YOLO26 或 RF-DETR 在本项目更优。[论文作者提供的正文](https://krisvillez.gitlab.io/profile/pdf/KV_A067.pdf)

### 3.4 其它方案的定位

| 方案 | 在本项目的定位 |
| --- | --- |
| Omnipose | 如果主要是长条、弯曲、分叉形态，把它加入对照；其细菌模型不能直接保证适用于木浆、棉等纤维 |
| StarDist | 若样品主要是近似星凸的横截面，可加入轻量对照；弯曲长纤维、孔洞等形状与其表示方式不匹配 |
| SAM 2 | 可以试验沿焦层传播提示，需验证双向一致性与身份切换；视频时间连续性不能直接等同于离焦变化 |
| SAM 3／3.1 | 文字／示例找对象和交互分割的研究候选；当前不作为 8GB 的必需组件 |
| 普通 U-Net＋分水岭 | 对分散、边界清楚的横截面可作为低成本基线；单纯前景分割无法解决真实交叉纤维的身份 |
| 真三维 U-Net／体实例分割 | 当前目标用不到体积标签；增加数据和显存负担，也不能把普通明场焦点堆栈自动变成光学断层 |

Omnipose 对细长、分叉细菌形态有直接论文证据；StarDist 则明确采用星凸形状表示。这些是形态匹配的依据，不是纺织样品精度承诺。[Omnipose 论文](https://www.nature.com/articles/s41592-022-01639-4)、[StarDist 官方实现](https://github.com/stardist/stardist)

SAM3 官方当前要求 Python 3.12+、PyTorch 2.7+、CUDA 12.6+，并在仓库中发布了 SAM3.1 跟踪更新。它增加独立运行时和资源适配工作；3.1 的多对象视频跟踪改进，不代表已经解决本项目跨焦层识别。[SAM3 官方仓库](https://github.com/facebookresearch/sam3)

## 4. 多焦层处理应怎样设计

### 4.1 使用原始像素，冻结空间变换

每次任务固定来源切片、原始 tile 版本、空间布局版本、焦层集合和 ROI。同一 XY 区域的焦层先检查平移或小幅尺度漂移，保留变换与有效覆盖。

拼接边界可能产生混合像素。建议把采集 tile 的原始像素作为可追溯输入，将预测映射到冻结的全局布局；如使用重建视口，应固定插值、混合规则，单独评价拼接缝附近的误差。显示缩放、DPR、当前浏览缓冲不应成为模型输入坐标的依据。

切片布局或标定变化后，相关结果应按现有分析结果的过期机制处理。未采集区域属于未知覆盖，不能训练成普通背景。

### 4.2 先形成各层候选，再做两种不同的合并

首轮参考流程对 ROI 中全部有效焦层推理，便于建立多焦层召回基准。清晰度排序可决定处理顺序，但尚未验证前不只保留“最清晰的三层”，否则可能漏掉只在其它深度清楚的纤维。

同层相邻图块的重复预测，依据重叠区域的 mask、位置和方向合并。跨焦层候选则需要考虑：

- 掩膜的 IoU、重叠面积占较小对象面积的比例；
- 中心线和端点的距离、方向连续性；
- 宽度、纹理、类别信息的一致性；
- 局部清晰度随焦层的变化；
- 是否触碰图块边缘、是否只有部分对象清楚；
- 邻层是否存在两个独立对象的反证。

首版可用有几何门限的相邻层匹配，并允许经过有限缺层后重新关联；复杂的拆分／合并先标记复核。只凭重叠就对候选做传递合并，可能通过某一层的错误大 mask 把两根纤维串成一个对象，应增加冲突检查。

长纤维横跨多个图块时，中心线连续性有帮助，但“方向相近”本身不足以合并相邻平行纤维。跨图块去重和跨焦层去重需要独立记录证据。

已有明场 Z-stack 丝状结构研究采用逐层骨架、图匹配和局部清晰度来恢复结构关系。这为上述关联思路提供了更贴近成像方式的参考；其真菌与打印原型实验不能替代 FDM 测量验收。[原始研究](https://doi.org/10.1016/j.ecoinf.2025.103317)

### 4.3 每个对象生成一个代表掩膜

推荐先实现最容易验证的版本：对已经关联的对象，在边界完整且清晰的候选中选一个代表焦层。对象不同部位清晰于不同焦层时，再增加受对象身份约束的局部轮廓融合。

局部融合需要记录每段边界或区域来自哪个焦层，并限制只在同一对象的证据范围内选边。不要直接对所有焦层掩膜取并集：离焦膨胀会增大面积；也不要简单取交集：模糊或漏检会导致边界收缩。

景深合成图适合总览，也适合作为单独的实验输入，但应与“逐层候选后融合”对照。其视觉清晰度并不能证明交叉处的对象身份正确。

对于遮挡区域，输出可观测的轮廓及不确定部分。若后续业务需要补全不可见形状，应独立定义为推断轮廓，不能与实际测量边界混用。

### 4.4 全局对象应保存什么

建议每个全局对象至少保存：

- 稳定的 `global_instance_id`、类别及复核状态；
- 各焦层局部实例和来源 tile 的引用；
- 全局范围内的独立稀疏 mask／RLE，及显示用轮廓；
- 代表焦层；采用局部融合时的边界来源焦层；
- 来源与布局版本、模型版本、阈值、坐标变换；
- 关联置信度、边界质量、遮挡／截断／缺层标记。

**不同对象的二维掩膜允许重叠。**汇总数量按全局 ID 计一次；各对象投影面积之和与图像中的联合覆盖面积是不同统计量。二维投影长度也不应被报告为真实三维长度。

COCO RLE 适合作为权威交换格式；显示轮廓可按缩放简化，但面积应从权威 mask 或已验证的精确几何计算。普通单通道实例标签图可另行导出，明确它如何处理重叠。

## 5. RTX 3070 8GB 的运行方案

下表均为验证起点，实际参数由可用显存和目标纤维像素宽度决定。

| 项目 | 8GB 起始建议 |
| --- | --- |
| GPU 并发 | 一个 GPU worker、一个当前模型；交互任务与批量任务按优先级排队 |
| 外部空间分块 | 从 512～1024 像素边长比较，预留约 15%～25% 重叠；细长对象另设跨块连接策略 |
| 层处理 | 逐焦层进入 GPU；像素和已完成 mask 存在有界 CPU 缓存／磁盘 |
| batch | 从 1 开始；Cellpose 内部 tile batch、μSAM 提示 batch 单独控制 |
| 数值精度 | 验证支持后使用 FP16／BF16；以边界、面积变化检查精度影响 |
| 显存目标 | 初步以 worker 峰值约 6～6.5GB 为预算目标，给 Windows 桌面等保留余量；不能把 8GB 全部视为模型可用 |
| OOM 应对 | 降低提示／tile batch，释放缓存；必要时切较小模型或缩小外部块，并记录变化 |
| μSAM 兜底 | ViT-B 不能满足实测预算时比较 ViT-T；不能悄悄替换后仍将结果标成同一模型 |
| 其它内存 | 检查候选数乘以 mask 像素的开销；按候选分批处理，不驻留整片所有实例掩膜 |

缩小外部图块不一定按比例降低 SAM 编码器显存，因为它可能仍把输入变换到固定网络尺寸。还要控制提示数量、掩膜解码和缓存。大图分块及减少 batch 是 Cellpose 官方给出的内存控制方式，但其其它显卡基准不是 3070 验收结果。[Cellpose 资源说明](https://cellpose.readthedocs.io/en/latest/benchmark.html)

推理和训练必须分开预算：

- **8GB 推理**：以上小模型、逐层分块路线值得作为兼容目标验证。
- **8GB 微调**：μSAM 从较小模型、冻结部分网络、少量对象／batch 起步；RF-DETR／YOLO 使用小模型与小 batch。不要预设所有模型都能全参数微调。
- **更大显存设备**：可承担训练、更大的空间上下文、更多候选和较大模型对照；最终部署权重仍应回到 3070 验证。

μSAM 文档列有 8GB 下限制训练部件的配置，而当前训练源码也提供 Tiny 和参数高效配置。文档表与代码默认项并不完全相同，落地时应锁定版本并检查实际训练设置。[官方资源表](https://computational-cell-analytics.github.io/micro-sam/micro_sam.html#training-your-own-model)、[当前训练配置源码](https://github.com/computational-cell-analytics/micro-sam/blob/main/micro_sam/training/training.py)

FDM 继续负责界面、采集和测量；GPU 引擎使用独立 Python 环境／进程，通过任务和资产引用通信。缓存 key 应覆盖模型、来源像素、焦层、区域、预处理与布局版本。权重和环境准备完成后可以本地离线执行，无需上传样品。

## 6. 怎样用最少实验选出合适方案

### 6.1 第一阶段：30～50 个多焦层 ROI 的对比

该数量用于筛掉明显不适合的路线，不是发布级样本量。ROI 应来自多个独立切片，覆盖孤立纤维、密集交叉、低对比、弯曲、不同宽度、孔洞、图块边界和缺失覆盖。

同一 ROI 标注各层可见实例、跨层共同 ID 和最终可观测二维轮廓；不能只用一张最佳焦层图的标注评价所有焦层。保留没有目标的困难背景。

建议先跑四组：

| 组 | 输入与模型 | 要回答的问题 |
| --- | --- | --- |
| A | 现有 YOLACT：单层与逐层两种方式 | 单靠更多焦层，现有权重能提升多少 |
| B | μSAM ViT-B：AIS 与 APG | 自动候选质量与交互修正是否值得引入 |
| C | Cellpose `cpdino-vitb`，资源允许时加 `cpsam_v2` | 自动分割质量、细长对象断裂和显存情况 |
| D | 同一模型：景深合成后分割 vs 逐层分割后关联 | 焦层融合放在哪一步更合适 |

若原始数据主要是长而弯曲的纤维，加入 Omnipose；若是近似星凸横截面，加入 StarDist。第一轮不用把所有模型都接入正式 UI。

### 6.2 第二阶段：带自有标注的小模型微调

根据第一阶段错误类型，先规划约 200～500 个空间裁块，来自不同切片、制样批次和采集条件。样本数量应由学习曲线和失败类型覆盖决定，不能用很多相似裁块代替独立样本。

以原始切片或更严格的制样批次分训练／验证／测试。一个对象的所有焦层、相邻裁块、增强版本必须留在同一集合。可将人工修正后的 μSAM 结果用于训练候选，但不能把未复核的伪标签当测试真值。

微调 RF-DETR-Seg Small、YOLO26n/s-seg 或首轮胜出的显微模型时，共用测试集。对于孔洞和重叠必须先验证训练数据加载器是否保留语义；不能仅因格式叫 COCO 就假设读取完全一致。

### 6.3 评价整个测量链路

| 指标 | 原因 |
| --- | --- |
| 实例召回、精确率、AP50／AP75 | 检查漏检、误检与轮廓质量；明确使用标准 COCO AP 还是其它指标 |
| 错误合并与错误拆分数 | 一根纤维切成三段、两根合成一根，可能只有很小像素误差却有严重计数误差 |
| 跨焦层重复 ID 数、身份切换数 | 直接评价“同一对象只计一次” |
| 图块接缝处重复、断裂与遗漏 | 检查大切片部署相对孤立小图是否退化 |
| 面积、直径／宽度偏差 | 最终测量用途比自然图像分割排行榜更重要 |
| 中心线覆盖／clDice | 长纤维连通性的重要补充；需按对象评价，防止两根连成一根仍高分 |
| 人工修正时间 | 同等准确率下，更易修正的方案可能更适合工作台 |
| 显存峰值、系统内存、P50／P95 延迟、整片总时长 | 冷启动和热运行分开，包含读取、解码、关联与结果入库 |

FISBe 是细长丝状结构的公开实例分割基准，其评价实现专门区分错误合并与错误拆分，可以借鉴指标定义；其神经元数据与本项目样品并不相同。[FISBe 官方评价实现](https://github.com/Kainmueller-Lab/evaluate-instance-segmentation)

3070 实机验收应覆盖 Windows 上长时间连续批处理、取消后重试、模型切换、密集候选、缺层、空间布局变更与 UI 同时浏览。任何候选数量上限都应被记录并触发细分或提示，不能静默丢弃对象。

## 8. 进入实现前的具体产出

第一份实现任务宜限定为“本地多焦层 ROI 评测器”：读 `.fdmslide` 的同区域全部焦层，输出各层候选、全局 ID、代表轮廓、复核图和测量／资源指标。先完成 YOLACT、μSAM、Cellpose 的可重复对照，再把选定引擎接入正式画布。

第一轮的交付应包含固定样本清单、来源分组、环境与权重版本、参数、逐对象错误记录及 3070 资源曲线。由结果决定下一步是优化候选模型、层间关联，还是边界融合，避免在错误环节投入训练。
