# 从 CU“含量实验－非冻结”过渡到实时试验

## 核对依据

本次重新核对了 CU6 的 dialog 324 原始控件资源、已保存的真实 Win32 窗口树、先选／后选及计数状态机，以及此前原界面 13 项操作验证。资源与运行记录分别见 `/Volumes/LARD/cu_reverse/work/content_nonfreeze_20261013/persistence_resources/resource_evidence.json`、`runtime/cu6_main/settled_entry.json` 和 `runtime_validation.json`。本次实现过程中没有重新运行原 CU 完成这些操作，不把历史验证写成新的实机验收。

原来的工作布局是中央实时画面、右侧功能面板、下方当前视场数据、左侧全部视场数据。右侧的九行类别表是主要操作区：每行直接选类别，独立加减额外计数，并列显示平均直径、含量和实测数。将其压缩为一个类别下拉框会增加来回选择的次数，所以新工作区保留直接类别行操作。

新工作区保留中央实时画面和右侧高频类别区；来源、标定和测量方式放在顶部，原来的历史区改为画面下方的分页，与“当前视场”“全图候选”切换查看。右侧“更多设置与汇总”收纳类别配置、经纬重量、计算设置和导出。操作习惯与布局对应关系见下表；后文另列明确调整和错误防护，不表示逐像素复刻原界面。

## 保留的操作习惯

入口为主窗口“试验 → 实时试验”。新试验默认使用“含量试验”、贴边测径、两次点击、先选、数字键选类、经向，并开启保存测量原图；先配置绵羊毛和山羊绒两类。需要其它类别时展开“更多设置与汇总 → 设置本方向类别”，最多九类。已有试验会恢复保存的含量／直径模式、点击／拖动方式和先选／后选设置；每次新开工作区时，数字键默认用于选类。

| CU 操作 | 实时试验中的对应行为 |
|---|---|
| 两次左键跨纤维测径 | 默认仍为两次点击；第一次留住后台原帧，第二次使用本次点击坐标，屏幕持续更新 |
| 右侧 1–9 类别按钮 | 直接类别行、数字键和小键盘 1–9，当前类别始终可见 |
| 每类独立计数加／减 | 每行直接补计数，不必先改变当前测量类别；减号只减少补计数 |
| 先选 | 类别决定下一条测量的归属 |
| 后选 | 选类绑定本场、当前操作者和方向的最新测量操作；计算、核验、待确认期间均可改类，不会误改前一条。最新操作取消、失败或视场结束后，选类只准备下一次测量，不回落修改历史 |
| 右键选类 | 右键先取消草稿，再显示非模态类别菜单；遵循同一先选／后选模式，不暗中补计数 |
| 移动载物台换视场 | 检测到移动后清除本场标记、草稿、候选和未入账结果；已入账历史保留，稳定后继续测量 |
| 经纱／纬纱、最多三名操作人 | 保留各人独立的两组类别、重量和记录；用“改名”把默认操作者改为实际姓名，原记录归属不变；另有参与者再“添加” |
| 每类平均直径 | 主类别表显示原始实测均径；分组计算使用的均径在计算设置／摘要中单独说明 |
| 当前视场和历史分开 | 下方分页为“当前视场”“试验历史（全部操作者）”“全图候选”；历史用操作者列区分归属，候选页中的结果尚未入账 |
| 类别颜色与场内编号 | 沿用恢复的九个类别颜色，显示“场内序号 [类别号]”；文字背景增强对比，颜色不作为唯一分类线索 |
| 输出数据 | CSV 导出原始测量／补计数账本；Excel 另含当前统计引擎的方向、经纬和多人汇总，无须先打开 Excel 才能在界面看到含量 |

第一次使用时，选来源、核对标定，将“操作者 A”改名，再选经向／纬向。习惯先选的用户直接点类别后两次点击测径；习惯后选的用户先切到“后选”，在完成两次点击后，用类别按钮、数字键或右键菜单指定这一条，即使结果还在计算也能正确归类。两击之间右键会取消草稿，此时选类只用于下一次测量。正常情况下连续测量，必要时用对应类别行的加减补计数，移动载物台后等待“视场就绪”继续。

遇到越限先看待确认区的测量编号、类别、直径和范围，再点“保留”“改为当前类”或“放弃”。橙色虚线尚未入账；多条等待时，按钮处理显示的首项，后选仍作用于最新操作，编号不同时界面会明确提示。改类后仍越限需再次选择保留。查看汇总时先确认当前方向／经纬混合／多人层级，结束后保存项目。保存原图、计算方法和高级参数不会插入每次测量流程。

批量测量时选择传统或多尺度全图，再点“分析当前视场”。候选初始均勾选接受，但尚未赋类：双击类别逐条指定，或用“勾选项批量设为当前类别”；排除不需要的候选，核对越限项后勾选“确认保留”，最后点“确认已赋类的勾选项”。确认会一并处理本批，未勾选项随本批排除；未赋类或未确认越限时不会入账。疑似与本场记录重复时会另行询问，取消分析只清除未入账候选。

## 必须明确说明的变化

- **计数模式显式切换。** CU 的裸 Ctrl 会切换数字键含义；新工作区直接显示“数字键选类／数字键额外计数”。额外计数模式中，1–9 选中对应类别并为它补一根，不触发后选改类；减号只减少当前类别的补计数。行内加减则不改变当前选类。文本输入和候选类别编辑时不会抢数字键，也不会因按键自动重复增加计数。
- **撤销是真正的撤销。** CU 的“恢复”实际删除最新记录；新界面使用“撤销／重做”，覆盖测量、改类、改径、补计数、删除和操作者改名。手工操作尚未结束时会明确要求先处理，避免撤掉上一条：Esc 取消草稿，计算／核验等待结果，待确认项保留或放弃后再撤销。已入账原图仍在写盘、单纯全图候选计算均不阻止撤销。
- **越限在界面内确认。** 保留、改类、放弃绑定显示项的操作 ID；队列已变化时不会误处理下一条。已入账记录后选到越限新类别会提示并保留原类，确需修订时选中记录，点“改径／改类”。全图候选逐项赋类，越限保留必须明确勾选，换类后重新核对；不凭直径自动认定材料。整批确认后，后选指向该批最后一条，已有更晚未完成手工操作时仍跟随该手工操作。
- **切方向会明确结束本场。** CU 有当前记录时要求先到新视场再切方向；新界面保留历史，结束未完成手势并切换独立方向账本，避免通过重新选择同一操作者来间接换场。
- **统计层级明确。** 默认类别表对应当前操作者、当前方向，与 CU 面板相同。经纬加权和多人汇总需明确选择，不把它们与当前方向含量混为一谈。
- **缓冲忙不会冒充换场。** 原图保存慢时明确暂停新的测量或确认，并继续接收最新预览；不会清掉已经确认的本场标记。真正的来源尺寸／代次变化仍立即隔离旧标定与旧请求。
- **移动核验完成后才正式入账。** 等待期间新显示的帧也必须核验；两秒仍追不上则明确拒绝本次结果。旧帧先通过并不允许越过未核验的新画面，避免后来清场时历史已经被错误增加。
- **旧文件边界明确。** 本轮不导入 `.UV_手动含量实验`；新项目保存所有试验设置和记录，不能把 CU 文件选择后悄悄当作空试验。

暂停时按状态提示处理即可：缓冲暂满先等任务或原图保存完成，不必用“新视场”清除标记；移动或核验超时后，等视场就绪再测，拒绝的结果没有入账。断流时检查来源，重新连接后核对标定；若旧来源尚未停止，稍后重试切换或关闭。原图写入失败可以继续保存测量元数据，核对后可在记录表明确放弃失败原图，历史记录不会因此删除。

## 过渡验收

除算法对照外，界面回归应按实际操作链验证：先选连续测量、后选跨类迁移、某一行补计数而不改当前类、从零减数、数字键／小键盘、文本编辑焦点、换场后的后选、经纬和操作者切换、当前列表与历史列表操作隔离、候选编辑与历史删除隔离，以及项目重开后的模式恢复。

Windows 还需检查目标显示缩放下的文字、九行类别区域和按钮可达性。Qt 离屏渲染、Parallels 和真实相机验收分别记录；本说明不代替最终验证报告。

画面持续更新不代表每次测量都已成功入账。高分辨率动态输入可能触发核验超时，应以记录表和明确提示为准；具体分辨率、帧率下的吞吐量和成功率以最终性能报告为准。

R4 的 `scripts/validation/probe_cu_workspace_ui.py` 已在 Windows Qt 验证九类按钮、数字键模式可见、行内补计不改当前类别、真实测量操作 ID 的后选、非模态右键菜单及操作者改名。[1280×720 截图](validation/cu-live-measurement-2026-10-15/ui-windows-1280x720-r4.png)和[源码身份说明](validation/cu-live-measurement-2026-10-15/ui-windows-1280x720-r4.identity.json)对应 R4 独立快照；200% DPI 下请求1330×900被桌面限制为1293×802，九行仍可达。完整源码探针结果在 `build/cu-live-windows-final-r4/ui-probe-final-r4/`；此前R3与macOS离屏证据仍保留原身份，不冒充重新执行的R4结果。

上述图像是合成静态图的**源码 Qt 截图**，不是安装包截图或真实CU设备流。[R4发布记录](validation/cu_windows_release_final_r4_20261015.json)另行验证同一安装器解出的实际EXE：主窗口菜单进入实时工作区、11个关键控件可见、关闭后自然退出0且无剩余进程；没有执行注册式安装／卸载。R4沿用R3的操作与界面，仅调整原生运动峰值扫描的有限数分类。功能、布局和峰值内核提速不代表高频性能通过，[R4正式性能](validation/cu-live-measurement-2026-10-15/R4_PERFORMANCE.md)已经完成：短程36条件15通过／21未达标；2K合成换场的Windows真实Qt一小时记录14036条、359次换场，数据完整性通过，但GUI发布最大值23.716 ms超过4 ms门槛，不能称全面达标。该小时不代表4K／6K或真实相机；[R3短程成绩](validation/cu-live-measurement-2026-10-15/R3_PERFORMANCE.md)完整保留，不能据新版内核收益改写旧失败。设备及发布边界见[验收矩阵](validation/cu-live-measurement-2026-10-15/DEVICE_MATRIX.md)。
