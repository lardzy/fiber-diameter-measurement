# 本研究目录的 Git 与本地档案边界

本目录记录 2026-10-22 至 23 日对一台指定 Windows 11 虚拟机的空间审计及获授权清理。Git 保存源码、报告、精简清单和小型执行回执；完整机器盘点、逐文件身份及恢复档案留在本地，由本目录的 [.gitignore](.gitignore) 排除。**忽略只影响 Git 跟踪，不代表这些本地文件可以删除。**

## Git 中保留的内容

- [首次空间审计报告](空间占用分析.md)、[最终清理结果](cleanup/清理结果.md)、保留及维护规则、[归档恢复说明](cleanup/README-归档恢复.md)。它们记录不同阶段的事实，首次审计中的“未清理”状态不是最终状态。
- `tools/` 与 `cleanup/tools/` 的 Python、PowerShell、C# 源码和固定输入，以及宿主传输、磁盘测量、归档校验脚本。
- 审计摘要、候选/保留清单、组件维护日志、空间前后测量、保留文件核验和启动检查等小型回执。
- [delete-summary.json](cleanup/delete-summary.json)：从原始删除回执投影出的 32 个目标统计，包含目标路径、状态、文件/目录数量、逻辑字节和目录是否残留，省略逐文件/逐目录列表。摘要记录原始 `delete-result.json` 的字节数与 SHA-256，生成摘要没有重新执行清理。

以下内容没有进入 Git。仅克隆仓库不能取得它们，也不能完成原始归档的完整校验或恢复：

| 本地路径 | 用途 |

| `host/host-inventory.json` | 宿主虚拟机文件与配置盘点 |

`cleanup/*.zip` 也覆盖该目录后续生成的归档。归档不因被忽略而获得异地备份；需要迁移或清理这份研究目录时，应先按[归档恢复说明](cleanup/README-归档恢复.md)保存并校验上述配套材料。它们不属于可以随意重建的编译缓存。

既有报告中的这些本地文件链接和脚本输入保持原义：在原工作区可以访问，在仅有 Git 内容的副本中可能缺失。需要全量核验时，应先补齐匹配 SHA-256 的本地档案，不要把缺失解释为原始验证失败或用新生成的文件冒充旧证据。

## 校验清单与历史字节

根目录 `SHA256SUMS.txt` 和 `cleanup/SHA256SUMS` 是历史交付清单，包含未提交的本地材料。保留它们的原始字节，不因 Git 忽略范围而删行、重算或改写历史哈希；仅在配套本地文件齐全时核对相应条目。

此次整理发现一项既有差异：根 `SHA256SUMS.txt` 中 `空间占用分析.md` 的历史哈希与当前报告不一致；当前报告已含后续清理完成及完整索引迁移的提示。本次没有再次改动该报告或更新旧哈希，也不把这份历史清单描述为当前全部通过。该报告的当前提交字节应以 Git 内容及新的提交范围校验清单为准。

此次 Git 整理新增本说明、忽略规则及删除摘要，不修改已有报告、原始执行回执或历史校验清单。新增的 `COMMITTED-SHA256SUMS.txt` 仅覆盖本次纳入 Git 的文件，不包含清单自身，与历史全量清单分开使用。

## 脚本适用范围

这些脚本绑定了当时的虚拟机名称、绝对路径、文件身份、允许目标和执行阶段。清理已经完成，来宾临时目录已删除，旧前置状态也已经改变。**源码用于审计与理解当时操作，不应当作通用清理程序直接运行。**

在另一台机器或当前状态下重新使用前，必须重新盘点、确定范围和保留规则并核对当前身份；已有授权、旧执行回执或旧路径名称都不能替代新的状态核对。单纯阅读、提交或校验这些文件不需要启动虚拟机，也不应触发任何删除或磁盘压缩。
