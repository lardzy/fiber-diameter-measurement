# CU 模板加载复核与 FDM 模板功能重做依据

日期：2026-11-11。FDM 检查基线：`ec21a0c085ab77e785710fde49ad29db0fa44fab`，版本 0.4.14。

本文记录修复前的调查快照，文中的“当前 FDM”指上述基线。后续实现和真实 Excel／安装验证见 [修复验证报告](../validation/trial-template-redesign-20261111/README.md)。

## 结论

`sheet.xlt` 是完整的 Excel 报表模板，包含工作表、可见性、格式、公式、控件和 VBA。它不是仅用于指定原始数据地址的“映射文件”。FDM 当前虽将用户选择的路径交给 Excel，但随后仍主动写入标准、组距并执行 CU 的“分组”宏；该宏会重新组织工作表显示。这与“按所选模板原样创建工作簿，然后写入测量数据”不是同一个行为。

本轮确认两条独立问题：

1. **替换默认模板文件不一定生效。** FDM 首次将程序资源中的模板复制到用户目录，之后始终保留该个人副本。替换程序包中的 `sheet.xlt` 后，已有用户仍读旧副本。已通过真实 Python 解析函数隔离复现。
2. **即使读取正确文件，也可能改变用户期待的报表页面。** FDM 打开工作簿后自动执行“分组”。用户提供的 `sheet.xlt` 中，该宏明确隐藏除“标准选择”之外的工作表，再显示固定的原始数据、分组统计及棉麻／非棉麻报表，并重新选择当前工作表。此项由当前 FDM 源码与该文件实际 VBA 静态证明；没有执行宏。

用户明确说明故障发生在**打包后安装到另一台 Windows 电脑**，且此前已确认使用“含量试验 → 报告 → 选择模板”。本轮没有取得那台机器的程序身份、偏好文件和工作簿，因此不能宣布上述某条已经被证明是现场唯一原因，也不能把主设置里的另一种模板入口当作用户操作错误。

## 1. 原 CU 的实际调用链

### 路径来源和打开方式

CU5、CU6、免脱色版均使用以下链路：

```text
GetModuleFileNameA(NULL, 程序路径缓冲, MAX_PATH)
    → 拆分 EXE 的盘符和目录
    → 在同目录拼接 sheet.xlt
    → CreateDispatch("Excel.Application")
    → Application.Workbooks
    → Workbooks.Open(完整模板路径, 其余参数缺省)
    → 保留返回的 Workbook / Worksheets 对象
    → 取得 Worksheets.Item("原始数据")
    → Range.Value2 写入原始数据
```

必须纠正此前描述：原程序实际调用的是 **Workbooks.Open，DISPID 0x783**，不是 Add。观察到文件名加十四个 `VT_ERROR / DISP_E_PARAMNOTFOUND` 缺省参数。Excel 对模板文件的缺省 Open 行为是创建基于模板的新工作簿；`Editable=True` 才是直接编辑模板。[Microsoft 文档](https://learn.microsoft.com/en-us/office/vba/api/excel.workbooks.open)

FDM 使用 Add 并不单独证明它会打开错文件；模板路径、已关联工作簿和打开后的初始化更需要核对。

| 版本 | EXE 路径初始化 | 打开模板 wrapper | 取得 Workbooks | 调用 Open |
|---|---|---|---|---|
| CU5 | `0x7e7b20`，调用点 `0x7e7e3f` | `0x86a5c0` | DISPID `0x23c` | DISPID `0x783` |
| CU6 | `0x607a00`，调用点 `0x607d1f` | `0x68a670` | 同上 | 同上 |
| 免脱色 | `0x47a190`，调用点 `0x47a4be` | `0x529ae0` | 同上 | 同上 |

CU6 含量构造器 `0x6a3010` 拆解 `this+0x482c` 所在的 EXE 路径，生成 `sheet.xlt`，调用创建 Excel、打开模板和取得“原始数据”的封装。新 REA 反编译还复核了日期、逐操作员输出、整批输出和 Excel 探活恢复相关入口。

在已查明的启动链中，没有先复制到 AppData、优先读取旧个人模板、或者从程序资源释放默认模板的行为。此为该调用链范围内的结论，不声称已排除 CU 全程序的所有文件复制功能。

### 工作簿复用、测量与保存

- CU 在活动试验中保留 Excel COM 对象，后续测量向该工作簿写入，不是每次重新读取磁盘模板。
- CU6 `0x6a47a0` 通过 A1 读取检查对象；可用时复用，失败才沿已保存路径重新打开模板。替换磁盘模板不会自动改写已经打开的工作簿。
- CU6 `0x6a3f80` 依次调用 `0x6a2900` 输出三位操作员数据。单元格写入封装 `0x68b4e0` 使用 Range / Value2；原生试验保存与 Excel 文件保存分开。
- 历史 CU6 运行记录确有同一 `sheet1` 从空表更新到 D25=15、D26=30、E25=18 的证据。本轮没有重新运行 CU，这些是历史运行证据。
- 退出时释放 COM 引用与成功关闭工作簿不是同一结论；已留存的退出反编译不能独立证明所有退出分支均成功关闭 Excel。

### 模板宏并非通用的打开初始化

原 CU 模板的 `ThisWorkbook.cls` 仅含属性，没有 `Workbook_Open`。`Standard_Change` 是“标准选择”中的窗体控件宏，设置组距后调用“分组”。已复核的含量构造器没有调用此宏；不能把用户操作标准控件的行为当作“每次打开必须自动分组”。

## 2. 用户实际模板中的显示副作用

检查文件：`/Users/lishuyang/Downloads/sheet.xlt`。

SHA-256：`56f6f1510932d1d1a33b34b6831671b17f5ab4366d26dea320a371f705d90417`。

此哈希与此前用户提供的 `sheet11.xlt` 一致，文件名变化不影响身份。没有修改该文件。

静态读取 Workbook 的 BIFF 记录进一步确认：该文件共有 **12 张工作表**，保存时活动页是 **“特种毛(报出)”**。相对原 CU6 的 8 张表，增加的四张表如下：

| 用户模板中的工作表 | 文件保存时 | “分组”宏源码的处理 |
|---|---|---|
| 特种毛(报出) | 可见，且为活动页 | 整体隐藏后没有恢复分支 |
| 麻棉(报出) | 可见 | 整体隐藏后没有恢复分支 |
| 分组加权统计 | 可见 | 整体隐藏后没有恢复分支 |
| 织物纤维含量报告 | 可见 | 整体隐藏后没有恢复分支 |

这四张恰好就是用户模板增加的报表页。因此，不能以 Excel 最后显示了原 CU 报表就断定打开的是原 CU 文件：当前 FDM 的初始化足以改变这四张新表的可见性和初始活动页。

当前 macOS 仓库及个人模板虽与用户 Downloads 模板哈希不同，也均有上述 12 张表，初始活动页同样是“特种毛(报出)”。**哈希不同不等于“那份就是 CU 原厂旧模板”**；需要结合工作表内容和初始化行为判断。另一个电脑的实际文件仍未取得。

从该文件静态提取的“模块1 / 分组”包含：

- 遍历 `Sheets`，将非“标准选择”工作表隐藏。
- 重新显示“原始数据”“分组统计”。
- 按 `标准选择!C10` 显示“非棉麻织物／非棉麻纤维”或“棉麻织物／棉麻纤维”。
- 改变部分列的隐藏状态，清除、生成分组区公式。
- 末尾选择“非棉麻纤维”“棉麻纤维”或“标准选择”。

FDM 当前 `excel_live.ps1` 的 `New-Batch(open)` 自动加入 `settings` 和 `macro` 操作；`Apply-ReportSettings` 设置标准索引与组距；`Recalculate-Report` 激活工作簿并调用该宏。因此有完整的静态路径把“新模板的初始显示”改成“CU 宏规定的显示”。是否这正是现场所说的“旧表”，仍须读取现场生成工作簿确认。

## 3. FDM 源码与隔离复现

| 项目 | 本轮结果 | 依据 |

“报告 → 选择模板”还会紧接着启动单独的 `inspect()`，与新实时工作簿创建可能并发。前次真实 Excel 验证将 `panel.inspect` 替换为空函数，因此没有验证完整的正常按钮路径。当前需将此列为独立验证项目，不能凭两个任务都单独通过就声称完整入口通过。

并发静态复核没有证明检查任务一定误关实时 Excel：若实时进程已存在于检查任务的进程快照，检查任务会拒绝占用该进程，不执行 Close/Quit。同一新进程被两个任务误认领仅是待验证条件风险，本报告不把它认定为现场根因。细节见本地 `choose-inspect-concurrency-analysis.json`。

本轮四个隔离复现使用生产 Python 解析器／协调器和模拟通信，**没有真实 Excel，也不是远端故障复现**。原始配置与模板前后哈希未变。

本机 Windows 新 onedir 的 manifest 是 `ec21a0c`，不能笼统归因于“用户还在用旧包”。该 onedir、用户另一个电脑安装的程序、当次运行的程序是三个不同证据对象。

## 4. 建议重做的行为合同

### 一个明确的模板来源

1. 默认直接使用程序提供的模板文件；取消隐蔽的首次复制、永久优先个人旧副本行为。页面显示完整有效路径，并提供打开所在目录。
2. 用户选择外部模板后，直接以所选完整路径作为有效来源；含量报告页与主设置“采集与试验 → Excel 模板”使用同一个服务和配置。普通测量的原始记录导出模板继续单独命名和管理。
3. 文件不存在、不可读或配置损坏时明确报错，不能静默改用 CU 默认表。UTF-8 BOM 等可识别格式正确读取。
4. 在选择、创建工作簿及重新进入时核对源文件身份；保存路径、大小、修改时间与 SHA-256。日常测量不反复哈希模板。
5. 旧个人副本不删除。迁移时明确指出旧选择和新来源，不能再把隐蔽副本当成不变的实际默认。

### 模板本身决定初始报告

1. 对 `.xlt` 按 CU 的模板打开语义创建独立工作簿，模板原文件不作为实时测量保存目标。
2. 保留模板的初始可见工作表、当前页、布局、公式、控件和宏。只按映射写入约定的测量输入。
3. 不在通用 `open` 中无条件执行 CU“分组”、改标准／组距、重建报告页。需要重新统计时作为明确的用户动作；特殊模板确需初始化时，由该模板的明确配置定义。
4. 样品、人员等首次信息填入与测量输入分开；沿用用户已确定的人工维护边界。模板格式检查只能检查能否写入必要数据，不能为了通过检查把模板改成默认报表。

### 模板选择与工作簿关联分开显示，操作上一次完成

1. 在当前试验选择模板，就为当前试验准备该模板的新工作簿，同时设为以后默认；旧工作簿保留给用户保存。
2. 新工作簿创建、必要映射验证、当前试验数据补齐成功后，才切换当前关联；失败保留旧关联并明确显示失败，不将旧表标成新模板。
3. 已打开的工作簿不因磁盘源文件变化而被静默改写。发现同路径内容变化时提供明确的重新创建入口；新试验使用当前文件内容。
4. 只读检查与正式创建不并发开启相互独立的 Excel 自动化流程。复用已打开目标进行必要验证，或将离线检查先完成，再创建工作簿。
5. “查看 Excel”只定位当前成功绑定的工作簿；显示其名称、源模板路径、源指纹和关联状态。一次性导出与实时工作簿使用同一明确来源。

### 可带回的安装版诊断

增加单次模板诊断输出，记录实际 EXE、构建 ID、配置目录、模板选择来源和哈希、试验 ID、关联代次、Excel PID／工作簿名、创建与初始化阶段及错误。这样能区分“选错文件”“旧个人副本”“保留的旧工作簿”“初始化宏改变显示”，避免靠截图外观猜测。

## 5. 下一轮验收应覆盖的完整流程

- 安装版普通用户环境：首次安装、保留旧个人副本的升级环境、外部模板路径、同名替换、中文路径、退出重启。
- 正常主窗口路径：“采集与试验 → 含量 → 报告 → 选择模板”，不关闭 `inspect()`，不直接只构造独立报告面板。
- 用原模板和用户模板的实际工作表内容、可见状态与活动页辨别，不能只检查传出的路径或加一个人工标记。
- 对照“仅按模板打开”和“FDM 创建并写入”工作簿，必要输入之外的格式、可见性、页面和人工字段保持一致。
- 既有记录补齐、旧工作簿人工修改、模板更换失败、Excel 忙碌、同路径内容变化，及人工保存／另存。
- 本轮不重做已经验证过的全部测量同步算法；重点验证模板选择、工作簿创建、输入初始化及报告操作的边界。
