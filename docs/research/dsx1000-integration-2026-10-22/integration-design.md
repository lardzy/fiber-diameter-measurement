# FDM 接入设计与离线部署边界

2026-10-22。本文件为待验证设计，未增加可运行的 DSX 后端。设备环境固定为用户已验证 FDM 可启动的 Windows 10 1909；不把重装/升级作为前提。

## 1. 当前工程与分支

FDM 0.4.10 是 Python/PySide6 离线显微图像工作台。`src/fdm/ui` 负责交互与任务编排；`services` 负责采集、设备控制、图像处理、测量和存储；`native` 为部分高耗时算法提供本地实现；`tests` 与 `docs/validation` 保存回归及平台验收材料。普通图像项目与 `.fdmslide` 切片各有持久化路径；数字切片用 SQLite 保存清单、各焦层 tile 及空间索引。

分析基线：`lard/cu-live-measurement`，HEAD `04eda270f6071a212bb0dd4438033a27cbafad74`。首轮记录为领先2次提交；交付前复查本地远程跟踪分支已与HEAD一致（0 ahead / 0 behind，本轮未 fetch 或 push）。此分支近期集中在采集/含量及直径试验的实时测量体验和稳定性，尚非 DSX 专用分支。最近提交：

## 2. 路线选择

| 路线 | 本轮判断 | 采用门槛 |
|---|---|---|
| 原厂批量扫描＋全部层图输出 | 内部完整层图和按事件推进已证；外部出口未证 | 可指定范围/间距，并输出每层完整像素、位置/身份、可靠完成与取消；不能只有EFI或拼接图 |
| **同机桥接＋RDK逐层二维快照** | **优先现场验证候选**；入口、运动与快照链已找到 | 整数µm网格满足业务；位置鲜度、新文件完成、控制权及停止恢复全通过 |
| 同机桥接＋内部托管服务 | 可能避开RDK量化/导出局限，但尚无稳定外部初始化契约 | 进一步限定分析原厂宿主、依赖注入、事件/缓冲生命周期和资源所有权；不能直接认为加载DLL即可 |
| 驱动/硬件协议适配 | 不作为本轮推荐 | 上层确实不能满足且初始化、状态、曝光同步、停止等均有充分证据后再评估 |

原厂采集后导入仅用作图像质量与格式的对照，不替代最终 FDM 调度。选择 RDK 候选是因为它已经提供原厂进程内的控制路径；不是证明所有采用条件已经通过。

第二轮提供了 [独立现场收集工具](collector/README.md)，用于默认观察和手动单次 RDK 操作；它不是本节拟议的 FDM 桥接后端，也不实现自动五层/45张扫描。新增调用证据见 [深入分析](deep-analysis/deep-findings.md)。

## 3. 桥接进程与依赖

拟议桥接进程只做协议/会话、任务关联、输出校验和错误归一化，不直接加载相机驱动。FDM 到桥接使用同机管道或等效本机通信，桥接到原厂采用已确认的 RDK TCP 地址。LAN 用于成果交换，不插入每个电机/曝光步骤的控制回路。

本次收集工具采用 C# WinForms、x64、.NET Framework 4.8，另附 PowerShell 5.1 基础盘点脚本。正式桥接首选独立 x64 小程序；具体运行时仍须按现场验证结果锁定。若使用 .NET Framework，可将目标定在现场已安装且经验证的版本；若选择 Python，则随验证过的 FDM 运行时打包独立 helper。**当前不新增运行库安装前提，也没有承诺某个未测试的构建能在1909运行。** 纯协议桥接本身不必匹配原厂进程位数；一旦转为加载原厂 DLL，则必须按原厂实际架构与 x64 native 依赖重新确定宿主，不能放入 Qt 主进程试错。

原厂 APP/CTRL 保持唯一设备所有者，沿正常登录和初始化流程工作。由 APP 启动的 RDK 模式涉及旧 CTRL 退出及上下文恢复；桥接不能自己启动第二套 CTRL。进入扫描前显式取得已验证的远程模式，完成后释放并确认原厂恢复操作。

## 4. 统一接口合同

以下是语义草案，不是已经存在的 Python 类或可直接调用的 DSX API。

| 合同 | 必需内容 |
|---|---|
| `capabilities` | 可用轴、坐标单位/网格、绝对/相对支持、位置来源/鲜度、完成语义、已验证停止能力、快照模式/格式、是否支持批量层图 |
| `read_position` | 坐标值、原始单位和变换版本、源会话、采样/收到时间、来源种类、可用的序号/鲜度证据；未知必须明确表示 |
| `move` / 终结结果 | request_id、目标、接受时刻、回复时刻、报告位置、target_reached与其证据、终结原因；拒绝、限位、取消、超时、不明状态不合并为success |
| `request_capture` / 完成结果 | capture_id、field/z_index、成像模式、目标文件/图像身份、捕获关联证据、尺寸/位深/通道、标定、报告位置、像素所有权、成功/失败 |
| `cancel` / `stop` | 区分请求已发出、原厂已接受、任务已终止、轴状态已确认；未证明异步能力时返回“不支持可靠中止/状态未知”，不得伪造成功 |

调度器采用：准备 → 接管 → 移动 → 验证位置 → 必要稳定 → 请求拍照 → 等待并校验图像 → 提交tile → 下一层/视场 → 完成写盘 → 释放。所有操作都有期限，但期限只用于发现异常；不能到时自动当作完成。

第二轮已证 FocusResultData.set_ZInfo 用 BeginInvoke 异步更新 Focus 字段；XY 查询则直接读 UiResultData 缓存。位置缓存可能在回复后刷新，所以“回复后立刻读一次”的协议不足。应先在现场确定可验证的刷新/事件规律；若无法可靠识别本次运动后的新坐标，只能记录接口缺口。短时间轮询到相同值不能自动证明新鲜，尤其不能用于未动/限位/复位后的假成功。

普通快照输出采用每个 capture_id 独占的本地目录或唯一基础名，锁定当次保存格式，确认原厂实际附加counter/扩展名及 _C/_H 文件族的规则。`CHATSAVE` 不负责设置格式，其目录必须存在、counter为0..999；不能依赖长期递增counter提供全局唯一性。不同请求不复用路径；先证实可表达/不会覆盖，再执行扫描。

正常非拼接路径已补证 APP 自动保存处理返回先于 CTRL 转交结果和 UI 状态0，但保存失败、取消也能到0，原生 writer 的全部文件关闭/持久化行为未证。`SHOT` final 后仍保持位置不变。应联合使用本次请求/启动信息、状态、错误和唯一新文件完整解码建立结果；如果启动状态因采集太快没被轮询观察到，必须有另一种经验证的身份关联，不能凭状态0推测成功。没有可靠结束信号时，文件出现/大小暂时不变不能单独作为曝光或写入完成的证明。

错误归一化必须保留历史/共享来源：内存 ErrorCode 不随每条请求清零，任一 final reply 可能消费 APP 写出的共享错误文件。不能把 GETERRCODE 或 SHOTSTS 回复强行绑定为本次保存结果，也不靠定期读取错误码清空状态。

## 5. 坐标、标定和完整 Z 栈

建议定义独立 `PhysicalPosition` 数据：单位µm（内部可用十进制定点nm保存数值，但不暗示nm精度），同时保存坐标系ID、原点、轴方向、原厂raw/display变换和接口可表达网格。XY采样步距由物镜/相机标定和重叠率计算，然后检查能否落在RDK整数µm网格内；实际网格与期望的偏差必须明确，不能静默四舍五入。

Z采集先确定中心/范围；原厂 ExtendMode 切换会重算 pitch，必须在模式确定后核对实际层距、范围和层数，再冻结目标层列表。使用自动对焦时只用于扫描前确定中心或范围；不逐层AF。每层同时记录目标位置与独立报告位置，后者注明缓存/设备查询/未知来源。原厂内部 `Zpitch × CurrentStep` 只能记录为 nominal_z，不能冒充 measured_z。

拟议采用 **有版本升级的 `.fdmslide` 物理坐标扩展**：

- 旧格式/自研后端仍保留原整数步数字段及语义。
- 新版增加按 tile_id 关联的物理位置/采集身份记录，manifest标明坐标系统、单位、变换和生成后端；focus层序仍由z_index负责。
- 新数据不把µm塞进旧steps字段，也不以假0/取整值作为可用于控制的旧坐标。兼容字段如何留空/迁移须在实现时与schema一并设计；不写出可被旧版静默误读为step坐标的文件。
- 新读者继续读取旧文件；旧读者对新版本须有明确的拒绝/仅图像查看策略，在实现测试中验证，而不是假设它已支持。
- 保留每层capture_id、文件/像素哈希、成像参数、坐标来源和成功终结证据；缺层/失败单独标记，不填上一张替代。

二维镜头标定、像素分辨率与样品台µm坐标是不同量。必须记录图像像素与样品台轴的旋转/镜像/比例映射；不能仅凭运动量推断物镜比例尺。来源于原厂文件的标定也要与实际倍率、像素模式核对。

解码后给 FDM 独立拥有的不可变缓冲，不借用会被原厂下一帧覆盖的指针。首轮选择完整无损二维输出，确认位深/色彩和现有tile编码能力；若当前tile格式不能保留必需的高位深，先列格式缺口并扩展后再接受，不能悄悄降为8位。EFI或同层HDR处理必须在元数据注明；全部焦层不可由融合图替代。

## 6. 取消、失败与恢复

RDK单命令串行接收，`ENDSHOT`存在不等于任何时候都能及时执行。首先停止FDM继续派发，使用已验证的原厂停止手段，并分别报告“已请求取消”和“已确认停止”。失联、超时或原厂退出进入状态未知，不能自动重试移动、重复SHOT或自动回零。

已提交tile保留，未校验的图像不进入ready状态。重连创建新session/generation，核对原厂模式、位置和采集状态，丢弃旧会话迟到结果。恢复原厂使用必须有明确接管/释放验收；缺少可靠停止/恢复时不能进入无人值守长扫描。
