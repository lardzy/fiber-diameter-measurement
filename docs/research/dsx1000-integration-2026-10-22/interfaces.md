# DSX1000 证据化接口清单

2026-10-22；静态接口研究，不是设备操作脚本。具体方法、构建身份和证据 ID 由 [入口专项](entrypoints/entrypoints-findings.md)、[运动专项](motion/motion-findings.md)、[采集专项](acquisition/acquisition-findings.md) 提供。31 个 RDK 命令的参数个数和模式约束已从属性字节解析，见 [元数据](entrypoints/rdk-command-metadata.json)；以下只列与接入相关的子集。未解释的参数不填猜测值。第二轮补证见 [保存、缓存与错误分析](deep-analysis/deep-findings.md)；现场操作使用 [独立收集工具](collector/README.md)，本表不自动授权或执行命令。

## 1. 启动、传输和设备占用

| 层面 | 已证实的静态行为 | 适配约束/未知 |
|---|---|---|
| 原厂 APP → CTRL | APP 协调登录、WCF、原厂系统/用户状态；RDK 启动路径会终止已有 CTRL 再启动新的 CTRL | 应使用现场确认的正常原厂入口；不能在已有采集时直接另启 CTRL |
| RDK 模式 | CTRL 首参数必须匹配 `_dsxApplicationRdkOnlineMode` 才创建 RDK 上下文；APP 有 `/ID:` 及正常 `/PASS:` 登录相关处理 | 字符串存在不证明选件已启用；不绕过登录，不单独使用该参数试启动 |
| 初始化 | 监听后首次客户端连接与原厂初始化、APP `StartedNotify` 协调 | 客户端先理解自动初始化/握手，不盲发重复 INIT |
| TCP | 配置端口 35001，UTF-8 文本，CRLF 行边界，地址由本机 DNS 解析选择 | 实际地址/监听条件待核对；不能假定 localhost，也不需要为同机接入预先改防火墙 |
| 分发 | 接收回调同步执行命令，返回后才继续接收；多行命令放入栈再弹出 | 单连接、单请求，收到终结应答后才派发下一条；禁止多行流水线 |
| 应答 | 部分命令先接受再等待业务释放；`SendAll` 广播、等待状态共享 | 客户端自建请求身份并串行匹配，不能假定支持独立多客户端会话 |
| 编码与参数 | 参数按空格/逗号拆分，未查明带引号路径转义；部分数字调用文化相关Parse/ToString | 现场核对区域设置、数字小数点和路径可表达性；首次用简单独立目录，不能直接套用包含空格的路径 |
| 控制权 | `CHMODE` 的远程模式锁定原厂 UI/控制台，退出模式释放 | 复用原厂唯一硬件所有者；不能另外打开相机/串口抢占 |
| 连接中断 | 所查 EOF/异常路径记录并退出，未证明自动停止/释放 | 失联即状态未知；连接关闭不是停机确认 |

`CommandWait` 循环中的 `WaitOne(1000)` 是等待/检查周期，事件可提前唤醒，不能据此推断每个动作固定消耗一秒。

## 2. 外部命令的可用语义

| 入口 | 参数/单位 | 静态用途与完成含义 | 接入判断 |
|---|---|---|---|
| `CHMODE=` | 1 个；1 接管、0 释放 | 改变远程控制模式及原厂操作状态 | 接管/释放流程要现场闭环 |
| `MVSTG=` | 3 个；X、Y 为 Int32 µm 绝对位置，另有速度枚举 0/1/2 | UI/业务 → StageService → 同步设备移动；服务 finally 释放 RDK 等待 | 回复后仍需检查错误、位置/鲜度及目标容差；速度枚举的现场效果待核对 |
| `MVZR=` | 1 个；Double µm 相对请求 | 当前显示位置＋相对量后 `conv.i4`，以整数 µm 目标进入 UI；底层走 Z 相对移动 | **不具备已证明的亚微米目标能力**；接近限位/STOP 可正常释放而不设错误，不能仅凭最终回复认定到达 |
| `STGPOS?` | 0 个；返回整数µm，半值远离零取整 | 直接读 UiResultData.StageData 缓存；其更新后的 UI 通知使用 BeginInvoke | 缓存刷新、坐标原点/方向和与本次移动的关系要核验；不能据此验证亚微米误差，不预设每次都发硬件查询 |
| `ZPOS?` | 0 个 | `Focus.RawZCurrentPos → ConvertZPosForDisp → ConvertUnitOfLength → 字符串` | Focus 字段在 UiData.ZInfo 的 BeginInvoke 通知后才更新；缺少逐查询硬件屏障或新鲜序号 |
| `GETSTS?` | 0 个 | 仅定位到命令元数据，未在所查完整handler列表定位实现 | 不作为已证可用状态入口 |
| `GETERRCODE?` | 0 个 | 读取粘滞的历史 ErrorCode；元数据禁止拍摄中执行 | 每条 final reply 都可能消费并删除共享异步错误文件；不是当前请求独占错误，不把0替代成功 |
| `SHOT=` | ONOFF、path；0复用保存设置，1覆盖本次保存位置/名称 | 按所选模式派发采集；普通/Extend另行设置，时间序列模式被拒绝 | **最终回复不是新图或文件完成屏障**；不返回实际文件名/采集身份 |
| `SHOTSTS?` / `RESTOFSHOT?` | 各 0 个 | 正常非拼接结果路径在 APP 自动保存返回后置0；停止、保存失败也可到0 | 需结合本次启动、错误和唯一完整新文件；0不是成功状态证明，快速任务可能在两次轮询间完成 |
| `ENDSHOT=` | 仅参数0 | 派发停止拍照请求后返回，不等待停止完成 | 同连接的接收可能被前一命令阻塞；不是已证的异步停止接口，更不是所有轴急停 |
| `RDSETTING=` | 首参数0、现有条件文件路径 | 通过原厂菜单处理器加载条件文件 | 不等于任意Z配方或原始层出口；逐项核对生效参数 |
| `ACQMODE=` | 1→内部Mode0普通Snap；0→内部Mode1 Extend | 参数与内部枚举反向映射 | 还需确认普通采集类型和处理链，不能按数字直觉设模式 |
| `CHATSAVE=` | ONOFF、已存在目录、基础名、counter 0..999 | 目录不得以反斜杠结尾；依次更新自动保存参数并等待 | 不设置格式/扩展名；已证部分格式添加 _C/_H、不同位置有唯一编号处理；完整碰撞/实际文件族仍须核对，counter不能充当全局唯一身份 |
| `AFEXE=` / `MVZHOME=` | 各1个 | 自动对焦/回零相关入口 | 仅作为范围/中心确定等独立动作；固定栈采集不得逐层重置焦点，现场首轮不把回零作为默认初始化 |
| `LIVE=` | 2 个 | 实时显示相关控制 | live 刷新不是 snapshot 完成；预览不可顶替定量层图 |

## 3. 内部运动与图像接口

| 内部路径 | 已证实 | 不应外推 |
|---|---|---|
| `SsuStage.GetCoodinates` / `ZDrive.GetZPosition` | 分别发出 `XYP?` / `FP?` 并解析硬件回复；XY 脉冲×312.5 → nm，Z 脉冲×10 → nm | 数值换算不是实际精度/重复定位指标；外部 RDK 查询不自动等同此调用 |
| 同步设备运动 | `AHardwareWithPort → IPort.Receive → EventWaitHandle` 等待匹配回复 | 未有设备时序证明其与机械停止、曝光窗口的精确关系 |
| Z `Moved` | 来自 NFP 位置通知 | 不能直接当作本次命令完成事件 |
| 普通重复快照 | 过滤图事件 → 同步事件3 → Z移动/回复 → 释放下一次拍照 | ExtendMode 的不同分支不同；连续扫描的位置/曝光同步尚未建立 |
| `CAM_SIA_CaptureEx` | 使用快照缓冲；驱动事件3进入 snapshot，事件2进入 live | native 返回不代表曝光完成；内部 FrameNo 不保证跨请求全局唯一 |
| `EFIInputImageInfo` | FrameNo、名义 ZHeight、像素指针、字节数；合成前复制每层 | 不保证传感器RAW、绝对位置或外部可持有的指针寿命 |
| debug层图文件 | INI Debug.SaveStackImagePath 非空且目录存在才写 raw；写入返回值未检查 | 不作为可靠产品出口；不修改 ZSTACK_IMAGE_SAVE 试图绕过缺口 |

`OlydCamera` 的104个 P/Invoke 声明指向 `CamDriver64.dll`。原厂托管层还负责设备初始化和状态，不宜只导入一个 DLL 就假设可以独立取图。

第二轮已跟到 APP `PerformAutoSaveInfoOperation → ExportImage → Result`、CTRL 转交结果 DAO 及 UI 状态0的正常顺序。托管编码器存在 Close/Dispose，Exporter 也有等待退出；原生 DSX/TIFFExt writer 的全部关闭/持久化语义未证，不能将这些分支概括为通用落盘屏障。`GETERRCODE` 查询可能消耗共享状态，收集器默认观察页不进行协议查询。

## 4. 拟议调用顺序与完成门槛

1. 核对文件身份和正常启动模式，启动已确认的原厂流程；监听出现后建立一个RDK客户端，再等待原厂自动初始化成功通知，确认设备可操作。该模式会先等首个客户端，不能反过来等待初始化完成才连接。
2. 按确认的原厂流程接管；读取配置、坐标变换、行程及状态，锁定本次扫描参数；ExtendMode 切换可能重算层距，需记录切换后的实际值与单位。目标必须能被当前接口准确表达，禁止静默截断层距。
3. 为移动分配本地 request_id，串行提交；记录接受应答和终结应答。保留全部原始回复，对历史/共享错误注明关联不确定性；核查终结原因，并等待具备已验证鲜度的位置报告进入目标容差。
4. 必要光学稳定量在设备验证后独立应用；不能将“等待一段时间”作为未知到位状态的替代。
5. 为当前 field/z_index 分配不复用的 capture_id 和输出名。确认自动保存/配方后派发一次二维 SHOT；其 final 只推进到“等待图像”。
6. 用本次启动关联、状态/错误、唯一新文件和完整可解码内容建立完成证明。若无可靠启动或完成身份，保持未完成。文件大小稳定、目录出现或时间戳单独都不足。
7. 核验尺寸、位深、通道、标定及XY/Z关联，复制为 FDM 所有的不可变像素/文件记录，再提交 tile。此前不得推进到下一层运动。
8. 结束后等待写入完成，再按已验证流程释放远程模式。任一步取消/超时进入专门终止流程，保留已提交数据，不能误报“已停机”。

以上是接口合同设计。完成反馈的物理语义、缓存鲜度、唯一文件和取消能力必须经 [现场规程](field-validation.md) 证明，不能靠增加轮询或固定 sleep 掩盖缺口。
