# FDM 可借鉴方案与实现顺序

依据本轮静态证据及当前 FDM `04eda270f6071a212bb0dd4438033a27cbafad74`。本文是设计，不是已经改入产品的功能。DSX 设备接入与离线算法可以分别开发，但采集必须保留可追溯的原始数据。

## 当前代码与新功能的边界

| 当前代码事实 | 对接入与借鉴的影响 |
|---|---|
| `src/fdm/live_experiment/candidate_alignment.py` 用固定参考、Hann 和 OpenCV `phaseCorrelate`，并结合位移/response/相关系数/梯度比判定候选 | 已有图像配准基础和帧身份保留方式；它服务实时测量候选，不是扫描网格的全局配准器，不宜直接用 DSX 的 .35 门限替换现有判定 |
| `src/fdm/services/digital_slide_store.py` 的 `focus_levels` 是 `list[int]`，解析调用 `int()`；tile 的 `stage_x/stage_y/focus_z` 是整数，持久化字段也是整数 | 直接塞入 DSX 的小数 µm 会丢精度；必须设计明确单位的物理坐标元数据，保留旧设备步数语义和旧文件读取 |
| `digital_slide_renderer.py` 与 store 的预览合成消费已有 tile 像素位置，在重叠区域作半透明融合 | 新配准应先产出布局和融合缓存，再由查看器消费，不能在每次绘制时重新估计位置；当前透明叠加不等同全局拼接算法 |
| 现有数字切片保存完整焦层并按层浏览 | EFI 与高度场应作为派生资源，不替换原始 Z 栈；完整 Z 层是检查错层、样品多表面和算法失败的依据 |

这些代码观察只用于界定迁移点，不从 UI 选项推断设备实际执行状态。原采集瓶颈已经明确为缺少可靠运动完成反馈，本轮没有重复做泛泛排查。

## 推荐顺序

### 1. 离线 Z 栈重放与数据合同

先实现一个与设备无关的离线入口，输入带真实位置的完整 Z 栈，输出 EFI、原始高度、处理后高度及质量/有效性标签。固定参数与版本，对同一输入可重放。沿用本轮 CPU 核心作为可检查基线，再做速度优化。

原始记录建议至少包含：

```text
stack_id, tile_id, acquisition_id, frame_id
source_generation, acquisition_order, z_index
target_position {x, y, z, unit, coordinate_frame}
reported_position {x, y, z, unit, observation_source, observed_at}
frame {width, height, channels, dtype, byte_order, stride, pixel_format}
timestamps {request_utc, event_utc, monotonic_ticks, source}
calibration {pitch_x_um, pitch_y_um, objective, optical_zoom, NA, revision}
image_sha256, original_path
```

目标位置、报告位置、人工填写和由序号推算的名义位置必须分开。图像序号与 Z 数值也应分开；不将非均匀层距强行换成整数序号乘平均间距。没有实际位置时明确记录 `nominal`，不要生成看似精确的编码器坐标。

派生记录建议保存：算法/源码/参数 SHA、输入身份与顺序、输出高度单位、原点与方向、裁切范围、重采样倍率、像素标定、原始响应、测得/补值/无支持/边界峰值掩膜。栈内稳像裁边再放大，会改变像素物理比例；只保存最终宽高无法恢复这一变化。

`.fdmslide` 的兼容设计应先增加版本化物理元数据或独立 sidecar/表，再决定最终 schema；不能把当前整数坐标字段静默改为 µm。旧设备后端和旧文件应继续按原语义读取。

### 2. 明确失败状态的二维拼接

建议独立组合“物理坐标先验 → 邻接重叠 ROI → 图像配准 → 图一致性 → 布局缓存 → 融合”。本轮 3×3 合成验证从整数像素先验开始，覆盖重叠配准、图优化和融合；物理坐标到像素的转换仍须结合标定单独验证。它是有明确选择的研究架构，并非某个原厂 EXE 的完整替身。

- 保留每条边的估计、匹配代价、纹理量、接受原因和残差。Composite 的 `q` 是 ROI 灰度范围指标，不是几何正确概率。
- 明确选择失败边策略。原厂某 OLS 路线把非正 score 换成 .05 后继续进入优化；改进实现可删边或用稳健损失，但必须记录策略差别。
- 每个连通分量独立报告；先验位置回退仍可显示，但应标记。覆盖掩膜不等同配准有效性，孤立图块有像素不代表已成功定位。
- 先解决位置，再处理亮度/色调接缝。默认 APP 配置可能直接覆盖；不能把接缝隐藏得好当作几何位置正确。
- 完整多层切片优先用一组可信的 tile XY 布局应用到所有层；若逐层位移确实不同，保存层间变换并验证，防止不同焦层浏览时跳动。

### 3. 高度场与科学显示

以 µm 的浮点高度场作为内部科学表示，UInt16 压缩编码必须携带可逆范围、步长、偏置及无效区定义。原始高度、扣除基底后的高度和显示夸张各存一份参数关系，显示倍数不修改测量值。

可先提供平面/二次基底/球面扣除、剖面图、网格与 PLY 导出。用户选取的参考点或背景剖面应保存；如果样品形貌被当成背景拟合，会真实地改变测量结果。球面外无解区保留洞，不用平滑填满后冒充实测。

原厂“手动 spline”已证实是三点二次曲线，另一焦点拟合才是自然三次样条。界面和代码应按真实数学操作命名，避免把两个功能混用。

### 4. 预览稳像与反光抑制

预览稳像可作为显示体验功能单独开启，并显示当前偏移、重置和失配状态。原始图像、测量坐标和采集完成判断继续保持独立。纯色和周期纹理可产生高 reliability；必要时组合纹理、帧新鲜度、模型残差和运动状态，而不能只有单阈值。

Hamal 可作为可选显示/导出增强；先限制于已证明的位深、模式和缩略图覆盖尺寸。当前不建议直接用于定量测量预处理，也不建议把它命名为“恢复过曝信息”。原始像素和增强参数应保留，便于撤销和对照。

## 算法与设备调度的接口

设备后端只承诺它实际能证明的状态：请求已发送、应答已收到、硬件忙闲/到位已观察、帧已采集、文件已关闭等分别表示。算法后台消费已完成并冻结的图像记录，不能从“相关峰很高”“文件大小暂时不变”推断采集成功。

采集队列、磁盘写入和重建队列分离；有界缓冲和取消传播应保存已完成输入。原厂接口/桥接进程仍按前期接入报告推进，本轮参考 Python 不作为运动控制程序。

## 进入产品前的对照门槛

按 [现场操作卡](FIELD-ALGORITHM-CARD.md) 获取相同原图与原厂输出后，对比 Z 峰值、有效区、裁边、像素标定、配准误差和失败案例。性能分解为采集、必要稳定、编码/写盘和离线重建；合成脚本速度与画面好看程度均不代替实际采集提速和测量准确度。

优先验收“数据与单位正确、失败可识别、同输入可重放”，然后才做 GPU、并行、流式与更复杂拼接模式。CUDA 与原厂旧引擎逐位兼容不是实现上述独立功能的前提。
