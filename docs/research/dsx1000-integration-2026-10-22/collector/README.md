# DSX1000 现场证据收集器

这个独立 Windows 工具为 DSX1000 接入分析收集可复查的时间线。默认只观察；操作者满足文件身份、正常启动、现场停止手段和正在记录等前提后，可以手动开启同机 RDK 单步验证。**它不是 FDM 设备后端，不会自动完成数字切片扫描。**

现场步骤见 [中文现场操作卡](中文现场操作卡.md)。原厂控制链路、未证边界和 FDM 设计见上一级研究报告。

## 运行与包内容

- 完整解压发布包后运行 `DsxEvidenceCollector.exe`。保留 `DsxEvidenceCollector.exe.config` 与 `baseline.json` 在 EXE 同目录。普通用户运行，不需要 Python、NuGet、SDK 或互联网。
- 运行目标为 Windows x64、.NET Framework 4.8。真实设备的 Windows 10 1909 尚未运行验收。若 GUI 无法启动，保留错误并使用 `Collect-Basic.cmd`，不为测试升级设备环境。
- `Collect-Basic.cmd` 调用附带 PowerShell 5.1 脚本，收集系统、原厂进程、被动 TCP 表和关键文件身份，输出基础 JSON/ZIP。它没有图形观察、完整时间线或受控验证能力。
- `baseline.json` 固定了本轮静态分析副本的34份关键文件身份。全部匹配才开放受控验证；不匹配仍可观察并带回差异。匹配不代表功能、许可或硬件配置已经验收。
- 默认会话位于 `%LOCALAPPDATA%\DSXEvidenceCollector\Sessions`。收集目录必须与被观察的原厂图像/日志目录分离，避免自我递归记录。

## 能力和边界

| 能力 | 实际行为 |
|---|---|
| 环境盘点 | 原厂目录自动发现与手动选择；系统/区域设置/运行库、文件版本及 SHA-256、原厂进程、本机监听及连接表。仅读表，不探测端口，不收集完整进程命令行。 |
| 原厂操作观察 | 记录文件创建/变化/缺失/重命名、稳定候选、已有文本日志追加以及人工标记。名义轮询500 ms，稳定候选门槛2 s；这些是观测时刻，不是设备事件的精确发生时刻。 |
| 实验参数 | 保存倍率、分辨率、曝光、模式、Z 范围/间距/层数和备注等人工填写内容。五层和45张模板仅用于标记实验，没有批量控制功能。 |
| 样本带回 | 停止观察后选择本轮图像和文本日志复制；记录复制前后源哈希、复制件哈希及变化情况。日志复制件会脱敏并转换为 UTF-8。稳定副本或哈希相等不证明图像与位置对应。 |
| RDK 验证 | 开始观察后，人工启用并连接指定本机 IP/端口；正常接管/释放、缓存位置查询、错误查询、单次 XY/Z 移动、普通二维拍照、拍照状态查询及停止拍照请求。没有任意命令输入框。 |
| 异常 | 超时、断连、陌生/重复/格式错误应答使连接进入未知状态；不自动重连、重发或继续下一步。记录故障保留部分会话，限制后续控制。 |

原厂日志候选路径为 `%PUBLIC%\OLYMPUS\DSX-BSW\Log\CurrentLog`。工具不改日志级别，不执行会删除归档日志的 `DSXLogBackup.vbs`。已有日志默认从开始观察时的末尾读取；需要历史内容时，结束后选择该文本日志作为脱敏样本。无法解码、截断尾行和轮转会留下缺口记录，不会被填成成功事件。

日志和错误文本对 `/PASS:` 等已知口令模式进行脱敏，不读取完整进程命令行。该处理不是任意业务秘密的自动识别器；请把观察目录限定为本次采集需要的图像和原厂日志。

## 受控验证约束

连接是明确的人工操作，可能参与原厂初始化。现场须确认正常 RDK 启动与登录方式；工具不会启动/结束原厂进程，不绕过口令，不孤立加载原厂 DLL 或抢占驱动。没有正常 RDK 入口时，保留被动观察报告即可。

- 一次只发一个请求，不排队；所有请求带本地请求身份。原厂协议本身没有 request ID，匹配依赖当前唯一在途请求。任何不匹配回复都不留给下一请求。
- 等号后空格是原厂 wire 格式的一部分，例如 `MVZR= 2`；客户端从固定按钮生成规范格式。UTF-8 按增量解码，CRLF 分帧；`NAME+` 是临时应答，`NAME: +` 才是最终协议应答。
- 初始移动范围和位移为空，必须填入经现场确认的范围。XY 是整数 µm 绝对目标，Z 是整数 µm 相对量；非整数请求不静默取整，Z 小数起点也不自动修正。位置来源为 UI 缓存，鲜度未证。
- 普通二维拍照先设置普通 Snap 模式，再使用独立 `capture_<身份>` 子目录和 `frame` 基础名。保存目录须与观察图像目录一致；该 RDK 路径使用本地 ASCII 路径且不能含空格/逗号/引号。证据会话和普通观察路径可以包含中文。
- SHOT 最终回复只表示派发；拍照状态0还可能意味着停止。下一张/移动要等人工结束本轮拍照观察。异常结案仍明确标为结果未确认。
- `GETERRCODE?` 是手动历史/共享错误查询，原厂回复流程可能消费共享错误；它不自动执行，也不构成本次成功判定。
- “停止记录”不停止硬件；“请求停止拍照”不是任意轴急停。关闭连接没有已证实的自动停止或释放控制语义。

默认命令期限30 s，界面可调整；期限是客户端故障界限，不是最小稳定等待。不能通过延长期限或收到 `+` 将未知物理状态解释为到位。

## 数据与恢复

一次会话包含多个实验 run。每次“开始观察”建立新的实验身份；拍照观察未结束时不能切换 run。文件列表按当前观察轮次展示，样本应在开启下一轮前复制。

| 输出 | 内容 |
|---|---|
| `summary.json` | 会话、实验参数、按类别的已取得证据计数、未收集项目、错误与解释边界；覆盖计数不证明动作完成。 |
| `events.jsonl` | 逐条事件，含序号、会话/实验身份、UTC、单调时钟、来源、请求/拍照身份及数据。会话级环境事件可能没有实验身份。 |
| `timeline.csv` | 与事件对应的便于筛选的时间线；目标坐标、报告缓存、人工参数不混写。 |
| `environment.json` | 系统/进程/监听快照与关键文件预期/实测身份和差异。 |
| `samples/` | 人工选择的图片与脱敏文本日志；事件中记录复制过程及校验结果。 |
| `manifest.json` | 导出时的文件身份清单；不自包含其自身哈希。 |
| 会话 ZIP 与 `.sha256` | 封存后的证据包及外部 ZIP 哈希；原目录保留。 |

正常导出要求停止观察并断开工具连接。导出后会话封存，后续采集新建会话。程序异常退出、文件被锁定、缺少权限或磁盘失败时，已有文件保留；JSONL 的完整有效行仍可分析，截断行是证据缺口。界面“检查已有会话”提供只读 JSONL 检查，**不提供打开旧会话并续跑的功能**。保留原目录，不直接修改、补齐或覆盖旧事件；导出失败时带回原目录和错误记录。

## 构建与验证

源码为 C# 5 / WinForms，仅使用 .NET Framework 系统程序集。`build.ps1` 使用现有 `Framework64\v4.0.30319\csc.exe` 构建 x64 程序；不会安装编译器或 SDK。`validate.ps1` 执行模拟测试和界面检查，`build-identity.json` 记录编译器、源文件和 EXE 身份。

本次构建环境为 **Windows 11 ARM64 虚拟机，现有 .NET Framework 4.8.1 编译工具链，生成 x64 程序**。虚拟机没有 .NET 4.8 reference pack，因此构建使用现有框架程序集，源码及配置以4.8兼容为目标；这不能替代在4.8/Windows 10 1909上的实际运行验证。

验证包含模拟 RDK 拆包/合包/初始化通知/临时与最终应答/错误/超时/断线/迟到回复/白名单/单请求约束，及文件慢写、重命名、日志变化、复制校验、部分会话、中文路径、错误记录和 GUI 布局。模拟服务仅绑定 localhost 随机端口，不连接35001或真实设备。最终次数、结果、图像和构建哈希以随包验证摘要及其原始记录为准。

没有执行原厂程序，没有控制实机，没有修改 FDM 产品代码。**实机到位反馈、位置鲜度、新帧身份、保存完成、取消和原厂重新接管仍是现场验证任务。**
