# DSX1000 现场操作卡

适用日期：2026-10-23。用途：收集原厂采集时间线，并逐项验证 RDK 接口。本工具没有实现 FDM 自动扫描。请先完整解压发布包，保留 EXE、同名 `.config` 和 `baseline.json` 在同一目录，再双击 `DsxEvidenceCollector.exe`。

**先观察原厂正常工作。只有关键文件身份匹配、原厂正常 RDK 启动方式与现场停止手段明确后，才使用第二页。** 默认启动不会建立网络连接，也不会启动原厂程序。

## 1. 环境核对与准备

1. 在“1 观察与收集”页点击“新建会话”。默认会话位置为 `%LOCALAPPDATA%\DSXEvidenceCollector\Sessions`，也可选有足够空间的本地目录。
2. 核对“原厂 DSX-BSW 目录”：应选择同时包含 `DSX-BSW-APP`、`DSX-BSW-CTRL` 的 DSX 根目录，不要选择 LEXT 或备份安装包。
3. 点击“核对环境与文件”。工具读取系统、运行库、原厂进程、本机监听表及34份关键文件的版本/哈希。查看会话内 `environment.json`。文件不匹配、缺少或读不到时仍可进行观察，受控验证保持禁用。
4. 选择原厂实际图像输出目录和已有日志目录。默认日志候选是 `%PUBLIC%\OLYMPUS\DSX-BSW\Log\CurrentLog`，以设备现有位置为准。两者不能包含本次证据目录，也不能位于证据目录中。不要选择整个磁盘。
5. 核对磁盘空间。测量期间只观察变化；需要带回的完整图像和日志在停止记录后手动勾选复制。

如果 EXE 无法启动，保留错误现象，使用同目录 `Collect-Basic.cmd`：输入 DSX-BSW 安装目录（不确定时可留空），等待输出目录提示。这是 PowerShell 5.1 **基础盘点兜底**，没有图形时间线、目录观察或设备控制功能；不要为本次试验升级系统、驱动或原厂软件。

## 2. 先记录原厂采集

1. 选择“原厂二维拍照”，填写倍率、分辨率、曝光及备注，点击“开始观察”。
2. 在开始原厂操作时点击“开始操作”；原厂显示完成时点击“原厂显示完成”。发生取消或异常时使用对应人工标记。这些时间戳代表操作者点击时间。
3. 在原厂完成一次普通二维拍照。结束后点击“停止记录”。勾选本次需要的图像和文本日志，点击“复制勾选样本并校验”。
4. 再选“原厂多焦层：精细”或“原厂多焦层：快速”，填写原厂实际 Z 起点、终点、间距、层数，开始一轮新观察。两种模式需要比较时分别记录，保持其他条件可比。
5. 每轮结束后先复制该轮需要的样本，再开始下一轮；界面的文件选择清单会随新一轮观察清空，已复制样本和之前的事件仍保留在会话中。

“五层记录（人工操作）”与“3×3×5 记录（人工操作）”只是实验标签。Z 范围、层数等输入只写入记录，不会发送 Z 扫描任务。未完成接口闭环前不自动执行五层或45张采集。

**“停止记录”只停止收集，绝不会停止电机或相机。** 文件“稳定候选”也不代表原厂已关闭文件，更不代表拍摄成功。

## 3. 再做受控单步验证

### 建立连接与接管

1. 原厂正常采集观察完成后，先在原厂核对可用的正常 RDK 启动方式、登录权限及停止手段。工具不提供启动参数、账户绕过、驱动直连或另一套 CTRL 启动功能。没有已确认的正常入口就只带回观察报告。
2. 在第一页面选择“RDK 单步验证”，设置需要观察的输出/日志目录，点击“开始观察”。必须先建立实验记录才能连接。
3. 在第二页面勾选“启用本次受控验证”“已核对正常原厂 RDK 启动方式”“现场有人值守，已确认原厂停止手段”。填写环境报告中确认的**本机监听 IP 和端口**。默认端口为35001，但不能只凭默认值认定服务存在；工具只允许本机 IP，不能连接其他设备。
4. 点击“连接指定本机端点”，阅读确认框。首次连接可能参与原厂初始化；确认没有其他 RDK 客户端。工具不会额外发送 `INIT`。
5. 在原厂实际完成初始化并确认空闲后，勾选“原厂已完成初始化，已人工确认当前空闲”，再点击“接管远程控制”。协议回复只表示原厂协议处理结果。

### 查询与单轴短距离移动

1. 点击“读取 XY 与 Z 缓存”，并与原厂界面核对位置。读回是 UI 缓存，鲜度尚未证明，不能当成编码器即时反馈。
2. 填写**本次经现场确认的允许范围**。初始范围和位移均为空。XY 使用整数 µm 绝对目标并明确选择原厂速度枚举；Z 使用整数 µm 相对量。工具不会把非整数目标静默取整；Z 起点缓存带小数时也会阻止移动。
3. 先在一个轴上选择可观察的短距离，核对方向、范围及停止方式后，仅点击一次移动按钮。命令执行期间其他请求不会排队。
4. 回复后重新读取位置并人工核对。工具清除旧起点缓存，并且不显示“到位成功”。不要因没有报错就认定目标已达。

“查询历史/共享错误”仅用于人工调查。它可能返回历史错误，原厂回复过程还可能消费共享错误状态；不要用“无错”作为本次拍照成功的证明。

### 单张普通二维拍照

1. 第一页的“原厂图像输出目录”与第二页“快照独立保存目录”必须一致。建议提前建立一个本地独立目录，例如 `C:\Users\Public\DSXEvidenceShots`；RDK 输出路径必须使用 ASCII，不含空格、逗号、引号，不能使用网络共享目录。
2. 在原厂确认普通二维、关闭时间序列，并核对保存格式、曝光、分辨率与标定，再勾选“已在原厂确认普通2D、非时间序列、格式/曝光和标定”。
3. 点击“单次普通二维拍照”。工具选择普通 Snap 模式，为本张创建唯一 `capture_<身份>` 子目录，再提交以 `frame` 为基础名的 SHOT。原厂仍可能附加计数器或扩展名，实际文件以记录为准。
4. **SHOT 的最终回复仅表示已派发采集。** 此时移动和下一张拍照保持锁定。使用“读取拍照状态”，并在原厂检查图像/操作状态。状态0也可能来自停止，不等于成功。
5. 原厂报告状态0且人工核对后，点击“记录本次拍照观察结束（人工）”。它只结束本轮观察标记，不生成拍摄成功结论。必要时点击“请求停止拍照”，随后仍需核对实际停止状态；它不是任意 XY/Z 运动的急停按钮。

## 4. 异常、收尾与带回

| 现象 | 现场处理 |
|---|---|
| 连接超时、命令超时、断线或应答格式异常 | 工具进入状态未知，不重发、不自动重连。到原厂界面核对设备与控制权，按现场已确认方式处理；不要重复相对移动来“补发”。 |
| 记录写盘失败、日志不可读或部分文件缺失 | 保留已经产生的会话目录。检查记录中的缺失/错误信息；收集故障会限制后续受控操作。不要把不完整时间线解释为动作未发生。 |
| 拍照中发生连接/收集异常 | 可在原厂人工核对后点击拍照观察结束，按异常结案；记录仍标明未确认图像成功、未确认设备停止。 |
| “请求停止拍照”不可点击 | 可能有在途命令或连接状态未知。工具没有第二连接的停止旁路，使用原厂已确认的现场停止手段。 |
| 程序退出或导出失败 | 原会话目录保留。不要删除或改写 `events.jsonl`；完整行仍可分析，截断尾行属于证据缺口。可用“检查已有会话”做只读检查；不能续跑旧会话。 |

正常收尾：先在原厂确认操作结束 → 记录本次拍照观察结束 → “释放回原厂” → 核对原厂可正常操作 → “断开工具连接” → 第一页“停止记录” → 勾选并复制样本 → “导出证据 ZIP”。断开连接和退出程序都不代表设备已停止。

带回生成的 ZIP 及旁边的 `.sha256` 文件。原会话目录仍保留；导出后会话封存，后续实验应新建会话。样本只选择图像及已有文本日志，日志副本会脱敏并转为 UTF-8；它的哈希不应与原日志字节哈希相同。日志里的已知口令参数会遮盖，完整进程命令行不会采集。

## 5. 验证边界

本工具在 Windows 虚拟机中构建，并使用模拟 TCP 服务、模拟文件和界面检查验证，未运行原厂程序、未发送设备命令。真实 Windows 10 1909 上的启动、DSX 运动完成、正确新帧、保存完成及控制权恢复均待现场确认。测试范围与最终结果见发布材料中的验证摘要。
