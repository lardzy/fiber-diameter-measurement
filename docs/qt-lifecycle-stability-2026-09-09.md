# Qt 原生崩溃排查与 0.4.5 修复记录

日期：2026-09-09。排查起点：`main / 54a6bf0`。验证环境：macOS arm64、Python 3.13.12、PySide6/Shiboken6/Qt 6.10.2。

本轮定位到两条可复现的应用生命周期问题：控件跨布局移动后残留失效的 `QWidgetItem` 包装对象，以及窗口销毁后仍执行的延迟界面回调。二者都涉及 PySide 与 Qt 原生对象的生命周期边界。修复保留原来的 Qt 版本、画布缓存及测量算法，版本更新为 **0.4.5**。

## 1. 为什么之前的崩溃位置不固定

原始实现刚创建一个主窗口，还没有开始测量，就能查到两个异常布局项：C++ 对象已经不存在，Shiboken 包装对象仍标记为有效。这两个对象来自数字切片“采集任务”区域。

`MainWindow._install_capture_task_bar()` 将已处于布局中的提示标签、进度条和按钮直接加入底部任务栏。Qt 在隐式迁移过程中删除了旧布局项，但本机 PySide 6.10.2 没有同步注销所有已经暴露给 Python 的包装对象。

随后分配 `QAction`、`QTimer` 等对象时，分配器可能复用旧布局项的地址。原生崩溃现场显示：Shiboken 查到的旧对象类型为 `QWidgetItem`，正在初始化的新对象却是 `QAction`；错误最终发生在 `PySide::SignalManager::retrieveMetaObject`。这解释了为什么此前会在创建菜单、工具栏或其他看似无关的位置崩溃。

证据链：

- 新建主窗口后检查到 136 个布局项包装对象，其中两个指向已释放的原生对象。
- 两个异常项都属于“采集任务”布局；不需要打开图片或生成测量对象。
- 独立的窗口创建、显示、关闭循环也能复现，排除了“仅 pytest 才会触发”的解释。
- 最小对照中，直接把控件加入另一个布局，会留下仍报告有效的旧项；先调用旧布局的 `removeWidget()`，旧项会立即失效，而控件继续存活。
- 捕获到的原生崩溃现场中，Python 循环垃圾回收并未处于执行状态。没有证据将 GC 作为根因。

相关采集栏代码可追溯到 `9d5a9a4d` 的主界面调整，早于本轮画布局部更新优化。因此不能把该崩溃简单归因于新缓存策略。

修复内容：

- 新增 `layout_utils.detach_widget_from_layout()`，迁移前显式移除旧布局项。
- 在采集任务栏、`FlowLayout`、折叠区内容切换和五类测量工具上下文中统一使用。
- 统计面板重新排列已有卡片、筛选控件时，显式移除控件对应的布局项，避免丢弃 `takeAt()` 返回的非 Python 所有项。
- 查找原布局时只遍历 QObject 管理的子布局，不逐项生成无关 `QMainWindow` 原生布局的 Python 包装对象。这一边界通过全屏进入、退出及布局恢复测试单独验证。

Qt/Python 对象所有权规则参考：[Shiboken Object ownership](https://doc.qt.io/qtforpython-6/shiboken6/typesystem_ownership.html)。上述具体失效行为来自本次运行时检查，不能仅凭 `shiboken6.isValid()` 排除。

## 2. 窗口销毁后的延迟回调

修复布局项问题后，进一步让测试真正销毁已关闭的窗口，连续运行 `test_canvas_lifecycle.py` 时又稳定复现了另一条崩溃链：

1. 主窗口已经销毁，但没有 Qt 上下文的 `QTimer.singleShot()` 回调仍留在事件队列中。
2. 延迟恢复检查器高度、侧栏宽度和窗口布局时访问旧对象，产生 `Internal C++ object ... already deleted`。
3. 本机 6.10.2 的后续虚方法回调错误处理出现引用计数异常：`DocumentCanvas.paintEvent` 函数从有效变为已释放，而类字典仍引用它。
4. 下一次绘制读取这个失效函数，最终在 `Sbk_QObject_getattro` 崩溃。

跟踪日志记录了先出现的对象已删除异常，以及之后函数引用计数的变化。6.10.2 的 `BindingManager::getOverride()` 返回借用的函数引用，`Sbk_GetPyOverride()` 的待处理错误分支会对该返回值执行减引用操作，与本次观察到的链路一致。这里没有将其对应到未经证实的上游缺陷编号，也不宣称其他 Qt 版本具有相同表现。

源码依据：[bindingmanager.cpp](https://github.com/pyside/pyside-setup/blob/v6.10.2/sources/shiboken6/libshiboken/bindingmanager.cpp)、[basewrapper.cpp](https://github.com/pyside/pyside-setup/blob/v6.10.2/sources/shiboken6/libshiboken/basewrapper.cpp)。

修复为每个产品代码中的一次性延迟回调指定实际的 QObject 上下文，覆盖主窗口、自适应布局、全屏、数字切片初始适配与导航图、画布图块调度、图像处理窗口、截图编辑器和启动入口。Qt 会在上下文对象销毁时取消尚未执行的回调，这是官方提供的生命周期约束：[QTimer::singleShot](https://doc.qt.io/qt-6/qtimer.html#singleShot)。

回调的归属按用途设置：界面工作归对应窗口或控制器；对话框预检查归对话框；退出应用归 QApplication；截图代理的启动命令归代理。后台测量确认、采集写入原有的关闭等待和请求版本检查保持原样，不能以取消回调代替完成已接受的业务操作。

## 3. 测试本身的生命周期修正

`QWidget.close()` 通常只隐藏窗口。此前大量测试只调用 `close()`，闭包和信号引用使已经关闭的主窗口及其子控件长期积累，后续全局主题切换会遍历这些旧控件。该现象造成长批次内存增加及极慢的主题测试，也掩盖了实际销毁时才暴露的回调问题。

测试清理现在只对**已经成功关闭**的主窗口调用 `deleteLater()` 并完成 Qt 延迟删除。判断依据为窗口隐藏且主窗口已经移除自己的应用事件过滤器；如果关闭被后台任务拒绝，则不强制删除。清理不替换 Qt 虚方法，不修改生产环境的关闭交互，也不关闭 GC。

新增回归验证以下行为：

- 原布局项在控件转移后失效，控件本身及新布局保持有效。
- 重复加入控件不会生成重复布局项。
- 嵌套工具布局、折叠区替换、统计面板反复换行均正确释放旧项。
- 查找未加入布局的控件不会暴露无关的主窗口原生布局项。
- 主窗口的延迟检查器恢复、数字切片初始适配在对象存活时正常执行，销毁后不再调用。
- 原有关闭文档、取消隐藏画布图块、晚到结果、全屏及工作流用例在同一进程连续执行。

## 5. 版本、性能和验收边界

- `src/fdm/version.py`、Windows 安装器版本包含文件和 README 当前版本均为 **0.4.5**。
- 没有更改项目格式、导出几何、RAW 轮廓、面积计算、快捷键或操作步骤。
- 没有回退后台栅格进程、局部图块失效及精确画面交接；画布代码只补充延迟调度的生命周期归属。
- 没有更换或锁定另一套 Qt/PySide 依赖，没有通过禁止 GC、吞掉所有异常或永久保留旧控件绕过问题。
- macOS 离屏测试能够验证此次引用失效和销毁边界，但不等同于 Windows 安装包实机验收。Windows 仍应执行发布自检，并检查连续开关项目、数字切片、全屏、主题切换及测量后立即关闭等操作。
