# 画布交互性能优化：实现与验证

日期：2026-09-07。起点：`0.4.3 / 45c023d`。本轮保持版本号、Qt 画布、项目与导出格式不变。

三批实现已落入工作区。主要收益来自稳定预览复用、局部掩膜、定向记录更新，以及将复杂 Qt 栅格绘制移出 GUI 所在的 Python 解释器。没有更换分割模型、引入 GPU 渲染或简化持久化 RAW 轮廓。

## 第一批：草稿和剔除预览

- 主体、当前识别和每块确认剔除分别缓存不可变坐标快照与栅格图像；几何版本没有变化时，不重新转换全部顶点、构建路径或重复描边。
- 保留孔洞、半透明填充、黑色外描边和彩色虚线的原有顺序。平移复用图像坐标中的显示层，缩放等待期间使用该层上一份完整画面。
- 连续面积、自由圈选、控制点拖动进入交互显示状态。被动对象与稳定编辑背景在同一手势中复用，活动提示点、光标和控制点继续即时反馈。
- 导航变换、吸附状态等派生通知按帧合并；鼠标松开立即应用最终位置。实际吸附判断和自由圈选采样保留原规则，自由圈选继续覆盖新增闭合边形成的填充楔形重绘范围。
- 魔棒确认时接续已经显示的草稿栅格，正式对象的精确主体和选中反馈在后台准备完成后替换，避免刚确认后第一次拖动重新执行复杂描边。

入口：`draft_preview_cache.py`、`screen_layer_cache.py` 和 `canvas.py`。

## 第二批：局部后处理与有序确认

- `MaskRegion` 保存只读局部像素、原图原点和原图范围。分割 ROI、模型输入及扩张规则保持原状，结果相交、剔除、连通域选择、填孔和轮廓提取在局部范围完成。
- 提示点直接读取连通域 label，最终选定后才创建一次结果掩膜。保留原有取整、边界裁切和 8 连通语义；数字切片的来源原点仍转换回全局坐标。
- worker 生成可直接提交的最终轮廓；没有新增剔除的确认复用已完成版本。掩膜移交后只读，实际修改才分配新像素。
- 有剔除的确认进入 FIFO 队列，一次确认即清空当前草稿并接受操作。冻结文档实例、类别、来源像素和几何快照；晚到结果不会把焦点抢回旧图片，也不会归入后来切换的类别。
- 后续测量按接受顺序写入；再次确认去重；撤销优先取消最后一个尚未完成的操作。保存与导出自动等待已接受操作，失败时明确中止该次快照，避免静默漏掉测量。
- 几何编辑更新对应记录行、画布与统计，不重建类别/标定控件或重置整表。新增测量使用单对象历史命令，坐标以无损 float64 字节保存，避免为整份文档反复构造 JSON；复杂跨对象操作继续使用原历史路径。

入口：`mask_region.py`、`area_commit.py`、`prompt_segmentation.py`、`prompt_segmentation_worker.py`、`measurement_commit_queue.py`、`history.py`、`main_window.py`。

## 第三批：完整预览到精确画面

- 可见画布缺少精确图块时先显示同一文档的完整预览，目标视口的图块全部就绪后统一替换。首次没有预览时显示原图和“正在载入测量显示…”；隐藏诊断画布保留精确直接渲染以供对照。
- 面积坐标使用不可变数值快照，Qt 路径由后台构建；混合面积、直径线、折线、点和标签按原绘制顺序生成快照。计数标记与标签保持原来分批绘制顺序。
- 新增、删除、几何/外观变化增量维护索引和相关图块，保留无关图块。选中对象的可见性筛选使用保守标签边界，精确质心只在真正绘制时计算。
- 仍打开的图片保留近期缓存，关闭时释放；完整预览、草稿、RAW 快照与活动层全部受全工作区共享预算约束，不随打开图片数量无限叠加。预算见 [画布性能基准](canvas-benchmark.md)。
- 精确图块继续匹配 zoom、DPR、设备像素相位、主题/样式与文档版本。预览不参与吸附、命中、面积数值、保存或导出。

实现中增加了一个共享的 Qt 栅格进程。实测发现部分 PySide 原生路径/描边操作即使放入 QThread，也可能持有 GIL 并推迟 GUI 回调；独立解释器消除了这条阻塞。使用一个进程和最多两个桥接线程，传输坐标与绘制值快照，不传窗口、源图片或模型。应用入口处理 `freeze_support()`，退出清理进程；崩溃后的后台 worker 可以重建一次。

入口：`overlay_geometry_snapshot.py`、`overlay_process_renderer.py`、`canvas_overlay_cache.py`、`canvas.py`、`app.py`。

## 性能记录

环境：Apple M5 Pro、64 GiB、macOS 26.6.2 arm64、Python 3.13.12、PySide6/Qt 6.10.2、NumPy 2.4.3、OpenCV 4.13.0。结果来自离屏 Qt 合成数据，不包含显微镜设备或真实分割模型推理。

### 连续快速拖动，期间编辑、提交和缩放

可见状态的 1024×768 画布，90 帧，每帧间隔 16 ms、水平移动 18 个逻辑像素，并在过程中执行几何修改、新增面积及 1.25 倍缩放。表中“输入到图像”包括鼠标处理与 QImage 绘制，不含操作系统合成器；事件循环分发另列，避免只看鼠标槽函数而漏掉后台安装开销。

| 场景 | 输入到图像 P50 / P95 / 最大 | 事件分发 P95 / 最大 | 鼠标处理 P95 | 同步缺图块回退 |
|---|---:|---:|---:|---:|
| 2K / 50 × 1 万点 / 3 剔除 | 1.24 / 2.17 / 2.41 ms | 1.81 / 5.66 ms | 0.13 ms | 0 |
| 4K / 100 × 1 万点 / 10 剔除 | 1.49 / 1.69 / 2.34 ms | 2.02 / 8.03 ms | 0.07 ms | 0 |
| 8K / 100 × 1 万点 / 10 剔除 | 1.63 / 1.91 / 2.55 ms | 2.14 / 4.24 ms | 0.07 ms | 0 |
| 4K / 20 × 5 万点 / 10 剔除（压力） | 1.42 / 1.60 / 4.49 ms | 1.67 / 4.53 ms | 0.07 ms | 0 |

以上场景的初始和最终精确缓存均成功完成，没有后台绘制错误。另测 2K / 20 × 1 千点 / 3 剔除，输入到图像 P95 为 3.03 ms。

复杂度高时，精确画面准备仍有成本：主场景停止操作后到目标精确缓存完成约 4.48–5.71 秒，5 万点压力场景约 9.35 秒。期间显示的是完整预览并可继续操作。首次绘制图片/载入状态的 UI 回调约 30.8–58.6 ms，**不能把它当成全部精确对象的首帧耗时，也不能宣称全部冷启动已达到 16.7 ms**。这些指标与旧报告的完整 RAW 冷帧不构成同口径速度比。

压力测试还定位并修正了两条遗漏路径：刚提交面积的首次主体/选中描边，以及为选中面积做图块筛选时的同步精确质心计算。后者的最长事件回调由本轮定位时约 95 ms 降至约 4.5 ms。

### 局部后处理与真实界面安装

同一个 512×512 主体、孔洞和剔除区域，执行最终剔除和轮廓生成，12 次采样：

| 原图 | 整图后处理 P50 / P95 | 局部后处理 P50 / P95 | 逐像素与几何对照 |
|---|---:|---:|---|
| 2K | 8.59 / 17.24 ms | 3.36 / 3.96 ms | 一致 |
| 4K | 22.47 / 23.63 ms | 3.70 / 3.95 ms | 一致 |
| 8K | 95.44 / 109.35 ms | 3.60 / 4.17 ms | 一致 |

8K 构造样本中的主体加剔除掩膜从 128 MiB 降为约 266 KiB。此数值是输入掩膜持有量，不代表整个应用内存或算法峰值。

通过实际 MainWindow 新增入口测试，在已有 50 个对象时，新对象 1 千 / 1 万 / 5 万点的 UI 安装 P95 分别为 **1.92 / 3.80 / 11.24 ms**，包含记录行、分类计数、动作状态和历史命令。5 万点压力场景仍超过单次输入 8 ms 的目标；普通 1 万点场景已在该目标以内。

## 正确性与验收范围

- 局部/整图掩膜逐像素与轮廓、统计字段对照：2K/4K/8K、图像边缘、孔洞、多碎片、空结果、提示点取整/裁切、数字切片原点。
- 实际确认路径：有剔除的确认去重，确认后切数字类别、切图片、继续测量，撤销 pending 操作，保存重开，叠加图导出；导出孔洞像素与原图一致。
- 显示对照：DPR 1/1.25/1.5/2、亮暗背景、分数像素原点、孔洞、自交/凹多边形、重叠透明层、混合测量/标签、计数绘制顺序及图块接缝。
- 生命周期：过期预览丢弃、跨文档隔离、局部索引更新、图块取消预算、文档关闭、后台进程故障恢复；确认后的显示转交在下一次草稿取消后仍保留。
- 自由圈选、剔除工具、类别快捷键、吸附、面积编辑和数字切片原有回归一并运行。

最终回归通过 **2500 个用例，另有 1416 个子测试**：140 个测试文件按文件隔离运行，合计 2154 个用例及 1396 个子测试；另外 4 个主窗口相关文件的 346 个界面用例按独立进程逐例运行，包含 20 个子测试，全部通过。新增模块的 Ruff 检查、35 个 Python 文件的编译检查与 Git 空白检查通过。

测试中反复创建/销毁主窗口的长批次出现过 Qt 原生崩溃，涉及 `test_ui_canvas_and_export.py`、`test_main_window_analysis_batch.py`、`test_screenshot_main_window.py`、`test_workbench_workflows.py`；故采用上述逐例隔离方式。原始版本对照也有布局/快捷键测试不稳定，但未证明与本轮原生崩溃同源。**原生崩溃原因尚未定位，不能将隔离通过表述为整套测试单进程稳定通过。** 没有通过禁用应用垃圾回收或删除断言掩盖问题。

Windows 常用机的真实输入到屏幕延迟、PyInstaller 打包后的新进程启动，以及高 DPI 大窗口长时间测量仍需实机验收。本机像素矩阵与独立进程测试不能替代该验收。真实模型推理耗时、本地已有文件/十几张实图的长时交替测量也没有用合成基准冒充。
