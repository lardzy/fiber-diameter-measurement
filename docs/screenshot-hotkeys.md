# Windows 截图快捷键

截图工具继续通过独立托盘进程中的 Windows `RegisterHotKey` 接收全局组合键。测量工作台关闭后，托盘进程仍可使用；本次改动没有增加常驻键盘钩子或新的 C++ 输入扩展。

## 设置与诊断

在测量工作台或截图托盘的设置页中，每个截图模式都有独立状态：请求的组合键、实际生效组合键、注册结果、Windows 错误码和最近一次接收时间。注册冲突会尝试恢复旧绑定；一组快捷键可以互换。Windows 注册与恢复都可能失败，因此以“实际生效”状态为准。

- `1409` 表示组合键被系统或其它程序占用。释放占用后，点击“重新注册并检测快捷键”，无需重启工具；修改组合键后先应用设置。
- `87` 表示参数或组合配置无效；`5` 表示 Windows 拒绝访问。提示不猜测具体占用程序。
- 最近接收时间不变化：先检查注册状态、前台软件和宿主机是否截获按键。时间变化但截图没有出现：继续检查截图队列、标注窗口和输出错误。

## 录入

点击快捷键输入框后，本工具暂时注销全局快捷键，避免原绑定抢走录入。离开输入框、隐藏页面或关闭对话框会恢复；设置进程异常退出时，录入租约最多 15 秒后失效。无法确认已释放时停止录入并保留错误提示。截图工具未启动时可以离线修改配置。

Windows 录入会保存原生虚拟键及修饰键，减少键盘布局和显示字符转换造成的歧义。旧配置仍可读取。支持 PrintScreen 仅产生释放事件的情况；如果系统根本不把它送到录入框，可以使用旁边的特殊键菜单选择 PrintScreen 及其组合，保存后仍须通过实际注册检查。菜单选择不会强行夺取已被占用的按键。Tab 移到下一个控件，Esc 结束录入，Backspace 清除；明确识别为 AltGr 字符的事件不作为全局组合键。

## 调度与输出

全局快捷键、托盘和 IPC 请求进入同一个有界队列（最多 8 项），原生消息回调只接受请求，不直接截图。Windows `MOD_NOREPEAT` 抑制长按；尚未派发的同模式快捷键请求合并；IPC 相同请求编号去重，不同内容重复使用编号会报错。仍保留已有行为：新选择请求替换旧选择、已有标注时提示先完成或取消、延时截图等待原设定时间。

图片编码和文件写入在独立顺序工作线程执行（含正在保存的任务最多 4 项），避免慢磁盘堵住快捷键消息。剪贴板操作保留在 GUI 线程。每次保存持有图片和配置快照；同名文件依次处理，队列满会明确报错。标注保存期间暂停编辑，失败后保留画面重试；退出会等待已接受的保存，若标注输出失败则取消退出。较早的慢保存不会覆盖后来已成功截图的“上次区域”。

`STATUS` IPC 响应提供队列深度和最近 64 次请求的阶段记录：接收、派发、选择层出现、画面就绪、输出排队、完成／失败／取消／被替换。计时使用 `perf_counter`，起点是应用收到消息；这不包含实体键盘和 Parallels 宿主转发延迟。

## Windows 回归探针

从 Windows 项目根目录执行（源码环境）：

```powershell
$env:QT_QPA_PLATFORM = 'windows'
.venv\Scripts\python.exe scripts\validate_screenshot_hotkeys_windows.py --output build\hotkey-check.json --samples 30
```

探针使用独立设置、临时输出和自己的前台窗口，实际注册系统快捷键，通过 `SendInput` 注入测试组合并核验 PNG；不会修改登录自启或用户截图设置。仅在确认自己的窗口位于前台、修饰键空闲时发送输入。默认验证后清除截图文件，JSON 保留尺寸、哈希、时序和结果。PrintScreen 未送达等限制会单独记录，不能当作该项验收通过。

验证范围与数据见 [2026-10-14 验证报告](validation/screenshot-hotkeys-2026-10-14/README.md)。实体键盘、不同布局、管理员前台程序和安全桌面需要单独验证。
